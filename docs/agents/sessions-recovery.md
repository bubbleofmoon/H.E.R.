# Inbound, sessions and recovery

Read for durable ingress, session mapping, turn recovery, ledger locking or usage accounting.

## Inbound journal and gap recovery

- **`inbound.rs` (`data/inbound.db`, WAL, `synchronous=FULL`):** journals admitted events before wake scheduling (keyed by conv+messageId, else raw-text hash; lone UTF-16 surrogates -> U+FFFD + logged). `SharedJournal` keeps ingress off fsync/HTTP; heartbeats update last-alive on disconnect.
  - Stages: `received -> processing -> handled` (backfill never wakes; startup `processing` -> `interrupted`, reruns only if turn recovery proves non-execution). On reconnect, saved `received` precede new frames if current config admits conv (else settled). While `config.json` unreadable, reserved2 `--live-groups` saves and holds `<=10,000` events in memory and replays in arrival order once readable (no reconnect needed; newer events queue behind held ones); other modes log/count `config-unreadable` <=1/min in run record and skip mute/group-card work.
- **Gaps & notices:** reconnect opens gaps for allow/deny-admitted convs (last readable config if unreadable). Group recovery uses `get_group_msg_history` + `message_seq` over `OneBot`/`loopback_http.rs` (literal loopback, 5s/8s/8s, chunked, lone-surrogate safe, 16 MiB cap), attempted on reconnect on 60s->6h backoff (<=8 attempts; admin retry resets). Private gaps are terminal unrecovered (zero retry deadline).
  - Notices go to owner private only (no chat text/gateway detail), `<=10` convs in 800-char body (`unresolvedGaps` on `/api/inbound/gaps` retains all). `noticeState`: `pending -> queued -> unknown -> sent` (startup returns `queued -> pending`; pre-send -> `unknown`; pre-submit refusal -> `pending`; post-checkpoint ambiguity stays `unknown` without auto-resend; `notified_ms` on confirmed delivery only). Startup interrupted-event notices fire once per `processing -> interrupted` transition (citing local time and later ledger turn if any).
  - Retention (reconnect + hourly): 1d raw handled/backfilled frames, 7d/50,000 rows, 30d interrupted, 7d recovered gaps (never prunes `received`/`processing`/unresolved gaps).
  - Startup migration reserves SQLite writer only when needed (`BEGIN IMMEDIATE` for un-migrated recovery; already-migrated console opens stay read-only).

## Sessions, reconciliation and ledger locking

- **`session_map.rs`:** sole `data/sessions.json` writer (locked read-modify-write, preserves unknown top-level fields; damaged data fails closed; reset clears mappings/policies with verified backup + audit). Exact DSH session-not-found allows replacement+rotation; mode transition retires immediately; other policy changes retire pre-reuse.
- **Interrupted Admin interactions & harness recovery:** interrupted Admin question/approval continuation is lost on restart (reads intent+outbox; pending snapshot display-only). Interrupted non-`reserved2` harness turns (`chat`, `closed-agent`, open `reserved`) pause as `harness-interrupted` (no DSH probe/replay); pre-submit `reserved`/`reserved-summary` failures interrupted during retry delay (`!turn.reserved2 && turn.reason.starts_with("reserved")`, unsubmitted) still resume when valid under `chat::allowed_key` (honoring `allowAllWhenEmpty`, without altering `reserved2` `inbound_admitted`).
  - Interrupted `reserved2` harness wakes (`begun` mode or wake claim) self-reconcile on startup without admin resolution when outbox sends are absent/settled (`SendState::None | SendState::Settled`), `conversations.db` is readable, and no `running`/`uncertain` tool intents or `paused` turn exist: pre-admission wakes with no accepted attempt/store row/outbox follow unexecuted recovery; submitted wakes close running store turns, commit ledger abandonment pre-SQLite close (completed/cancelled/failed if tools/sends ran keeping confirmed sends without replay, or resumed/abandoned if none), and re-arm consumed finite `sleepUntil` (matching claimed config or unclaimed `confirmedAt` without active wake, even if paused/`socialV2.enabled=false`, while preserving newer config, unconsumed deadlines, and retired `sleepRetired`). Unresolved/unreadable outbox, unsettled tools, paused store turns, missing store rows post-attempt/send, or unreadable mode/DB fail closed as `send-unresolved` (`confirm:true` to retry).
- **Engine switches:** share conv admission gate; staged switches finish/clear before next turn. Unstaged failed switch in chat/owner-private closed-agent uses authoritative source; staged/post-failure retries on 5s->10m backoff (`admin_alert` on 1st fail).
- **Turn ledger & Windows OS 32/33 retry:** admission writes `begun` (with mode in reserved2, before budget/wake claim) -> `attempt` (with RPC ID; `layers` counts for layered briefings).
  - Only turn-worker/recovery ledger appends and their preceding tail-fold claim read retry Windows OS 32/33 within 1 shared 2s deadline (syncing `ended` and notice claims under append lock; exhaustion emits content-free diagnostic and fails closed). Never retry under send-chain, token-publication, hub or tick locks. `.without_retry()` disables append retries on scheduler/hub/interaction-gated cancel, whole `reset_all_v2` / access-revocation `cancel_ledger_turns`, restore reconciliation, and outbox/usage/other appends (whereas administrative `social_state::reset_conversation` / `reset_conversation_with` holds no hub lock and keeps the 2s retry wait; inline/closed-agent `.without_retry()` cancels finding `turn-ledger-finalize.lock` busy leave the turn open for recovery instead of failing cancellation). Full reads are one-shot except `GET /api/turns`, `GET /api/socialV2/send-outbox`, and `turn_ledger::reset_count` (`read_records_waiting` 2s OS 32/33 retry -> 503 / fail-closed).
- **Finalization gate (`data/locks/turn-ledger-finalize.lock`):** <=1 `ended` record/turn. Collector claims genuine completed DSH end via `observe_completion(rpcId)` and accepts (`end_attempt`) or releases (`release_completion`) pre-rejection/failover; durable `cancel-requested` leaves finalization to cancel handler post-revocation (parity-clock barrier errors log only without changing verdict). Live-observation cap ends `completed` with `observationSleep` (`end_cancellation`; unconfirmed stop pauses). Recovery settles via `end_reconciled` (errors on stale/incompatible claim pre-replay; cancel claim rotates token first). Unexecuted proof requires exact session-not-found, prompt absent in inbox, or complete log without it; preparation failures retry <=3 at 5/10/20s backoff.
- **Timeout wake expiry & cap revocation:** expired timeout wakes refused at admission clear matching `sleepUntil` (non-timeout keeps/restores); admitted wakes keep durable deadline until `begun`/`wake_claim`; expired held inbound closes via `turnTimeout`. Hub revokes unmapped DSH dispatch token at cap.

## Usage, timing, pauses and history log

- **Usage (`ledger.rs`, `ledger/storage.rs`):** merges `token-usage.jsonl` + `token-usage-rust.jsonl` (`Ledger::dsh_attribution`, `compact_plan` rewriting `.compact` sidecar at `DEFAULT_MAX_LINES = 20_000` keeping `DEFAULT_KEEP_SAMPLES = 10_000`, `plan_harness_reconciliation` + `harness-usage-reconcile.json`). DSH attribution subtracts ledger samples; `engine: harness` samples are excluded from DSH totals (`docs/agents/harness.md`).
- **Timeouts & `turn-timing.jsonl`:** `socialV2.turnTimeoutSecs` (180, 3-900) bounds chat/closed-agent/1st-gen reserved (reserved2 uses `prompts-modes.md` budget); reattach wait 900 (1-3600). `turn-timing.jsonl` records `turn_engine::Facts` (DSH cancel reasons: `turnTimeout`, `superseded`, `turnCancelled`, `turnInvalidated`, `dshAborted`, `collectorTimeout`, `collectorFailure` + phases; harness: `harness:<turnId>`, `turnInvalidated`, `harnessCancelled`, `harnessDeadline`; `rbridge-live.jsonl` predicates: `suspended`, `notTaken`, `notAllowed`, `missing`, `tokenChanged`, no tokens).
- **Pauses & owner recovery commands:** first `pausedAt` persists; `socialV2.pausedTurnAutoAbandonMinutes` (default 10, 0 disables; auto-abandons only, under `locks/turn-resolution.lock`). 8-hex turn code; pause + resolution alerts via bounded notice worker. Owner private (`user_id` and sender ID == `ownerQQ`) intercepts exact whole-message `<放弃|重试|abandon|retry> <8hex>` or `<重试|retry> <8hex> <确认|confirm>` (ASCII case-insensitive; extra words like `重试 123456 的任务` or `放弃 <code> 吧` go to model); journaled handled pre-resolution. Reset resolves `sessions.json` mappings; harness reset revokes generation immediately while handler settles storage/ledger.
- **Chat history log (`history_log.rs`):** gated on `history.enabled === true`; logs non-replayed ingress + durable `send_outbox` `intent`/`confirmed` as schema v1 in `data/history/<UTC day>.jsonl` (token-masked, never pruned/backed up; <=1 `[history]` error/min). Stripped on Windows via `scripts/strip_history.py` (with `scripts/snowluma_export.py`) before vault `data/memory-eval`.

## Crate contracts

Inbound recovery reserves SQLite writer before reading; already-migrated opens stay readers. Only turn-worker/recovery ledger appends and their tail-fold claim read retry Windows OS 32/33 within 2s (ordinary reads one-shot except `GET /api/turns`, `GET /api/socialV2/send-outbox`, `turn_ledger::reset_count`); never retry under send-chain, token-publication, hub or tick locks. Reserved2 adopts only self-minted tokens; rotation holds publication mutex across token write/publish and releases before ledger write.
