# MCP, auxiliary tools and memory

Read for tool schemas, protocol, generated DSH MCP config, memory access or settings.

- `--mcp-serve` is snowluma-safe. QQ schemas are recorded in spec/tools-snowluma-safe.json; registration at startup follows socialV2 tool/sticker/voice flags. Unregistered tools answer Tool X not found. Memory/settings tools are memory_write/search/index/forget/acl and settings_get/set.
- Stdio negotiates protocolVersion, supports ping and Method not found (-32601). Invalid JSON/non-2.0/non-string-or-integer IDs and non-object params/_meta are dropped; null params returns an error. Initialize/list/call validation returns -32603 schema issue lists. At most 64 concurrent requests run; overload/worker failure returns -32000 without dispatch. Unknown argument keys are dropped; QQ_SESSION_KEY/TOKEN fill only after validation.
- QQ tools are thin console clients with x-console-token, x-agent-call and x-agent-token; compactModelData bounds model output. Chat-bearing read results and memory search/index filter model-facing copies through `model_view`; `docs/agents/prompts-modes.md` owns the strip/blacklist contract. Console data and outgoing sends retain originals. Console authorization is authoritative. Send success requires a 2xx response with a JSON body containing boolean `ok:true`, for both DSH MCP and harness callers. A 2xx body with missing or non-boolean `ok` is unknown delivery; explicit `ok:false` remains an error classified by refusal/outbox evidence. Send errors retain delivery uncertainty as MCP `_meta.herDelivery:"unknown"`; transport loss, malformed success responses and unverified outbox progress never become definite refusals. Harness dispatch consumes this metadata before continuing. Agent status exposes mode, role, roleMode, dshReady and pause only; dshReady is an authenticated settings/describe probe and credential/probe errors mean false.
- Auxiliary stdio servers are --mcp-web-search-serve (web-search-safe: web_search/web_fetch) and --mcp-host-serve (snowluma-host: snowluma_status). They share stdio behavior and exit zero after in-flight calls on EOF. Recorded schemas/oracles live in spec/aux-baseline.json and tests/fixtures/aux-oracle.json.
- Each auxiliary call reloads selected config with bounded defaults; BOM/invalid JSON gives an empty config. Selected gateway/credentials come exclusively from dependencies.json and user/dsh/.credentials.yaml. No-root credentials use explicit DSH_HOME or USERPROFILE/.dsh, with no personal fallback when both are absent.
- Search strips CQ/control/whitespace and caps at 120 UTF-16 units. Auto tries DeepSeek then Bing RSS/HTML, preserving fallback notes; cache is five minutes/64 entries. Keys resolve config, named environment, then matching DSH credential refs and go only to a validated HTTPS endpoint. Redirects from that endpoint are refused; keys never enter logs/results/argv.
- Fetch permits only credential-free HTTP(S), rejecting localhost/local suffixes and any private DNS result before connection and at each of at most five redirects. Text is capped at 50,000 characters. Media and fetch share the same private-IP policy; tests/fixtures/safe-fetch-ip-corpus.json is the independent recorded regression corpus.
- Requests use hidden curl with validated pinned addresses, URL/headers/body on stdin, a 20-second total budget and eight seconds/address for multi-address requests. Every child is reaped at request completion/failure and dies with its Linux parent. Gateway HTTP redirects are refused. Search/fetch failures are error text results; snowluma_status returns reachable:false plus reason/hint without isError and never manages SnowLuma.
- `dsh-mcp-config --patch-file ... [--bridge-exe ...] [--runtime-root ... --console-port ...] [--check]` owns only its existing BEGIN/END marker block. All three managed IDs point to this binary with the matching serve flag. Root and port are paired. Outside text is preserved byte-for-byte; broken markers or managed IDs outside the block refuse edits. Changed files get backups; unchanged files are not rewritten. DSH plugins/preset tool namespaces remain stable.
- Historical memory schema is spec/memory-schema.sql. Chinese bigrams/ASCII tokens, FTS, ACL/team/role relationships and transactional initialization remain intact. Interrupted initialization fills missing schema/FTS without rebuilding an existing index. Selected roots ignore ambient database overrides. No-root memory uses HER_MEMORY_DB, then MEMORY_DB_PATH, then deployment default. Archived rows stay out of search/index; private rows remain owner-only even with wildcard ACL. The database carries `PRAGMA user_version` 1: opening an unversioned database runs that completion in one IMMEDIATE transaction and stamps version 1 without changing rows; version 1 opens skip the completeness check; a newer version refuses to open.
- Search query tokens retain Han U+4E00..U+9FFF, lowercase ASCII letters, digits and underscore, at most 24. Index segmentation keeps dots. Empty cleaned queries use recent fallback. This is explicit `memory_search`: every term must match, and no match falls back to pinned, important and recent rows. Automatic recall is `memory::recall`, which shares neither (`docs/agents/prompts-modes.md`). Row errors propagate without payload diagnostics; recall errors preserve available hints and continue the wake. Forget applies exact visibility without search-hit side effects or a 200-row cutoff.
- Memory tools and the console `/api/memory/*` routes share `memory_actions.rs`; tools pass no console credential; search/write/index/forget require the target's current token. ACL/settings require owner-private authority or actual console authority where allowed. Selected calls acquire the social gate and re-read authority/config after waiting. Settings-write invalid selected config returns 400 without changing either root. SQLite writes/audit are transactional; dedup upserts use BEGIN IMMEDIATE, grants reload per call.
- Search, recall, index, write and forget go through `memory::MemoryStore` (hit counting and the hot-block probe still use the raw connection): `for_reader(conversation)` gives search, recall, index, write (owned by that conversation) and forget (visibility check and delete in one transaction), with ACL scope, the private rule and owner authority (`private:<ownerQQ>`, integer `ownerQQ`) applied inside; `admin()` gives ACL and archive to callers that authorized first.
- Settings retain defaults: sendDelayMs 300, burst enabled, intervals 1000/3000, minute/hour 8/60, wake batch 8000, sticker collect 8388608 bytes, context 6000 characters/four recent messages, role 6000 characters. Send/wake/context shallow replacement and sticker.collect/role merging preserve null/zero/false; sendDelayMs uses nullish fallback. `memory.inject.relatedTopK` is the recall depth a wake executes: writes accept an integer 1 to 20 (a numeric string is stored as a number) and refuse anything else; reads show the executed depth (3 when unset; a hand-edited out-of-range value shows its clamp). Five optional paths remain absent (named MCP reads render undefined). Settings reads never return console credentials or mutate config; writes are immediately visible.
- Preview uses selected recall and returns the block the next wake would deliver (memories the conversation's current session generation already carries are left out), without counting search hits (`docs/agents/prompts-modes.md` owns the delivery contract). Explicit archive/unarchive retains memory and FTS with audit and is visible to search/index without a new MCP tool. Captured ACL/token-ledger expected outputs stay in tests/fixtures and are exercised through HTTP.

- Harness in-process memory dispatch records a structured source alongside its outcome for later model-copy rendering; `docs/agents/harness.md` owns that internal snapshot contract. Standard stdio MCP results keep their existing shape.
- `her-memory` probe diagnostics report metadata only; stored model text never enters its output.
