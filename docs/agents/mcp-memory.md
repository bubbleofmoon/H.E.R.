# MCP, auxiliary tools and memory

Read for tool schemas, protocol, generated DSH MCP config, DSH profile guard, memory access or settings.

## MCP servers and loopback transport

- **`--mcp-serve` (snowluma-safe):** each `tools/list` reads selected runtime mode and effective tool/sticker/collection/voice switches via mode-profile menu shared with harness (1st-gen simulation uses chat menu). `QQ_SESSION_KEY` selects conversation menu; shared DSH without key offers combined group+private capabilities (incl. owner-only tools if owner configured). Admin approved group send uses harness interaction handler. Calls validate arguments against current registration and recheck live authority at execution; unregistered tools return `Tool X not found`.
- **Stdio JSON-RPC (shared with `--mcp-web-search-serve` & `--mcp-host-serve`):** negotiates `protocolVersion`, handles `ping` and `-32601`; drops invalid JSON, non-2.0, non-string/int IDs, non-object `params`/`_meta`; null `params` errors; schema validation failures return `-32603` issue lists. Max 64 concurrent requests (overload/worker error -> `-32000` without dispatch). Unknown arg keys dropped; `QQ_SESSION_KEY`/`TOKEN` injected post-validation. Aux servers exit 0 after in-flight calls on EOF; aux schemas/oracles live in `spec/aux-baseline.json` and `tests/fixtures/aux-oracle.json`.
- **QQ tools & `loopback_http.rs`:** thin console clients (`x-console-token`, `x-agent-call`, `x-agent-token`; `compactModelData` bounds output). Console and SnowLuma WebUI loopback calls use `loopback_http.rs` (literal loopback check, split connect/write/read deadlines, 64 MiB cap, `Transfer-Encoding: chunked` decoding, pre-write `NotCommitted` vs post-write `Unknown`). `OneBot` (`onebot.rs`) routes QQ/OneBot RPC with lone-surrogate replacement.
  - Chat-bearing reads and memory search/index redact via `model_view` (`【已隐藏】` keeps IDs, cursors, media refs, generated memory IDs/counts usable; schemas/console/memory/outgoing keep originals; `docs/agents/prompts-modes.md`).
  - Send success requires 2xx + JSON `ok: true` (DSH MCP and harness); 2xx without boolean `ok` = unknown delivery; `ok: false` classifies by refusal/outbox evidence. Errors carry `_meta.herDelivery:"unknown"` on uncertain delivery (never turned into definite refusals).
  - Agent status exposes `mode`, `role`, `roleMode`, `dshReady`, `pause` (`dshReady` = authenticated settings/describe probe; errors -> `false`).

## Auxiliary search/fetch and `dsh-mcp-config`

- **Config reload:** every aux call reloads selected config (BOM/invalid JSON -> empty config) and selected runtime gateway; DSH login credentials live in `docs/agents/dependency-recovery.md`.
- **Web search (`--mcp-web-search-serve`):** strips CQ/control/whitespace, caps 120 UTF-16 units. Auto tries DeepSeek then Bing RSS/HTML (preserving fallback notes); model results/errors label DeepSeek as `primary` (`provider`/`fallbackFrom`), never by name; primary failure shows model fixed text + at most HTTP status (endpoint error -> stderr). Cache: 5 min / 64 entries.
  - Credential lookup: stored key bound to current base URL -> config literal -> named env var; unreadable store refuses primary search; keys go only to validated HTTPS endpoint (redirects refused; keys never in logs/results/argv). When `webSearch.baseURL` unset, Settings binding and bot consult own `DEEPSEEK_SEARCH_BASE_URL` then built-in default (set `webSearch.baseURL` in config if console/bot envs can differ; keys match only when resolved base URLs match).
- **Web fetch (`guarded_fetch.rs`):** credential-free HTTP(S) only; rejects `localhost`/`.localhost`/`.local` and private DNS pre-connect and at each of <=5 redirects; 50,000-char text cap; shared IP policy with media (`tests/fixtures/safe-fetch-ip-corpus.json`). Uses `DnsResolver`/`HttpTransfer` seam and hidden `curl` (`-q`, cleared curl/proxy env, pinned bracketed IPv6 `--resolve`, URL/headers/body via `-K -` stdin, 20s total / 8s per-address budget, child reaped on exit/Linux `PR_SET_PDEATHSIG`). Gateway HTTP redirects refused. Search/fetch errors return error text results; `snowluma_status` returns `reachable: false` + `reason`/`hint` without `isError` and never manages SnowLuma.
- **`dsh-mcp-config --patch-file ... [--bridge-exe ...] --runtime-root ... --console-port ... [--check]`:** owns only its `BEGIN`/`END` marker block (all 3 managed IDs -> this binary + flag + paired `--runtime-root` & `--console-port`). Preserves outside text byte-for-byte; broken markers or managed IDs outside block refuse edits; changed files get backups (unchanged untouched); DSH plugin/preset tool namespaces stay stable.

## DSH profile guard (`dsh_profile.rs`)

Applies to install root's runtime only.
- **Startup write (supervisor pre-DSH and live bridge; failure recorded + owner alert):** writes guarded rows into `user/dsh/profiles/web/cordis.patch.yml` between `# === her profile guard BEGIN/END ===` and moves block to end of file (outside lines preserved byte-for-byte; broken/duplicate markers refuse write).
  - Changed file first backed up as `cordis.patch.yml.bak-her-<UTC>-<nn>` (sorted after existing matching backups, `nn`+1 if clock didn't advance, >`99` refuses/writes nothing/alerts owner; case-insensitive on Windows; keeps newest 5 matching names only).
  - Guarded rows: `system-prompt` (`includeHarnessIdentity: false`, `includeRuntimeContext: false`, empty `personaPrefix`/`personaSuffix`), and `harness-dev-context`, `agent-instructions`, `tool-bash`, `tool-pwsh`, `tool-fs`, `tool-fs-search` disabled.
- **Pre-call verification:** runs before every DSH `session/create` and `session/prompt` (pipeline pre-DSH + `dsh::Rpc` incl. 401 retry):
  - Checks `BEGIN`/`END` block (empty/ASCII-space lines allowed; non-blank lines must match verbatim), all other profile rows (only top-level rows above block targeting guarded ids are overridden by it), and every preset file listed by `user/dsh/bundles/qq-agent-presets/package.json` `dsh.bundle.patch` (must contain >=1 preset; shell/file tool rows if present disabled; `agent-instructions` disabled or `config.maxBytes: 0`; no enabled `harness-dev-context`/`system-prompt`; persona `prefix`/`suffix` free of `model_text_policy::denied_terms`; every preset or `plugins`-overriding patch keeps `agent-instructions` as a direct item of its own `plugins` list).
  - Strict allowlist YAML reader: keys `[A-Za-z0-9_.-]+:` + space/EOL; values plain scalar (no leading indicator or `: `), `'...'` (`''` quote), `"..."` (no `\`), block scalar, `{}` or `[]`; any other form (quoted/explicit keys, tags, anchors, aliases, flow collections, escapes, trailing text after closing quote, multi-line plain scalars, tabs, nested sequences, document markers) refuses as `yaml`, and every non-comment guarded package name must be a parsed row.
  - Codes name preset files by `dsh.bundle.patch` index (`preset1`, `preset2`, ...), never filename. Gap refuses prompt with `对话后端配置未通过检查，回合未提交：<codes>` and alerts owner once per distinct code set (persisted in `data/dsh-profile-alert.txt` only after notice queue accepts; deleted on pass).
  - `her-cli dsh-profile check --runtime-root <root>`: read-only check (exit 0 `ok`, 1 codes one/line, 2 usage/runtime error).

## `her-memory`, provenance and settings

- **Store (`her-memory`, `her-memory/spec/memory-schema.sql`):** selected `data/memory.db` only (ignores `HER_MEMORY_DB` / `MEMORY_DB_PATH`). Current `PRAGMA user_version` is 4 (one-way migrations in single transaction; rollback requires pre-upgrade backup):
  - Unversioned DB completes interrupted init in `IMMEDIATE` tx (Chinese bigram + ASCII FTS, preserves rows/ACLs/teams/roles/FTS).
  - v2 adds `digest_cursor` (`conversation`, `space`, `through_seq`, `updated_at`, `replies_ms`, `replies_seq`, `failed_at`; written only by Digest). v3 adds `memory_provenance`. v4 creates `memory_embedding_cache(memory_id PK, model, embedding)` (empty `embedding` = failed fingerprint; delete/update triggers invalidate cache).
  - Archived/superseded memories excluded from search/recall/index. Private rows visible only to owning conversation + admin private (even with wildcard ACL).
- **Search vs Recall:** `memory_search` retains Han `U+4E00..U+9FFF`, lowercase ASCII alnum and `_` (<=24 tokens; index keeps `.`), requiring every term with fallback to pinned/important/recent rows (empty cleaned query uses recent fallback). Separate from `memory::recall` (`docs/agents/prompts-modes.md`). Row errors propagate without payload diagnostics; recall errors keep available hints and continue wake. Forget checks exact visibility without search-hit side effects or 200-row cutoff.
- **Local semantic recall (fastembed CPU `bge-small-zh-v1.5` + `sqlite-vec`):** Windows requires `ORT_DYLIB_PATH` pointing to trusted CPU ONNX Runtime DLL (`>= API 24` enforced; other hosts accept `ORT_DYLIB_PATH` or platform name). Model files (`onnx/model.onnx`, `tokenizer.json`, `config.json`, `special_tokens_map.json`, `tokenizer_config.json`) live under `<runtime>/resources/recall/bge-small-zh-v1.5/` (local disk only). Failed load cached until model file metadata changes or restart. Missing/incompatible runtime, busy encoder, query-encode errors or vector errors fall back to sparse recall.
  - Backfill & ranking: eligible wakes/previews backfill <=16 visible missing/stale rows (newest `created_at`, desc ID tie-break) within 250 ms total load+inference+query budget. One local worker finishes in-flight native call post-timeout (concurrent wakes use sparse). Inference runs outside SQLite tx; short `IMMEDIATE` tx rechecks rows/grants before publish; non-finite/all-zero vectors marked & skipped.
  - Cache budget: 2048 B/vector (512 f32) + 32 B fingerprint + SQLite overhead (~20 MiB/10k rows); linear scan over eligible post-ACL/scope/exclusion rows (cosine ceiling provisional 0.22; <=20 candidates/channel -> RRF offset 60; `vec0` index is follow-up). Explicit search remains lexical.
- **API, `MemoryStore` & provenance (`memory_actions.rs`):** console `/api/memory/*` and tools share `memory_actions.rs` (tools pass no console token; search/write/index/forget need target current token; ACL/settings need owner-private or console authority; selected calls take social gate and re-read authority/config; invalid settings write -> 400 without mutating either root; dedup upserts use `BEGIN IMMEDIATE`; grants reload per call).
  - `MemoryStore::for_reader(conversation)` applies ACL/private/owner (`private:<ownerQQ>`) inside; `write_digest(space, expected, through, replies, memories)` commits digest memories (`inference`) + cursor in 1 tx (no-op if stored seq != `expected`), `digest_failed(space)` records failure time only; `admin()` for pre-authorized ACL/archive. Delivery hit counting uses raw connection.
  - Provenance (`fact` | `inference`, independent of `kind`): unverified records (incl. legacy & model tool output, which strips `messageId`/`supersedes`) are `inference`; `source` grants no fact authority. Console writes with `messageId` + exact trimmed plain text of recorded incoming msg record unattributed `fact` in owner private, or attributed `inference` quote (`attributed_to` = speaker QQ) in other convs. Recall/tool results prefix `事实`/`推断` before `kind`.
  - Supersession: verified message write may pass positive int `supersedes` in same conv/scope (linked requires newer msg from same speaker; owner private may correct unlinked note); correction + link + archive commit atomically (retry returns existing id, `archived: true` when deduplicated existing memory is archived without bumping use timestamps); supersession blocks unarchiving predecessor until forgetting replacement clears link in 1 tx. `POST /api/memory/history {key, id}` returns original + `superseded_by` for live token of that conversation.
- **Prompts & writable settings:** `qq_get_prompt` returns same snowluma-safe `enabledTools`, effective wake defaults, and `recommended` (`null` if `socialV2.provideRecommendations` false; `socialV2` sections redacted).
  - `memory.inject.relatedTopK`: JSON int 1-20 on write; read defaults 3 (rounds/clamps finite numbers/numeric strings).
  - Named reads allow writable settings only (others return fixed refusal without repeating key). Secret redaction (`(已隐藏)`, incl. nested/array items and `qq_get_prompt` `recommended`) covers `security.*` and any segment (case-insensitive, `-`/`_` ignored) ending in `token(s)`, `secret(s)`, `password`, `passwd`, `apikey(s)`, `key(s)`, `credential(s)`.
  - Chat-writable settings = `SETTINGS_WRITABLE` + registry entries marked `chat` passing secret/path checks (`settings::chat_setting`; dotted path or retained chat spelling only; JSON pointer/case variants refused; `socialV2.sticker.stickerEnabled` -> `socialV2.sticker.enabled`, `socialV2.sticker.collect.maxBytes` -> collection byte cap default 8 MiB). Writes go through `settings::apply` (`actor: owner`, `source: chat`) -> `settings.db` + `config.json` mirror (mirror fail keeps change and sets `mirrorError` + note `配置文件这次没有同步，下次改设置或控制台重启时会补上` without raw error; store fail -> `设置存储暂时不可用，这次没有改动`). `SETTINGS_WRITABLE` replies omit sent value; registry `chat` replies note when effective + value; refused value returns name + bounds. Memory batch chat paths: `memory.inject.relatedTopK`, `memory.autoFlush.{enabled,contextPct,maxSessionsPerDay}` (typed JSON bool/numbers). Invariant `chat_settings_come_from_the_registry_and_are_never_secret`: `chat` entries are never secret and disjoint from `SETTINGS_WRITABLE`.
  - Preview uses selected recall without counting hits, excluding DSH briefing's carried recall. Explicit archive/unarchive retains memory/FTS with audit. Harness in-process memory dispatch saves structured source for model-copy rendering (`docs/agents/harness.md`); failed stdio/harness actions carry localized text, `isError: true`, `structuredContent.class` (`refusal` | `error`).
- **`memory-bench`:** reads LongMemEval question array on stdin -> JSONL per question (fresh in-memory store, top Recall hit, `_abs` expects no answer).

## Public recall calibration

Coordinator records owner approval at exact revision before running; runtime cosine ceiling (0.22) stays provisional until both folds pass:
- **Inputs:** pinned [cleaned LongMemEval small](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned/tree/98d7416c24c778c2fee6e6f3006e7a073259d48f) (`longmemeval_s_cleaned.json`) + [CPU BGE-small-zh-v1.5](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781) (`onnx/model.onnx` + 4 tokenizer/config JSONs) under `HER_LONGMEMEVAL_DIR` with compatible local CPU ONNX Runtime.
- **Method:** 1 memory/session in fresh in-memory SQLite per question, 5-item cap, fully backfilled cache; slice 1 = sparse-only. Split answerable & abstention -> sort each by `SHA-256(question_id)` -> indexes `0, 5, 10, ...` calibration, rest holdout.
- **Sweep:** cosine ceiling `0.16..0.32` step `0.02` on calibration -> must gain `>= +2 pp` evidence-session recall@5 AND add `<= +5 pp` abstention retrieval vs slice 1 (highest recall wins, ties -> strictest ceiling). Verify same two checks on holdout for that single candidate; stop without calibrated ceiling if either fold fails.
- **Run:** `cargo test --manifest-path her-memory/Cargo.toml --lib -- --ignored --nocapture longmemeval_recall_calibration` (verifies hashes, local inference only, prints aggregate metrics only).
