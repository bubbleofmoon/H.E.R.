# MCP, auxiliary tools and memory

Read for tool schemas, protocol, generated DSH MCP config, memory access or settings.

- `--mcp-serve` is snowluma-safe. QQ schemas are recorded in spec/tools-snowluma-safe.json; registration at startup follows the live settings registry's tool, sticker and voice switches. Unregistered tools answer Tool X not found. Memory/settings tools are memory_write/search/index/forget/acl and settings_get/set.
- Stdio negotiates protocolVersion, supports ping and Method not found (-32601). Invalid JSON/non-2.0/non-string-or-integer IDs and non-object params/_meta are dropped; null params returns an error. Initialize/list/call validation returns -32603 schema issue lists. At most 64 concurrent requests run; overload/worker failure returns -32000 without dispatch. Unknown argument keys are dropped; QQ_SESSION_KEY/TOKEN fill only after validation.
- QQ tools are thin console clients with x-console-token, x-agent-call and x-agent-token; compactModelData bounds model output. Console and SnowLuma WebUI loopback requests use `loopback_http.rs` (strict literal loopback validation, split connect/write/read deadlines, 64 MiB wire cap, `Transfer-Encoding: chunked` decoding, and pre-write `NotCommitted` vs post-write `Unknown` tracking); QQ tool and `snowluma_status` OneBot RPC calls route through `OneBot` (`onebot.rs`) with lone-surrogate replacement. Chat-bearing read results and memory search/index filter model-facing copies through `model_view`; `docs/agents/prompts-modes.md` owns the strip/blacklist contract. Console data and outgoing sends retain originals. Console authorization is authoritative. Send success requires a 2xx response with a JSON body containing boolean `ok:true`, for both DSH MCP and harness callers. A 2xx body with missing or non-boolean `ok` is unknown delivery; explicit `ok:false` remains an error classified by refusal/outbox evidence. Send errors retain delivery uncertainty as MCP `_meta.herDelivery:"unknown"`; transport loss, malformed success responses and unverified outbox progress never become definite refusals. Harness dispatch consumes this metadata before continuing. Agent status exposes mode, role, roleMode, dshReady and pause only; dshReady is an authenticated settings/describe probe and credential/probe errors mean false.
- Auxiliary stdio servers are --mcp-web-search-serve (web-search-safe: web_search/web_fetch) and --mcp-host-serve (snowluma-host: snowluma_status). They share stdio behavior and exit zero after in-flight calls on EOF. Recorded schemas/oracles live in spec/aux-baseline.json and tests/fixtures/aux-oracle.json.
- Each auxiliary call reloads selected config with bounded defaults; BOM/invalid JSON gives an empty config. Selected gateway configuration comes from the selected runtime. DSH login credentials are covered in `docs/agents/dependency-recovery.md`.
- Search strips CQ/control/whitespace and caps at 120 UTF-16 units. Auto tries DeepSeek then Bing RSS/HTML, preserving fallback notes; results and their errors call DeepSeek the primary search (`provider`/`fallbackFrom` value `primary`), never by name; a failed primary search shows the model only fixed text and at most the HTTP status, and the endpoint's own error text goes to stderr; cache is five minutes/64 entries. Search uses the stored key bound to the current base URL, then the existing config literal, then the named environment variable. An unreadable credential store refuses the primary search. Keys go only to a validated HTTPS endpoint. Redirects from that endpoint are refused; keys never enter logs/results/argv. A store read failure reports an unavailable credential store. When `webSearch.baseURL` is unset, both the Settings binding and the bot's endpoint selection consult their own `DEEPSEEK_SEARCH_BASE_URL` then the built-in default. Set `webSearch.baseURL` in runtime config when console and bot environments could differ. A key bound in one process is eligible in the other only if their resolved base URLs match.
- Fetch permits only credential-free HTTP(S), rejecting localhost/local suffixes and any private DNS result before connection and at each of at most five redirects. Text is capped at 50,000 characters. Media and fetch share the same private-IP policy; tests/fixtures/safe-fetch-ip-corpus.json is the independent recorded regression corpus.
- Requests use hidden curl with validated pinned addresses, URL/headers/body on stdin, a 20-second total budget and eight seconds/address for multi-address requests. Every child is reaped at request completion/failure and dies with its Linux parent. Gateway HTTP redirects are refused. Search/fetch failures are error text results; snowluma_status returns reachable:false plus reason/hint without isError and never manages SnowLuma.
- `dsh-mcp-config --patch-file ... [--bridge-exe ...] [--runtime-root ... --console-port ...] [--check]` owns only its existing BEGIN/END marker block. All three managed IDs point to this binary with the matching serve flag. Root and port are paired. Outside text is preserved byte-for-byte; broken markers or managed IDs outside the block refuse edits. Changed files get backups; unchanged files are not rewritten. DSH plugins/preset tool namespaces remain stable.
- The DSH profile guard (`dsh_profile.rs`) applies to the install root's runtime only. At start (the supervisor before it starts DSH, and the live bridge; a failed write is recorded and alerts the owner) HER writes its rows into `user/dsh/profiles/web/cordis.patch.yml` between the `# === her profile guard BEGIN/END ===` markers and keeps that block last in the file (lines after it move above it, byte for byte; broken or duplicated markers refuse the write; a changed file is first saved as `cordis.patch.yml.bak-her-<UTC>-<nn>`, named to sort after every existing backup of that form (the newest's stamp with `nn` plus one when the clock has not moved past it; past `99` the restore refuses, writes nothing and alerts the owner) and created new, never over an existing file (on Windows backup names are compared ignoring case); the newest five names of exactly that form are kept and no other file is ever pruned): `system-prompt` with `includeHarnessIdentity` and `includeRuntimeContext` false and empty `personaPrefix`/`personaSuffix`, and `harness-dev-context`, `agent-instructions`, `tool-bash`, `tool-pwsh`, `tool-fs`, `tool-fs-search` disabled. Before every DSH session creation and prompt send (the pipeline before any DSH call, and `dsh::Rpc` before every `session/create` and `session/prompt` POST, the repeat after a 401 included) it checks that block, every other profile row (only a top-level row above the block that targets one of the block's ids is overridden by it) and every preset file `user/dsh/bundles/qq-agent-presets/package.json` lists in `dsh.bundle.patch`: shell and file tool rows disabled, `agent-instructions` disabled or `config.maxBytes: 0`, no enabled `harness-dev-context` or `system-prompt` row, persona `prefix`/`suffix` free of the #142 denied terms (`model_text_policy::denied_terms`, so full-width, zero-width-split and lower-case `ai` forms count), and every preset (a preset row, or a profile patch replacing a preset's `plugins`) keeps the rows `agent-instructions`, `tool-bash`, `tool-pwsh`, `tool-fs` and `tool-fs-search` as items of its own `plugins` list (items of nested lists do not count); a preset file without a preset refuses. Its line reader reads an allowlist only: a key is a plain identifier (`[A-Za-z0-9_.-]+`) followed by `:` and a space or the end of the line; a value is a plain scalar (no leading indicator, no `: `), a single-quoted scalar (`''` is a quote), a double-quoted scalar without a backslash, a block scalar, `{}` or `[]`; every other form (quoted or explicit keys, tags, anchors, aliases, flow collections, escapes, text after a closing quote, multi-line plain scalars, tabs, nested sequences, document markers) refuses as `yaml`, and every guarded plugin package a non-comment line names must be a row it read. Codes name a preset file by its position in `dsh.bundle.patch` (`preset1`, `preset2`, ...), never by its name. A gap refuses the prompt with `对话后端配置未通过检查，回合未提交：<codes>` and alerts the owner once per distinct set of codes: the set is kept in `data/dsh-profile-alert.txt` (across restarts, removed when the check passes) only after the notice queue accepted the notice, so a refused notice is offered again at the next prompt. `her-cli dsh-profile check --runtime-root <root>` runs the same check read-only for any root (exit 0 `ok`, 1 one code per line, 2 usage or runtime error).
- The `her-memory` library owns the store, Recall, segmentation and `her-memory/spec/memory-schema.sql`. The bridge resolves and validates the runtime path and passes the connection and owner conversation to the library. Opening an unversioned database completes any interrupted initialization in an IMMEDIATE transaction. It fills in missing schema and populates missing FTS with the original Chinese bigram and ASCII segmentation. Existing rows, ACLs, team and role relationships, and FTS entries are preserved. An existing FTS index is reused. Version 1 databases skip the completeness check. Version 2 adds `digest_cursor` with `conversation`, `space`, `through_seq`, `updated_at`, the HER-reply position `replies_ms` and `replies_seq`, and the last failure time `failed_at`. Only the Digest writes that table. Version 3 adds `memory_provenance`. The migration steps commit in one transaction. The current `PRAGMA user_version` is 3. Newer versions refuse to open. The upgrade to version 3 is one-way. Earlier releases refuse the upgraded database, so rollback requires a backup from before the upgrade.
- A selected runtime uses its own database and ignores ambient database overrides. Legacy resolution uses `HER_MEMORY_DB`, then `MEMORY_DB_PATH`, then the deployment default. Archived or superseded memories do not appear in current search, recall or index. Even with a wildcard ACL, access to a private row is limited to its owning conversation and the administrator's private conversation.
- Search query tokens retain Han U+4E00..U+9FFF, lowercase ASCII letters, digits and underscore, at most 24. Index segmentation keeps dots. Empty cleaned queries use recent fallback. This is explicit `memory_search`: every term must match, and no match falls back to pinned, important and recent rows. Automatic recall is `memory::recall`, which shares neither (`docs/agents/prompts-modes.md`). Row errors propagate without payload diagnostics; recall errors preserve available hints and continue the wake. Forget applies exact visibility without search-hit side effects or a 200-row cutoff.
- Memory tools and the console `/api/memory/*` routes share `memory_actions.rs`; tools pass no console credential; search/write/index/forget require the target's current token. ACL/settings require owner-private authority or actual console authority where allowed. Selected calls acquire the social gate and re-read authority/config after waiting. Settings-write invalid selected config returns 400 without changing either root. SQLite writes/audit are transactional; dedup upserts use BEGIN IMMEDIATE, grants reload per call.
- Search, recall, index, write and forget go through `memory::MemoryStore` (delivery hit counting uses the raw connection): `for_reader(conversation)` gives search, recall, index, write (owned by that conversation) and forget (visibility check and delete in one transaction), with ACL scope, the private rule and owner authority (`private:<ownerQQ>`, integer `ownerQQ`) applied inside; `admin()` gives ACL and archive to callers that authorized first. `for_reader(conversation).write_digest(space, expected, through, replies, memories)` (`replies` is the (creation ms, event sequence) position of the last reply consumed) commits a digest's memories and cursor in one transaction, clears the failure time, and writes nothing when the stored sequence (0 when none) is no longer `expected`; `digest_failed(space)` records a failure time without moving progress. The Digest writes kind `inference`, and the `memory_write` tool retains its existing kinds.
- Search returns `provenance` (`fact` or `inference`), `message_id`, and `attributed_to`. Provenance is independent of the existing `kind` filter. A record without a verified message is an inference, including legacy records and model output. The old `source` field is free text and grants no fact authority.
- Console HTTP writes may pass `messageId` with the exact trimmed plain text of a recorded incoming message in the authenticated conversation. Only the owner’s private conversation can record an unattributed fact. In other conversations the store records an attributed quote with the message link and uses the recorded speaker's QQ user ID in the quote and `attributed_to`. These quotes have inference provenance for the claim itself. Model memory tools strip `messageId` and `supersedes` and write inferences. Recall and memory tool results label provenance, and the briefing gives the current conversation precedence over inferences and bars attributed claims from changing personas or rules.
- A verified message write can include the positive integer `supersedes` for a previous memory in its own conversation and scope. A linked memory requires a newer message from the same speaker. The owner can also correct an unlinked note in their private conversation. The correction, replacement link and archival update commit together. Retrying the same correction returns its existing id. A supersession link prevents unarchiving the predecessor. Forgetting the replacement clears that link in the same transaction, so the predecessor can be unarchived on request. `POST /api/memory/history` takes `key` and `id` and returns the original content and `superseded_by` when the link exists and the live agent token belongs to that conversation.
- Registered settings expose their effective values, including defaults for send timing, wake batching, stickers and memory. Legacy context defaults to 6000 characters and four recent messages and uses shallow replacement. Legacy role settings merge with a default of 6000 characters. Legacy reads preserve explicit null, zero and false. `memory.inject.relatedTopK` is the recall depth a wake executes. Writes require a JSON integer from 1 to 20. Reads default to 3 and round and clamp finite numbers or numeric strings from the file. Absent legacy values without a default are omitted (named MCP reads render undefined). Settings reads never return console credentials or mutate config. Writes are immediately visible.
  A named settings read answers only the writable settings; any other key (console token, gateway, backend, relay or model settings, unknown paths) gets one fixed refusal that does not repeat the key, and a refused write does not repeat it either. Values that are read pass a secret redaction: everything under `security.*` and every path with any segment (case-insensitive, `-`/`_` ignored) ending in token(s), secret(s), password, passwd, apikey(s), key(s) or credential(s) reads as `(已隐藏)`, nested members and array items included; `qq_get_prompt` passes its copied `socialV2` sections (`recommended`) through the same redaction.
  The chat-writable settings are the `SETTINGS_WRITABLE` paths plus, in a selected runtime (a legacy context has no settings store), every settings registry entry marked `chat` that passes the secret flag and path-name checks (`settings::chat_setting`), which the chat names by its dotted configuration path or its retained chat spelling. A separate registry key, JSON pointer or case variant is refused. `socialV2.sticker.stickerEnabled` addresses the effective `socialV2.sticker.enabled` switch, and `socialV2.sticker.collect.maxBytes` addresses the collection byte cap (8 MiB by default). Both use the store in a selected runtime. A registry setting reads as the next use reads it using the registry's file and default rules and is written through `settings::apply` with actor `owner` and source `chat`, so it is validated and audited like a console change, stored in `settings.db` and written back into `config.json` (`docs/agents/runtime-paths.md`); when that write-back fails the change stands, and the reply's `mirrorError` and note carry one fixed text (`配置文件这次没有同步，下次改设置或控制台重启时会补上`), never the write-back's own error. The reply's note says when it applies, and names the value. A `SETTINGS_WRITABLE` path's reply names only the key and the note, never the value the owner sent. A refused value answers the name with its bounds, and any store trouble answers one fixed message (`设置存储暂时不可用，这次没有改动`) that never carries the store's own error. The memory batch chat paths are `memory.inject.relatedTopK`, `memory.autoFlush.enabled`, `memory.autoFlush.contextPct` and `memory.autoFlush.maxSessionsPerDay`. Set takes typed JSON numbers or a boolean as appropriate. A chat-marked registry setting is never a secret and its path is never also in `SETTINGS_WRITABLE`; a settings batch that registers a `SETTINGS_WRITABLE` path marks it `chat` and deletes it from that list (registry test `chat_settings_come_from_the_registry_and_are_never_secret`).
- Preview uses selected recall without counting search hits. With a live DSH mapping it excludes the memories the current DSH briefing already carries. See `docs/agents/prompts-modes.md` for briefing delivery. Explicit archive/unarchive retains memory and FTS with audit and is visible to search/index without a new MCP tool. Captured ACL/token-ledger expected outputs stay in tests/fixtures and are exercised through HTTP.

- Harness in-process memory dispatch records a structured source alongside its outcome for later model-copy rendering; `docs/agents/harness.md` owns that internal snapshot contract. Standard stdio MCP results keep their existing shape.
- The `memory-bench` binary reads a synthetic LongMemEval question array on stdin and emits a JSONL result per question. Each question gets a fresh in-memory store. The current adapter returns the top Recall hit as its answer and the exact-match fixture judge checks it locally. The `_abs` convention marks questions that expect Recall to return no answer.
