# Dependency recovery and alerts

Read for DSH authentication/retries, model failover, relay and gateway health or recovery diagnostics.

- Windows supervisor console/resident connect probes allow five seconds (500 ms elsewhere). Only ConnectionRefused proves absence; timeout/other errors stay unknown. Connected consoles still require verified health and owner identity.
- dependency.rs provides bounded retry attempts, exponential capped backoff, total deadline, shortening-only jitter and Idempotency. Unknown accepted prompt/OneBot outcomes are Never retry. ReconnectBackoff doubles to a cap, warns once per outage and resets only after delivered traffic. Time/sleep are injected for tests.
- dsh_credential.rs alone owns the DSH login cookie: reading the selected root's secret, minting (issuedAt back-dated 60 s, expiresAt extended by the same amount so one hour remains), refreshing after a rejection, verified relogin, and classifying rejections. check_login sends with a fresh cookie and, after a 401, pauses 300 ms (capped by the probe deadline, so a secret rotation in progress is not read twice), refreshes once and repeats once; LoginWatch counts rejected fresh cookies in a row across checks (an acceptance resets, no answer leaves it) and fails at two. Health part `dshLogin` reports it; the live probe loop records `login-rejected` and sends one notice alert per failing streak naming clock skew and a DSH version change; the alert stays owed until notify_notice accepts it (no ownerQQ, hourly cap or key window refuse it): it is offered at once on the failing edge, then at most once per 60 s per scope (parity clock); recovery clears it (`login-accepted` on recovery). dsh.rs only carries the cookie as an opaque header.
- DSH call/call_with_rpc_id refresh the credential and repeat the same request ID once after 401, including prompt (401 proves refusal). No request repeats more than once for authentication. Task call_with_cancellation uses the same credential refresh with a shared deadline and cancellation checks across connect/read/write and before/after refresh; it never retries after stop. Bounded metadata call_with_deadline returns 401 without reauthentication. Verified relogin (up to four tries) remains for creation, selection and chat refresh; only --selftest-401 disables reauthentication. DSH home resolves explicit DSH_HOME or USERPROFILE/.dsh, never a hardcoded personal directory; selected roots use their own credentials/presets.
- Every DSH RPC path, with or without a deadline or credential refresh, requires a `server-response` with the request's exact string `rpcId` before reading `result`. Missing, non-string or different IDs return `RPC response identity mismatch（<endpoint>）`.
- Model selection occurs once per session, then on failover, replacement or changed candidate chain, starting at a sticky degraded candidate. SELECT_MODEL permits two attempts one second apart; 401 refresh does not consume an attempt. Shared per-root failover state survives per-turn Pipelines, with a two-retry per-conversation cap across messages until completion. Default effort is max; fallback inherits primary effort. Only explicit turn/end error or refused selection/prompt fails over. Timeouts/stream loss leave unknown work: stop DSH and rotate token; never deliver the prompt to another candidate. Failure to prove stop pauses the turn.
- Selected CLI children keep their profile under `data/cli-profile`. Each launch reads the bound `cliModel.apiKey` from Settings. When set, it supplies `ANTHROPIC_AUTH_TOKEN` and `ANTHROPIC_API_KEY` with `ANTHROPIC_BASE_URL` at the selected `model` origin, and `OPENAI_API_KEY` with `OPENAI_BASE_URL` at that origin plus `/v1`. `OPENCODE_GO_API_KEY` and `OPENCODE_API_KEY` are exported alongside both base URL variables. An OpenCode provider profile must select the corresponding relay URL. With no bound key, a nonempty supported alias in the explicit candidate environment supplies credentials. If neither is available, launch returns a configuration error directing the operator to `cliModel.apiKey` in Settings and health reports the advisory for configured CLI candidates. The selected child receives no ambient credential or DSH home variables. Provision the relay key and any required local CLI profile configuration in the selected runtime before the first CLI turn.
- CLI fallback after an exhausted DSH chain requires backends.failoverFallback exactly true. Explicit conversation-pinned backends remain independent and record their answers. Configuration of CLI backends alone enables no fallback.
- Harness turns use their own candidate chain (`harness.routes`), failover, sticky degraded route and retry cap (`docs/agents/harness.md` "Model routes and failover"); they never read the DSH chain (`dsh.provider`, `dsh.model`, `dsh.fallbacks`, `sessions`) and have no CLI fallback.
- AlertLimiter reads `alerts.keyWindowSecs` (default 60, range 1–3,600) and `alerts.hourlyCap` (default 10, range 1–100) for each admission. Deduplication is per key and runtime. The sliding hourly cap is per budget and process, and admission spends it even if delivery fails. An edit uses the existing timestamps. notify_owner and notify_admin share a budget; notify_notice and notify_memory (memory-layer alerts) each have a separate budget. A bounded queue/one worker sends redacted messages capped at 800, without retry; full queues drop and record. Gap notices use persisted per-window delivery claims; confirmation, refusal and unknown-send handling are specified in `docs/agents/sessions-recovery.md`. Missing owner logs only. Model failure, refused prompt, blocked reply, feedback, crash and recovery notices never go to groups.
- The supervisor starts and adopts the permanent loopback model relay. Initial DSH startup waits for relay readiness. The reconciler and shared health check use the same nominal three-second budget for one authenticated `GET /v1/models` on Windows and Linux. Connect, writes and buffered reads share the deadline, and health respects a shorter caller deadline. Both require HTTP 200 within a 512-byte status-line cap. A failed probe fails the shared health verdict immediately. Thread scheduling can overrun a socket deadline. The serial reconciler can also spend time on the locked hang recheck and on an administrator notice, whose gateway check and send have their own timeouts, before checking DSH.
- A refused or timed-out relay connection advances the two-minute hang timer and preserves the probe-failure streak. A request or response failure after connecting advances both. Other connect errors make the port observation unknown and reset the timer. A successful probe clears both. A new process identity starts a fresh streak. A replacement supervisor treats its timer restore as complete only after publishing the restored state. On the third failed probe the worker durably records the refused state, reason and pending notice together. It logs the refusal once and delivers the administrator notice using its fingerprint, even if the relay exits, enters backoff or the lifecycle gate is busy. A replacement resumes pending delivery. A known pre-send refusal remains pending and an uncertain send is never repeated. Under `lifecycle.lock` hang recovery verifies desired state, listener ownership and process identity, then rechecks the configured address before stopping the process. Relay pinning and private files are specified in `docs/agents/lifecycle-tasks.md`. Diagnostics omit keys, login data and upstream response bodies.
- Supervisor outage notices use a persisted pending/attempting/sent/unknown checkpoint and the notice rate budget instead of the fire-and-forget queue; `docs/agents/lifecycle-tasks.md` owns their delivery and replacement contract.
- run_record.rs JSONL fields are v/seq/ts/runId/trigger/component/event/outcome/reason, with repeat/firstTs/lastTs collapse summaries. Reasons redact credentials, paths and long opaque strings, at most 300 characters. Identical records collapse only inside their explicit run/window; byte caps compact storage and appends terminate torn tails. recovery_log binds the selected root's shared writer. Authenticated GET /api/recovery-record is newest-first, limit 1–200, before cursor plus component/outcome filters; no-root contexts have no record.
- DSH health probes authenticated settings/describe every five seconds and observes failed calls. Down/up edges record once; recovery alerts once. DSH-dependent chat/closed-agent, reserved and reserved2 work waits without repeated DSH calls. Chat leaves the queued head in place while DSH is down. Each conversation retains at most 50 items (oldest dropped/recorded), no global cap/time limit. Recovery redispatches through all epoch/access checks. Interrupted queued work after restart is reported and never blindly resubmitted.
- dependency-health.json is atomically published every probe for console status. Missing/stale file means DSH not ready and gateway unknown; administrator status does not call DSH itself. Gateway health uses heartbeat good/status, a 60-second get_status poll, edge-triggered warning and recovery. Each dependency-watch iteration reads `snowluma.silenceWarnMs` (default ten minutes, range one minute to one day). Silence begins strictly after that interval since the last packet.
- A reserved2 wake on the harness or the pinned CLI can run during a DSH outage when admission needs no DSH work. A handover that still needs its captured archive keeps the wake parked even after the live mapping disappears. A CLI pin takes precedence over the global engine default. The conversation's own stored harness choice overrides that pin. Failed CLI turns never re-run. At the reserved2 cap, a running pinned-CLI or first-session DSH turn without a DSH session mapping loses its dispatch token, so a late reply or submission cannot use it. A newly independent route releases waiting wakes through the same validity checks.
- Gateway reconnect is two seconds doubling to 30; event streams three to 30. Failed connect/close self-heals the SnowLuma token at most once per ten seconds: configured token, then configured home's account files, tested by get_login_info. Successful HTTP/account WebSocket token changes update selected config under the social gate, and discovered endpoints unless followDiscoveredEndpoint is false. dependencies.json endpoints are never copied into config. Logs name changed fields without values.
- Panic records last-crash.json; the next live start deletes it and privately alerts with redacted message/time. A resumed turn whose interrupted ingress was never handed back is reported once per event and never rerun. Rust process integration tests use tests/fixtures/dependency-recovery-cases.mjs and the fault-injecting fake-world.mjs with --features parity-clock; all endpoints are synthetic loopback servers.

- A pinned CLI failure ends the turn without conversation output, DSH replay or wake-reminder replay. Agy always requests `--output-format json` and accepts its `response` field. Other CLI results accept recognized answer envelopes or plain text free of error/refusal shapes; unknown structured output, nonzero exits, empty answers and diagnostics fail before relay. Each failed fallback candidate retains its own backend identity in reporting. CLI failure text contains classified metadata, command ID and exit code; trial logs reclassify failures before writing and retain no stdout/stderr.
- Model/backend failure alerts contain conversation key, backend/provider/model and error class/code only, never provider messages or chat content. DSH, CLI and harness share conversation/class deduplication through the bounded owner notifier's live alert limits. Refusal alerts say a blacklist search will run; the external watcher belongs to the coordinator.
- Refusals append metadata to selected `<data>/logs/model-refusals.jsonl`. The base fields are millisecond `time`, conversation `key`, `backend`, `provider`, `model`, `errorClass`, `errorCode` and `messages`. Each message reference contains only the carried `messageId` and/or `seq`. Preserve this production format for external readers. References come from structured wake and tool packets, including in-turn waits and unread reads. Each backend/provider/model identity records once per turn independently of alert deduplication. Empty candidates, safety/policy blocks and DSH `EMPTY_RESPONSE` are refusals. Quota, network, timeout and plain empty answers are separate classes and write no refusal record.
- The optional `turnId` and one-based `modelCall` locate a harness turn's refused request. This index includes model retries and failovers. A DSH refusal with a durable submission binding also records the `rpcId`, and its index is relative to that DSH submission. Count completed tool steps once per step and include retry starts. If DSH omits step metadata, the record omits the index.
- For DSH blacklist replay, match `turnId` and `rpcId` against `turn` and `rpcId` in `<data>/turn-ledger.jsonl`. The matching `attempt` row supplies the DSH `sessionId` and the matching `dsh_turn` row supplies `dshTurn`. Find that turn in the retained session history and use its prefix through the failed model call. Keep earlier tool results with their originating calls, matching `tool/result` to `tool/call` by call ID. The tool outputs already in history are the input to replay. For harness replay, see [Blacklist replay](harness.md#blacklist-replay).

- All diagnostic stdout/stderr, live/decision JSONL and activity text mask exact known conversation tokens, including separators made of spaces, LF/CRLF or Debug/JSON `\n`/`\r\n`/`\t`, plus maximal contiguous 48-ASCII-hex runs. This is independent of `security.outboundGuard`. Mask complete sources before JSON serialization, Markdown rendering, newline flattening or preview cuts; crash markers and panic stderr follow the same rule; preserve existing credential redaction. Longer hashes and ordinary text stay unchanged. Pipeline summaries remove a leading case-insensitive `thought` block through its first blank line, flatten newlines and show at most 80 Unicode characters plus an ellipsis. Local masking raises no owner alert; HTTP response payloads and alert wording retain their existing contracts apart from token masking.

## Crate contracts

Diagnostic stdout/stderr, live JSONL, activity logs and textual harness records mask known session tokens (including whitespace and escaped line breaks) and contiguous 48-hex token shapes independently of the outbound guard. Mask complete text before any preview cut; pipeline summaries omit leading reasoning. Protocol responses and alert wording retain their contracts. Canonical harness messages retain opaque binary/signature data and use safe aliases for sensitive protocol references. Details: `docs/agents/dependency-recovery.md` and `docs/agents/harness.md`.

Every DSH RPC entry point requires a `server-response` whose string `rpcId` matches its request before reading `result`; a mismatch returns `RPC response identity mismatch（<endpoint>）`. Authentication and retry rules: `docs/agents/dependency-recovery.md`.
