# Dependency recovery and alerts

Read for DSH auth/retries, model failover, relay/gateway health, CLI endpoints, refusal replay or alerts.

## DSH credentials, RPC and admission

- **Probes & `dependency.rs`:** Windows supervisor console/resident connect probes allow 5s (500 ms elsewhere); only `ConnectionRefused` proves absence (timeouts/others = unknown; connected consoles still require verified health + owner identity). `dependency.rs` owns bounded retries, exponential capped backoff, total deadline, shortening-only jitter, `Idempotency` (unknown accepted prompt/OneBot outcomes = `Never` retry), and `ReconnectBackoff` (warns once/outage, resets after delivered traffic; injected clock/sleep for tests).
- **`dsh_credential.rs`:** solely owns DSH login cookies (minting `issuedAt - 60s`, `expiresAt + 60s` -> 1h life; `dsh.rs` carries opaque header only). `check_login` pauses 300 ms (capped by probe deadline) after 401, refreshes once and retries once; `LoginWatch` counts consecutive fresh-cookie rejections and fails `dshLogin` health at 2 (`login-rejected`, 1 notice per failing streak naming clock skew/DSH version, owed until `notify_notice` accepts, offered on failing edge then `>=60s`/scope via parity clock; cleared with `login-accepted` on recovery).
- **DSH RPC & auth:** `call`/`call_with_rpc_id` refresh and repeat same `rpcId` at most once after 401 (incl. prompt; 401 = refusal). `call_with_cancellation` shares deadline + cancel checks across connect/read/write/refresh (never retries post-stop). `call_with_deadline` returns 401 without reauth. Verified relogin (<=4 tries) runs for create/select/chat-refresh; only test fixtures (`dsh_credential::Credential::fixed`/`fixed_in`) disable reauth. DSH home uses `DSH_HOME` or `USERPROFILE/.dsh` (never hardcoded personal dir). Every DSH RPC requires `server-response` with matching string `rpcId` pre-`result`, else `RPC response identity mismatch（<endpoint>）`.
- **Admission & ADR 0005:** DSH admission rechecks reserved2 allow/deny access; revocation during session creation cancels admission or retires/archives the created session (local admission cancellations skip error notes/alerts/health/retries). ADR 0005 calls `settings/describe` on local npm DSH (`her/dsh-contract-versions.txt`, `docs/agents/rust-validation.md`), requiring 200 on minted cookie and 401 on future-issued cookie.

## Model failover, CLI endpoints and outage isolation

- **DSH model failover:** selects once/session, then on failover/replacement/changed chain starting at sticky degraded candidate. `SELECT_MODEL` allows 2 attempts 1s apart (401 refresh excluded). Shared per-root failover state caps 2 retries/conversation across messages until completion (`max` default effort; fallback inherits primary). Only explicit `turn/end` error or refused select/prompt fails over; timeout/stream loss stops DSH and rotates token without trying another candidate (unproven stop pauses turn).
- **CLI endpoint & keys (`data/cli-profile`):** each launch resolves canonical effective endpoint `E` and bound `cliModel.apiKey` via `settings::resolve_model_endpoint_and_key` (`harness.apiBaseUrl` in `settings.db`, else `config.json`, else `dependencies.json` `"model"` baseline `D`). If set for `canonical(E)`, sets `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY` + `ANTHROPIC_BASE_URL=E`, and `OPENAI_API_KEY` + `OPENAI_BASE_URL=runtime::model_openai_base_url(&E)` (`/v1` appended only to bare origins). `OPENCODE_GO_API_KEY`/`OPENCODE_API_KEY` export alongside both URLs only when `canonical(E) == canonical(D)`, and OpenCode CLI backends fail closed when `E != D` (advised in health; OpenCode profile must match relay URL). Ambient supported env aliases apply only when `canonical(E) == canonical(D)`; otherwise missing bound key returns config error pointing to `cliModel.apiKey` in Settings + health advisory. No ambient cred or DSH home vars passed.
- **Fallback & failure lines:** CLI fallback post-DSH requires `backends.failoverFallback === true` (conv-pinned CLI stays independent). Persona `failureLine` (`docs/agents/prompts-modes.md`) runs only when all allowed routes/fallback or pinned CLI fail terminally (never on local access/policy refusal, cancel, unknown, unsubmitted retry-budget-remaining reserved2, or success). Harness uses `harness.routes` only (`docs/agents/harness.md` "Model routes and failover"), never DSH chain or CLI fallback.
- **Outage isolation (`#297`):** reserved2 wake on harness or pinned CLI runs during DSH outage if admission needs no DSH work (pending handover archive keeps wake parked). CLI pin overrides global engine default; stored conv `harness` overrides pin; failed CLI never re-runs. At reserved2 cap, running pinned-CLI or first-session DSH turn without mapping loses dispatch token.

## Relay, gateway health, alerts and refusals

- **Relay health & hang detection:** `GET /v1/models` (3s socket budget, 512B status-line cap, HTTP 200; failed probe fails health at once). Refused/timed-out connect advances 2-min hang timer (keeps failure streak); post-connect failure advances both; other connect errors reset timer; success clears both; new process identity resets streak; replacement supervisor publishes restored timer state. On 3rd failed probe, durably records refused state + reason + pending notice and sends fingerprint-deduped owner notice even across exit/backoff/busy gate (non-committed returns to pending; unknown never repeats). `lifecycle.lock` hang recovery rechecks desired state/listener/identity/address pre-stop (`docs/agents/lifecycle-tasks.md`). Diagnostics omit keys/login/upstream bodies.
- **DSH/Gateway probes & crash recovery:** DSH probes `settings/describe` every 5s (down/up edges once; chat queues head up to 50/conv; recovery rechecks epoch/access; interrupted queued work reported, never auto-resubmitted). `dependency-health.json` publishes each probe (missing/stale = DSH unready, gateway unknown). Gateway heartbeat + 60s `get_status` + `snowluma.silenceWarnMs` (default 10m, 1m-1d; edge-triggered). Reconnect 2-30s (event streams 3-30s); SnowLuma token self-heals <=1/10s (config -> home files -> `get_login_info`, updates config under social gate + endpoints unless `followDiscoveredEndpoint: false`, never copies `dependencies.json`; SnowLuma upgrades via `her-cli dependencies upgrade snowluma` atomically update/roll back bundled `program` and `snowluma.{homeDir,launcherPath}` when inside the old working directory). `last-crash.json` deleted on next live start with redacted owner alert. Tests: `tests/fixtures/dependency-recovery-cases.mjs` + `fake-world.mjs --features parity-clock`.
- **`AlertLimiter` & `run_record.rs`:** `alerts.keyWindowSecs` (60, 1-3600) per key/runtime and `alerts.hourlyCap` (10, 1-100) per budget/process (spent even on fail; `notify_owner`+`notify_admin` share, `notify_notice` and `notify_memory` separate; bounded queue 800-char redacted cap, no retry; missing owner logs only; errors never go to groups). `run_record.rs` JSONL (`v/seq/ts/runId/trigger/component/event/outcome/reason` + `repeat/firstTs/lastTs`, 300-char redacted reason, `GET /api/recovery-record` newest-first `1-200` + `before`/filters).
- **CLI classification & `model-refusals.jsonl`:** `agy --output-format json` (`response`); other CLIs accept stdout or recognized JSON (`response`/`result`/`text`/1st Chat Completions/1st Gemini text). Failures come from exit/deadline, HTTP error, explicit error/failure fields, or provider refusal metadata (successful answer may quote prose/diagnostics). Model alerts carry key, backend/provider/model, class/code only. `<data>/logs/model-refusals.jsonl` appends `{time, key, backend, provider, model, errorClass, errorCode, messages:[{messageId, seq}], [turnId, modelCall, rpcId]}` once per identity/turn (empty candidates, policy blocks, `EMPTY_RESPONSE` = refusal; quota/network/timeout/plain empty = separate, no refusal file). DSH blacklist replay joins `<data>/turn-ledger.jsonl` (`turn`+`rpcId` -> `sessionId` + `dshTurn`); harness replay uses [Blacklist replay](harness.md#blacklist-replay).
- **Token masking:** diagnostic stdout/stderr, live/decision JSONL and activity logs mask exact known conversation tokens (incl. spaces, LF/CRLF, `\n`/`\r\n`/`\t` breaks) and maximal 48-hex runs independently of `security.outboundGuard`, pre-JSON/Markdown/flattening/truncation; pipeline summaries strip leading `thought` block, flatten newlines and cap 80 chars + `…`.

## Crate contracts

Diagnostic streams, live JSONL, activity logs and textual harness records mask known session tokens (incl. whitespace/escaped breaks) and 48-hex shapes independently of outbound guard, before any preview cut. Every DSH RPC requires matching `server-response` string `rpcId` pre-`result` (`RPC response identity mismatch（<endpoint>）`).
