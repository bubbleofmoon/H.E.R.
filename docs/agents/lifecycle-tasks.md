# Lifecycle, owner gates and tasks

Read for supervisor startup/stop, desired state, signed releases, dependencies, relay ACLs, memory digest, backups/restore or task scheduling.

## Scheduled task and QQ login polling

- **`scheduled_task.rs`:** `her-cli install [--install-root <abs>]` (default `C:/qqbot`) registers single Windows logon task `HER` for caller SID (`InteractiveToken`/`HighestAvailable`, 3x 1m restart, no limit) -> `<install>/current/her.exe supervise --runtime-root <install>/runtime --install-root <install>`. `her-cli scheduled-task read|compare|remove` (compare exits 0 match, 3 drift/unreadable; COM BSTR XML read, hidden `schtasks.exe` UTF-16 BOM import, numeric HRESULTs, `UserId` compared by SID via `LookupAccountNameW`/`ConvertStringSidToSidW`). `HER_TASK_SCHEDULER_FILE` selects guarded file fake. Startup records `scheduled-task-check`, persists drift fingerprint in `data/scheduled-task-drift.json`, alerts once per fingerprint via `admin_alert::notify_notice`, clears on match. Tests never register `HER` (sole native round trip requires elevation + `HER-Test-*`; `#67` rehearsal uses `HER-Test-67-<guid>-*`).
- **QQ login polling:** supervisor polls every 30s (even with bridge down), persisting `data/qq-login-episode.json` under authority gate (`>=1m` retry spacing across restarts; `admin_alert` rate limits; confirmed delivery marks notified; confirmed login rearms).

## Signed releases, installation and handover

- **Discovery (`release.rs`):** `update.feedUrl` (default `https://api.github.com/repos/bubbleofmoon/H.E.R./releases`), tags `vX.Y.Z`, `update.policy` `off|notify(default)|auto`. HTTPS required (except loopback HTTP test fixtures) over `guarded_fetch.rs`.
- **Signed trust (`release_signature.rs`, v0.1.0+):** newest eligible release must carry `SHA256SUMS` (`<=1 MiB`) + `SHA256SUMS.minisig` (`<=4 KiB` Minisign Ed25519; `minisign-verify`), with `# HER-RELEASE vX.Y.Z N` (`N >= 1` non-decreasing; key changes bump `N` and require current signer retention) and `# HER-KEYS <primary> <backup>`. Verified current metadata supplies authority/floor (no external proof store; missing/invalid current recovers from newest verified `last-good`/previous link -> newest verified installed release; compiled bootstrap pins apply ONLY with zero versioned `vX.Y.Z` dirs/links and reject release/optimized/no-debug-assertions builds; replace placeholder pins before v0.1.0!). Install root is trust boundary (keep writable only by HER/admins); root `<install>/herupdate.exe` is exact verified buffer. Manual recovery: `<install>/herupdate.exe --recover --target <tag> --old-pid <pid> --old-start <start> --old-exe <exe>`.
- **Staging & worker (`release_store.rs`, `update.rs`, `handover.rs`):** `her-cli release install` verifies all 3 image hashes + `SHA256SUMS`, stages in `.staging-her-release-v1-<pid>-<ms>-<seq>`, publishes `releases/<tag>` atomically (occupied tag refused). Installed supervisors check at start + every 6h (`data/releases.json` v3 under `data/locks/release-check.lock`, released across feed I/O; post-I/O takes `update-restore.lock` -> `release-check.lock`).
  - **4-lock hierarchy:** `update-restore.lock` -> `turn-update.lock` -> `release-check.lock` -> `social-v2.lock`. Console `POST /api/releases/approve` (`confirm:true`) takes `update-restore.lock` (500 ms retry -> 409) -> `release-check.lock` -> `social-v2.lock`; chat `/update` under `turn-update.lock` takes `release-check.lock` -> `social-v2.lock` (non-blocking probe of `update-restore.lock`); supervisor auto-update (`autoAttempted`) takes `update-restore.lock` -> `turn-update.lock` outside `release-check.lock`. Auto admits only when turn ledger is idle (helper waits <=120s for exclusive `turn-update.lock` pre-retire; `--auto` rechecks ledger idle); manual approval drains active pipelines.
  - **Handover & rollback:** `her-cli release handover --runtime-root <install>/runtime --tag <tag>` re-verifies `last-good` (and current) before retiring owners, swaps `current`, runs candidate `assert-running` (<=120s total, 5s/probe; read-only trial uses `HER_TRIAL_CURRENT`), and updates `last-good` on pass. Failure/3 starts in 10m (`<install>/update-starts.json`, `locks/update-starts.lock`) rolls back to verified `last-good` via `update-alert.json` (`runtime/data/locks/update-alert.lock`, `pending` deferred while failed release sees `update-restore.lock` held). Prunes ordinary `vX.Y.Z` dirs keeping newest 3 + `current` + `last-good` (`herupdate.exe --prune --install-root <install>`).

## Owners, process identity, health and desired state

- **Owner locks:** `OwnerRole::{Live, Console, Supervisor}` hold `data/logs/rbridge-{live,console,supervisor}.lock` (never deleted/truncated; atomic pid/start/exe/groups marker). `lifecycle.rs` owns `check_live_heartbeat` (90s freshness, `live: true`, matching groups -> `Ready` | `WaitingForGateway`), `verify_live_heartbeat` (`Ready`), `LifecycleBackend`, `verify_owner` (`ProbeMode::{Existing, Create}`, `ImagePolicy::{SameReleaseTwin, ReleaseTag, HealthReadOnly}`), `stop_verified_owners_transaction` (rechecks under `lifecycle.lock` after `hold_stopped_task_gates`), `retire_verified_owners`.
- **`process_identity` & CLI:** verified kill pins handle/pidfd and rechecks PID/start/image. Diagnostics: `her-cli process identify|match|check --pid <id> --runtime-root <root>` (`resolved_script` ignores npm/npx wrappers); `her-cli stop-supervisor`.
- **`her-cli lifecycle assert-running --runtime-root <abs> [--wait <dur>]`:** read-only `health_check::check` (exit 0 all pass, 1 unhealthy JSON, 2 CLI syntax; 5s/snapshot). Parts: `desired`, `supervisor`, `console` (`/api/health`), `snowluma` (`status:ok, online:true, good:true`), `relay` (if configured), `dsh` (`settings/describe`), `dshLogin` (fails on 2 consecutive 401s). Top-level advisories (never fail `ok`): `scopeNotices`, `modelRoutes`, `live` (`not-running`|`waiting-for-gateway`|`ready`|`unready`|`unverified`), `cliModelNotice`, `dependencyNotices`. Checker accepts own exe or same-dir twin (`HER_TRIAL_CURRENT` only for installed trial).
- **Desired state (`data/lifecycle/desired-state.json`, `locks/lifecycle.lock` 5s):** `running|stopped|maintenance` (expired maintenance = running; unreadable = unknown, starts/stops nothing; exit 3 on write failure). `session_map::verify_cutover` + `prepare_live_startup` validate rollout/pipeline before writing `rust-heartbeat-live.json` (`waiting-for-gateway` -> `ready`; `watchdog_tick` uses `read_heartbeat_for_owner` and restarts on 2 bad heartbeats or `rollout.rustGroups` drift). Restart queue holds config gate. `process_tree.rs` contains CLI/task/npm child trees (Windows Job Object `KILL_ON_JOB_CLOSE` / Unix `process_group(0)` + `SIGKILL`).

## Dependencies, relay and upgrades

- **Config & pins:** `dependencies.{snowluma,dsh}` (`program`, `script`, `workingDirectory`; `_npx` refused for pinned DSH; `DSH_HOME=<runtime>/user/dsh`, `SNOWLUMA_HOOK_AUTOLOAD=1`; endpoints in `dependencies.json` must be distinct loopback origins). `dependencies.relay` opt-in (`program`, `arguments`, `workingDirectory`, `version`, `loginDirectory`, `clientKeyFile` all inside `<deps>/relay/<version>`, no symlinks/inline keys; probed via `GET /v1/models` 3s/HTTP 200; startup order: SnowLuma -> relay -> DSH).
  - Relay ACLs (`guarded_fs::ensure_entry_private`): version dir restricted to HER account only (`0700` Unix; Windows `PROTECTED_DACL` for process token SID with object/container inheritance, no `WRITE_OWNER`/SYSTEM/Admins, retries `ERROR_DELETE_PENDING` <=250 ms and skips vanished files; relay stdout/stderr discarded; no creds in alerts).
  - DSH pin (`dependencies.dsh.version`): exact semver listed in `her/dsh-contract-versions.txt`; managed install `<deps>/dsh/<version>` via guarded npm (`10m` cap, `.installer.json` owner marker, `dsh.installRetry` 10/20/40/60m backoff).
- **Monitoring & recovery (`data/lifecycle/dependencies.json`):** native listener PID + `process_identity` program/script/start check (Linux rechecks TCP table; inaccessible non-matching image ignored on start only; 30s defer for unresolved npm/npx wrapper; 90s listen wait; 2-min refused-connect hang recovery under `lifecycle.lock`; backoff 5/30/60s, 3 fails in 10m -> notice, 10m healthy clears; `[epoch-ms] refused: <reason>` in `dependency-<name>.err.log`). `her-cli stop --confirm [--with-dependencies]` stops verified dependencies only.
- **Upgrades (`dependency_upgrade.rs`, `data/lifecycle/dependency-upgrades.json`, `data/locks/dependency-upgrades.lock`):** discovers startup + 6h (`GET /api/dependencies`, `POST /api/dependencies/check`; DSH npm registry; SnowLuma GitHub `SnowLuma-v<ver>-win-x64.zip` + `sha256:`; relay none). Never auto-approves; supervisor consumes under install/restore gate -> exclusive turn admission -> launch gate (stages beside old -> verified stop -> copies SnowLuma `config/`+`data/` -> restricts ACLs -> 90s readiness + health check; unfinished upgrades recover pre-reconciliation).

## Memory digest (`digest.rs`)

- **Actions:** `memory-digest` (daily at `memory.digest.time` 03:00, any conv with new msgs) and `memory-digest-check` (every 30m at `memory.digest.checkMinute` 21, backlog >= `contextPct`% of `socialV2.context.recentLimit` [defaults 70/100]). Holds `data/locks/memory-digest.lock` (concurrent skips cleanly); stops on cancel/stop/maintenance pre-conv, pre-model and pre-write.
- **Evidence & cursor:** reserved2 reads `recentMessages` (`msg`); others read handled/backfilled `inbound.db` (`inbound`) merged with completed `conversations.db` replies (drops slash, recovery cmds, own `self_id`/`message_sent` echoes; passes `model_view`). `memory.digest.maxInputChars` (12000, 1000-100000; keeps room for cursor advance); `digest::PROMPT` yields <=8 `{subject, content}` written as `inference` (`digest:<conv>:<space>:<first>-<last>`) + `digest_cursor` (`replies_ms`/`replies_seq`) in 1 CAS tx.
- **Limits & model:** `memory.autoFlush.{enabled, contextPct(1-100), maxSessionsPerDay(0-100, default 8), minIntervalMinutes(0-1440, default 60)}`; oldest cursor first; empty/slash/interrupted pages advance cursor (`<=64` pages) without moving `replies_*`. Uses `harness/one_shot.rs` (`memory.digest.model` solo, else `harness.routes` chain under `memory.digest.timeoutSecs` 120/1-600; failures leave cursor and record failure time). Legacy `data/digest-{state,dispatch}.json` unread.

## Backups and restore

- **Full & nightly memory backups:** internal Rust (no child): snapshots `memory.db`, optional `conversations.db` & `settings.db` (SQLite online backup; `settings::backup_source` requires plain 1-link files + `locks/settings-store.lock`, retries sidecars 5s, v3 scrubs browser sessions + auth singleton via SQLite secure delete), `config.json`, `data/*.json`, `resources/{roles,patches,docs,说明.md}` into verified ZIP (`manifest.json` v1 SHA-256 + `PRAGMA integrity_check`). Shared `ArchiveScope`, `backup::runtime_inventory`, `backup::archive_location`, destination lock `.her-backup.lock` (30s SQLite & dest locks).
  - Settings: `dir` (install-root runtimes resolve under install root; rejects `releases`/`deps`/`runtime`), `keepDays` (>=1, default 7), `time` (`04:00`), `includeState` (`true`). Retention removes `qqbot-YYYY-MM-DDTHH-mm-ss[-collision].zip` past `keepDays`.
  - Nightly memory backup (`04:00` -> `backups/memory`, fixed drive on Windows, schema+rowcount manifest, keeps 14 newest) & monthly restore test (1st of month `05:30`, verifies newest ZIP in throwaway runtime against manifest). Notice claims in `data/{backup,memory-backup,memory-restore-test}-notices.json` (`data/locks/backup-notices.lock`). `GET/POST /api/backups/settings`, `GET /api/backups` (3s verification cap -> `pending`, rejects agent creds).
- **Restore (`her-cli backup restore <zip> --runtime-root <abs> [--memory-only] [--preview] [--confirm <c>]`, `/api/backups/restore{/preview}`):**
  - Pre-stop: validates archive, staging, `backup.dir` (`backup::check_pre_restore_destination`), full-restore settings v1-3 + archive `config.json` (`backup::validate_archive_config`); `#443` preview warns if archive lacks endpoint keys (clears all 3 classes) or has different effective model endpoint (switches endpoint/creds).
  - Lock order: holds `update-restore.lock` + `restore.lock` + nonblocking `console-credential` gate -> stops owners -> `quiesce_stopped_gates` -> exclusive `locks/restore-writers.lock` (shared by unstopped `memory.db` openers & chat-tool writers before `social-v2.lock`) -> `backup::create_pre_restore_scoped` (`<zip>.restore-until` 7d pin) -> `config/social-state` -> `transport_authority` -> `settings-store` gate -> stages `data/console-restore-recovery/` & replaces files (1s OS 5/32/33 retry) -> releases gates -> reconciles `conversations.db` against turn ledger -> verifies health + live `Ready` within 2m (else auto-rollback + <=35s alert; `--recover` replays interrupted restore; audit `data/audit/audit.jsonl` + `data/logs/restore.log`). Memory-only replaces `memory.db` only.

## Tasks and schedule

- **`TaskStore` (`data/tasks`, 5s `store.lock`, 500 runs / 1 MiB compaction, 256 KiB + 200 lines / 2000 chars / 6-digit mask):** jobs (`watchdog` 2m, `memory-digest`, `memory-digest-check`, `backup`, `memory-backup`, `memory-restore-test`, `upstream-check` 05:00 off, `console-restart` manual; civil `time.zone` refreshed every 1s). Unix bootstrap execs in-group (`disarm_drop` preserves live descendants).
- **`her/src/schedule.rs` (`data/schedule.json` v1, `data/locks/schedule.lock`, `data/schedule-timers.json` <=60s publish / >120s stale):** stores owner/HER reminders (`reminders.{maxPerConversation:20, maxTotal:200, minRepeatMinutes:60[15..1440], maxAheadDays:365[1..366]}`; owner floor 15m / max 366d), `systemPaused` (pausable jobs only; unreadable store pauses all pausable jobs), timer cancels (120s TTL). Daily digest & backup require `>=30m` circular gap and cannot collide with `memory.digest.checkMinute` (`409` on collision). Console writes hold `config_gate` + recheck auth (`/schedule`, `302` from `/tasks`).

## Crate contracts

Release discovery/install/handover authenticate exact `SHA256SUMS` + Minisign bytes pre-acquisition (`release_store.rs`, `update.rs`, `handover.rs`, `herupdate` minimal per ADR 0003). Dependencies start SnowLuma -> relay -> DSH; `dependency_upgrade.rs` recovers interrupted upgrades pre-reconciliation. Backups/restores share `ArchiveScope` and lock order (`restore-writers.lock` -> `social-v2.lock`/`config_gate` -> `transport_authority` -> `settings-store.lock`), reconciling `conversations.db` against turn ledger before restart.
