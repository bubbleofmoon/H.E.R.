# Domain docs

Single context: `GLOSSARY.md` at the repo root, ADRs in `docs/adr/`.

- Before exploring code, read the glossary and the ADRs relevant to the work. If a file is missing, continue silently; do not create placeholders.
- Use glossary names in tickets, designs, tests and refactor proposals. When a needed term is undefined, check existing usage first and clarify it with the domain-modeling skill.
- When a proposal conflicts with an ADR, name the ADR and the reason to reopen it.
