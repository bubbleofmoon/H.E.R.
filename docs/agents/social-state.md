# Social state, access and sends

- `GET /api/qq/login` requires current console administrator or desktop-session authentication and refuses either agent header, including when combined with an administrator credential. It returns only `ok`, `state` (`logged-in`, `needs-login`, `unknown`) and verified native QQ `processes` (`pid`, `start`) needed by the desktop action. It returns no UIN, process path, upstream error text or dependency credential. The route probes read-only; only the supervisor claims episode alerts.

Read for social configuration, authorization, console writes, quotas, feedback or send ordering.

- Release approval uses `POST /api/releases/approve` with the displayed tag and explicit confirmation. It accepts current console administrator or desktop-session credentials, refuses either agent header, and rechecks authorization under the configuration gate before persisting approval. Host, origin and JSON checks match other console administration routes. Approval and execution contracts: `docs/agents/lifecycle-tasks.md`. Dependency approval uses `POST /api/dependencies/approve` with `confirm:true`, the displayed `name` and `version`, under the same current-credential, mixed-agent-header, Host, Origin and JSON checks. Dependency status/check routes share administrator-only access.
- Persona routes (`GET /personas`, `GET /api/personas`, `GET /api/personas/item?id=`, `POST /api/personas/{create,update,duplicate,delete,approve,assign,import-roles}`) are administrator-only: either agent header refuses with 403. They are mounted from `console_persona.rs` behind the console front (Host, credential, JSON, Origin, audit). Storage, validation and re-brief belong to `persona.rs`. Bodies name a conversation as `conversation`, never `key`.

- Reserved2 stores `text`/`plain`/`tail` as 200-unit previews. A message whose rendered text is longer also keeps `textChars` (its real length in UTF-16 units) and `textTruncated: true` in `recentMessages` and `unread`, and its `fullText` once, in `recentMessages` (the list message detail reads), cut on arrival at the `socialV2.context.fullTextMaxChars` then in force (default 4000, range 200..20000); a later setting change does not re-cut stored text. Model-facing message lists and tool results carry the preview and the two markers but never `fullText`; `qq_get_message_detail` returns the full text in `info.text` (by QQ message id or local seq) with `textChars` and `textTruncated`, true only when the message exceeds the cap it was cut at. A message not stored locally is read from OneBot up to the cap now in force.
- Selected `social-v2.json` mutations take `locks/social-v2.lock`, waiting up to five seconds. A busy holder returns 503 without writing. Config, mode, role and social-state atomic replacements also take `locks/authority.lock`. Sticker send/add/remark hold authority across fresh validation, connect and request transmission, releasing before the response wait. Social writers acquire the social gate first. Authority writers wait up to 20 seconds; other queued social writers can exceed their five-second bound during a transmission.
- Text, burst, poke, sticker and voice sends recheck token epoch, mode, allow/deny policy, role silence, pause, social enablement and the relevant tool flag before each item. Pokes recheck after the member lookup. Text/burst/sticker/voice share `console_agent::send_chain`. Sticker sends pause 800–2000 ms inside the chain, outside state gates, before the final guard and attempt. Debug/test-clock builds may override the pause; release builds ignore that override.
- Outbox `intent`, `attempt` and outcome are durable. Append locks cover `sync_all`; errors propagate. A torn final line is terminated before another append. Readers skip only truncation JSON errors, with a warning naming file/line; other corruption fails. Unknown delivery is never automatically resent. Text resume refuses sticker and voice batches.
- Sticker quotas reserve fresh independently identified pending liabilities before network work. Proven non-submission/refusal releases; confirmed and unknown outcomes settle into numeric quota arrays. Text checks include pending sticker sends. Ambiguous refunds retain quota. Confirmed history and settlement share one mutation; failed persistence keeps liability and reports partial success without a second gate wait. Confirmed collection remains successful if settlement fails. Pending reservations expire after one hour; settled arrays retain the newest 500 entries. OneBot connect/write budget is 15 seconds total, with connect at most five seconds; write failures remain unknown.
- Resets preserve only pending sticker liabilities and mark pending IDs revoked; settled timestamps and other conversation state are discarded. Already submitted operations can settle their own ID. Submission validates ownership under authority coordination.
- `socialV2.send.duplicateWindowMs` atomically marks duplicate text before quota reservation. Concurrent duplicate calls receive 429. Successful sends, rather than model text, update reply state and read watermarks.
- Selected console front checks Host against its bound loopback port before credentials, exempting icon no-ops and `/api/health`. Authenticated writes require `application/json` (415); supplied Origin must match the console (403). Agent credentials cannot reach administrator routes. Console agents need a live conversation token; paused/disabled/non-reserved2 contexts refuse social calls. Status/send/image exceptions remain explicit in `console_agent.rs`.
- `POST /api/desktop/sign-in` additionally requires a selected runtime, proof of reading `data/console-token` and a live Windows loopback peer whose token user matches the console's installing-user task principal. Both desktop and console validate the token file's native owner and DACL through the same pinned read handle, allowing only the current user, SYSTEM and Administrators; missing, unreadable or broadly accessible files refuse even with a configured token. `process_identity` resolves the full TCP tuple, pins the peer process and rechecks its instance and tuple; supplied PIDs confer no authority. Unknown identity and non-Windows callers refuse. Desktop sessions use existing console header/query authentication, expire after 12 hours and are revoked by credential rotation or console exit; at most 128 are retained. Every successful rotation advances a generation independent of token contents, so restoring a prior token cannot revive sessions. Issuance captures the generation before reading credentials. Sign-in secrets do not enter audit records. Debug seam-1 fixtures may further restrict the peer SID with `HER_TEST_DESKTOP_PEER_SID_HEX`; release builds ignore it, and it cannot authorize a different real peer.
- Memory routes accept raw `x-console-token` administrator credentials only against nonempty `cfg.consoleToken` (trimmed); a generated file token confers no memory authority. A valid desktop session bound to the effective credential and current generation also grants memory administration. Agent-token rules and console preflight authentication still apply.
- Whitelist/security/token/undo writes hold the social gate across fresh raw config read, atomic write and audit capture. Owner-only whitelist changes preserve existing alias lists; naming a root's list rewrites that root as `{private, groups}`. Access changes acquire the closed-agent interaction gate, retire revoked mappings, rotate every affected token, clear bootstrap, cancel turns and settle queued ingress before responding. A later re-grant creates a fresh epoch. Failures are reported even if another cleanup step succeeded.
- `qq_wait_for_messages` (`POST /api/socialV2/wait`) holds a generation lease per normalized conversation. A new wait supersedes the previous one, which returns `superseded: true` with no messages within one poll and records no observation; a dropped handler releases only its own generation. A console wait (no agent token) never supersedes an agent's wait: it is refused with 429 while one runs. Every reply/messages/quiet poll rechecks the lease. Agent waits also recheck the agent token: a poll whose state read fails is skipped, and only a read state with a different token or no conversation ends the call (403). A lone agent wait retires on token rotation within its polling interval (80/100/200 ms); console waits recheck the lease only.
- Whole reset records ledger reset `*`, settles ingress, retires mappings, writes fresh conversations with `resetEpoch`, cancels turns and stops DSH work. Manual reserved2 wake rechecks authority and mode, queues at most 20 epoch-bound admin wakes, buffers while busy and obeys rate limits. The hub cancels only the captured old DSH session across reset/mode changes.
- Audits record method/path/status/result/error/key without request bodies; changed files have blobs, with config tokens redacted. Failed audit leaves the operation's status and adds `audit.ok:false`. Undo supports config/role-map only, checks current `afterSha` under the state gate, retains the current console token, refuses token-change/no-file records and is itself audited. Retry of a `send-unresolved` turn needs `confirm:true`; abandon revokes its token first.
- `feedback.rs` exclusively owns `<data>/feedback.json`, newest 500 redacted entries. A process mutex and five-second OS gate serialize it. Non-array data is renamed before starting an empty array; failed preservation refuses the mutation. Agent submissions obey session/tool/length limits plus five/minute and twenty/hour; console submissions use the console policy. Owner error notifications deduplicate by key for 60 seconds, ten/hour.
- `activity.rs` owns redacted `<data>/qq-activity.log`, rotating after 500 lines and serving the newest 100 to the console only. Writes are best effort. Feedback, sends, ingress decisions, turn outcomes and slang completion record their activity. Pause affects reserved2 scheduling and agent gates; resume does not replay old pending wakes. First-generation and chat modes ignore pause.

- Outbound replies and console text/voice requests read `security.outboundGuard` per reply/request. Only boolean `false` disables the outbound sentinel, sensitive-reply hiding and blocked-reply notices; missing, invalid and `true` preserve the default guard. `security.interceptNotify` separately controls notices while enabled. Model-input stripping and owner-only model/backend failure routing remain independent of the switch.
