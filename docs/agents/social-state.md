# Social state, access and sends

Read for social configuration, console authorization, settings/persona/inspector routes, quotas, mutes, feedback or send ordering.

## Console routes, auth and settings API

- **`console_front.rs` & `console_ui.rs`:** declarative route-policy table (`RoutePolicy`, `EXACT_ROUTES`, `route_policy`, `supports_request`) enforces Host, Origin, JSON (`1 MB` / `413` `bounded_post_body_too_large`), `AgentPolicy`, `KeyPreflight`, `SessionCookiePolicy`, and `admit_selected_request` -> `VerifiedCaller`/`AdminCaller`. Embedded SPA (`her/build.rs`, `HER_REQUIRE_UI_DIST=1`) serves HTML & `/assets/*` with `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; connect-src 'self'; form-action 'self'; base-uri 'none';`; `302` redirects (`/personas->/persona`, `/tasks->/schedule`, `/settings/conversations->/conversations`, `/settings/models->/models`); unknown `/api/*` never falls back to HTML. Unreadable config returns 503 pre-route; revoked proof returns 401; unavailable store returns 503.
- **Browser & machine auth (`/api/auth/*`, 1 MB body cap, agent headers 403):** canonical URL `http://her.localhost:<port>` (aliases redirect GETs stripping query; health/icon public). Native requests without Fetch Metadata accept machine token (query-token precedence); desktop bearer works with Fetch Metadata. Browser writes need canonical Origin + `application/json`; grants also need canonical Host and non-cross-site Fetch Metadata. On Windows, unauthenticated page GET on `http://her.localhost:<port>` without token/agent markers issues a browser cookie (`her_browser_<port>_<digest>`, HttpOnly, SameSite=Strict, `Max-Age=604800`, <=128 sessions, 1m backward-clock invalidation) if `same_installing_user` passes and `security.requirePasswordLocally` is `false` (default).
  - `/api/auth/status`, `/first-run` (Argon2id 8-1024 chars -> `settings.db` + `(hidden)` audit; subsequent -> 409), `/login` (5 consecutive failures trigger 1/2/4/8/15m throttle -> 429 `retryAfterMs`/`retryAfterSeconds`; reset/login clears), `/logout`, `/change-password` (rotates `auth_generation`), `/sessions`, `/sessions/revoke` (`credential_mutation_gate -> config_gate -> browser_anchors -> store_gate` in `console_auth.rs`, Argon2id outside gates).
- **Admin routes (reject `x-agent-token`/`x-agent-call` with 403, recheck cred under `config_gate`):**
  - `GET /api/qq/login` (desktop or admin; returns `{ok, state, processes:[{pid,start}]}` only, no UIN/paths/creds), `POST /api/releases/approve`, `POST /api/dependencies/approve`, `/api/preset/sim-prompt`, `/inspector` (`GET /api/inspector/{conversations,turn}`, admin/desktop/browser, GET-only -> 405), `/api/personas*` (`console_persona.rs`, body uses `conversation`, never `key`), memory ACL routes (native `x-console-token` / desktop bearer / browser POST + Origin + JSON; generated file token has no raw memory admin).
- **Settings routes (`console_settings.rs`, `console_settings/{conversation,models}.rs`, `/settings`, `/conversations`, `/models`):**
  - `GET /api/settings`, `POST /api/settings/{set,reset,undo}`, `GET /api/settings/history` (`100`/page via `before` cursor), `GET /api/settings/conversations`, `POST /api/settings/conversation/{set,reset,switch}`, `GET /api/settings/models` (DSH catalog `GET /api/dsh/model` stays until #13). Bodies use `setting`/`conversation`, never `key`. Errors: 400 invalid value/id or scrubbed/credential-bearing `harness.apiBaseUrl` undo (incl. `source: migration`, checked pre-`409` `migration`), 404 unknown undo entry, 409 credential/secret undo, superseded/retired/`access`/`migration`/`switch-rollback`/unadmitted conv, or missing `"confirm": true` on security settings, 503 store/mirror-removal fail (`mirrorError` on non-undo write-back fail). `conversation.route` reset stores JSON `null` (`configured order`), overriding `harness.firstRoute` rather than inheriting it.
  - Page saves (`POST /api/socialV2/config`, `POST /api/backups/settings`) route changed registry members through `settings.db` (1 `ConfigDiff` audit); direct `config.json` writes modifying registry members refuse (`<key> changes only through the settings store`).
  - `/conversations` Switch waits up to 180s for unsettled turn (409 otherwise); failed switch restores prior choice (`switch-rollback`) or retries on 5s->10m backoff. Access loss clears scoped settings in 1 tx (`source: access`, un-undoable).
  - `#443` model routes & credentials: `GET /api/settings` exposes `isSet`, `boundElsewhere`, `source` (`settings`|`file`|`null`) on `harness.apiKey`/`cliModel.apiKey`, and `fallback` on `harness.apiBaseUrl`; `GET /api/settings/models` exposes `effectiveModelEndpoint`/`effectiveModelEndpointSource`, redacted chain + route health + pricing + per-conv `order` (`inChain`, skips DSH startup). `POST /api/settings/set` accepts optional `expectedEndpoint` only on `harness.apiKey`/`cliModel.apiKey` (400 otherwise/non-string; 409 on canonical mismatch). Clearing `harness.apiBaseUrl` invokes `reset`; `ModelRoutesTab` validates secret drafts and snapshots inputs, saves/resets dirty `harness.apiBaseUrl` first, and aborts secret saves if validation or URL write fails; `harness.routes` edits validate 1-8 routes and mask stored creds (`redacted: true` opens blank replacement).
- **`/api/socialV2/config` & wake reconciliation (`config_tx.rs`):** returns/merges effective social config (defaults: `batchWindowMs` 8000, prob 0, proactive enabled 0.4). Changes to default wake prob/window, social saves, audit undo and console startup run `social_state::reconcile_default_wake_configs` under `locks/social-v2.lock`.

## Social state, access, sends and mutes

- **State & lock order:** `conversation_state.rs` owns `social-v2.json` (`locks/social-v2.lock`, 5s wait -> 503; `social-v1.json` under `locks/social-v1.lock`) protecting reserved keys (`token`, `generation`, `unread`, `impressions`). `social_state.rs` owns `SocialError`, `SessionStopper`, `StopTracker`. `config_tx.rs` executes coordinated config/settings/access/wake transactions (`ConfigDiff` via `CommitOutcome`/`CommitError`) under `locks/restore-writers.lock -> credential_mutation_gate -> closed_agent::lock -> config_gate (locks/social-v2.lock) -> locks/authority.lock (20s wait) -> locks/settings-store.lock`.
- **Previews & `fullText`:** reserved2 stores 200 UTF-16 `text`/`plain`/`tail` plus `textChars` and `textTruncated: true` when longer; `recentMessages` keeps `fullText` capped at `socialV2.context.fullTextMaxChars` (4000, 200-20000). Model lists omit `fullText`; `qq_get_message_detail` returns `info.text` (from store or OneBot capped at current limit).
- **Send chain & confirmation (`recorded_send.rs`):** text/burst/poke/sticker/voice recheck epoch, mode, allow/deny, silence, pause, `socialEnabled` and tool flags per item; `recorded_send::send_chain` precedes `locks/authority.lock` (sticker pause `reply.stickerPauseMin/MaxMs` 800-2000 runs inside `send_chain`, outside state gates, pre-guard; `authority.lock` covers validation/connect/send and releases before gateway response or history read). `chat::send_recorded` / `send_chat_text` run via `recorded_send::off_worker` (`block_in_place` on multi-thread runtime). Approved group sends use `<groupEpoch>:<turnId>` scope (outbox resumes refuse `approved-group`, `owner-interaction`, `owner-interaction-timeout`, sticker, voice).
  - Outbox `intent`/`attempt`/outcome sync under append lock (torn tail terminated pre-append); unknown delivery checks gateway history for 1 matching own message post-attempt (unreadable outbox/missing id/other unresolved 24h batch stays unknown; never auto-resent). `duplicateWindowMs` checks duplicates pre-quota -> 429.
- **Group mute (`group_mute.rs`):** `data/group-mutes.json` (`locks/group-mutes.lock`, survives resets) separates `personalUntil` (-1 = unknown end) and `wholeGroup`. Updated by own `group_ban`, `user_id:0` whole-group notice, per-connect refresh (`get_group_member_info`/`get_group_info`, 10m unknown-end recheck), and retcode 100 `result=120` refusal (incl. 1st-gen CLI). Stale refreshes drop; muted sends fail locally with 403 `{ok:false,error}` (`muted until HH:MM`; CLI treats as clean sleep; agent token marks turn ended); reserved2 queues unread without waking, chat/1st-gen drop handled, 1st-gen keeps jobs queued; 1 owner notice/new episode; reads fail open.
- **Stickers, feedback & activity:** sticker quotas reserve pending liabilities pre-network (1h expiry, 500 settled retained, OneBot 15s total / 5s connect; reset keeps pending IDs revoked). `feedback.rs` owns `<data>/feedback.json` (500 entries, 5s OS gate, 5/min, 20/h; 60s/10h owner error dedup). `activity.rs` owns redacted `<data>/qq-activity.log` (500-line rotate, newest 100 to console). Pause gates reserved2 scheduling/agents (ignored by chat/1st-gen). `security.outboundGuard` (`false` only disables sentinel/notices) and `security.interceptNotify` read per send (`settings::OUTBOUND_GUARD`, `INTERCEPT_NOTIFY`).
- **Access convergence, `/api/conversations/scope` & undo:** a conversation is answered only when `allow.{groups,private}` (minus `deny`) AND `rollout.rustGroups` (`--live-groups`) agree (`social_state::inbound_admitted` per event).
  - `POST /api/whitelist`, `POST /api/security`, `POST /api/conversations/scope`, `her-cli conversation <admit|remove> <conv> --runtime-root <root> --confirm`, and audit undo require `"confirm": true` (409 otherwise; `POST /api/whitelist` keeps JS `"07001" -> 7001`, `/api/settings/set` refuses leading zero -> 400). Access writes log `data/access-revocations-pending.json` (`before`/`after`/`targets`/`stops`) pre-`config.json` write under closed-agent + social gates, rotate tokens, clear bootstrap, cancel turns and stop DSH (retrying incomplete entries on startup/next change; 503 if file corrupt). Scope writes update both `allow.*` and `rollout.rustGroups` atomically (`409` if denied or missing `rollout.rustGroups`; reply returns `liveRestart`: `none|required|unknown`; CLI waits <=10s for DSH stops, exit 0/2/3).
  - Audit undo checks `afterRegistryFreeSha` (or raw `afterSha`), retains current token + non-security registry settings (`settingsKept`; non-object collision -> 409), prepares all files pre-write on multi-file undo (rollback on write fail), and requires `confirm:true` to retry `send-unresolved`.
- **Waits, resets & manual wakes:** `qq_wait_for_messages` (`POST /api/socialV2/wait`) holds per-conv generation lease (superseded returns `superseded: true`; console wait gets 429 while agent wait active; agent wait polls token rotation at 80/100/200 ms -> 403). Whole reset writes ledger `*`, `resetEpoch`, cancels turns, stops DSH; manual wake queues <=20 epoch-bound admin wakes.
