# Prompts and participation modes

Read for personas, roles, prompt delivery, scheduling, chat, closed-agent interactions, reply timing or slang learning.

## Prompt rendering, personas and roles

- **Prompt assembly (compat/CLI):** wrapped once at model delivery with current-time line (`time.zone` for local time + label; `host` follows machine/`TZ`; IANA follows calendar rules), enabled confirmed slang, then wake prompt. Order: role (closed-agent only), persona (`【人设】`, companion only), identity, token, bootstrap initial prompt, fixed guidance, state sections, reason tail. Live reserved2 uses briefing + wake delta; reminders keep their own body.
- **Automatic recall (`memory::recall`):** up to `memory.inject.relatedTopK` (default 3, cap 5/wake) by sparse or local semantic relevance; messages under 4 letters/digits/Han recall nothing.
  - Sparse: strips Chinese stopwords; requires >=2 distinct shared terms covering >=4 distinct chars, >=1 identifier covering >=4 alnum, or >=1 word covering >=6 chars.
  - Semantic: embeds answered message + <=4 current speaker names + latest active host topic. Unavailable semantic recall uses sparse ranking (pin/importance/recency/past-use boost <=0.05).
  - Never padded with pinned/recent rows; excludes ids in current session generation (`recalled` kept across same-generation full refresh, reset on new generation/session/epoch; DSH holds on wake accept, harness on canonical wake completion), plus index hint. Disabled when `memory.enabled` is false.
  - Delivery/accounting: compat full render holds nothing back; console preview suppresses DSH-held recall (may show harness history); reminders and `build_text_only` carry none. Rendering never counts search hits; each recalled memory gains 1 hit on accepted delivery (DSH wake delta or compat fallback, harness first usable response, CLI answer; refused/failed/unaccepted = 0; retries count only when accepted). Cosine ceiling/calibration: `docs/agents/mcp-memory.md`.
- **Personas (`persona.rs`):** exclusively owns `<data>/personas.json` (format 1; `locks/personas.lock`; damaged -> 503, renders none, never repaired).
  - Versions store `name`, `core`, `notes`, `compact`, `names`, `failureLine`, `traits.neediness` (0-3, default 1), `editMode` (`auto`/`manual`, default `auto`), `autoRules` (`parts` ⊆ `core`/`notes`/`compact`/`names`/`traits`, `perWeek` 0-20, `monthlyDriftPause`, `notify`), `source`, `approved`. Notes/compact/traits are stored-only.
  - Edits keeping `core` and `compact` equal to active version take effect at once; others await approval (approving older version rolls back). Identical save to latest returns `unchanged: true`; max 50 versions (prune oldest unapproved first, never active or newest).
  - Assignment: `default` + per-conversation `overrides` (canonical keys). Only `approved: true` with non-empty `name` and `core` is rendered/assignable; assigned personas cannot be deleted.
  - Rendering: companion modes (`chat`, `reserved`, `reserved2`) render active core once via `prompt::identity_core` as `【人设】<name>\n<core>` (DSH briefing via `briefing::persona_core`, compat/CLI, chat/1st-gen `identity_hint_v1`; cut at `role.maxInjectChars` default 6000, 1000-20000 UTF-16 until #18; reminders carry none). Assignment change bumps briefing generation of changed mapped conversations (next wake delivers full briefing in same session, preserving memory/history).
  - Approval/budgets: approving unapproved version refuses 409 if `core > 1500` or `compact > 300` estimated tokens (`persona::CORE_TOKENS_MAX`/`COMPACT_TOKENS_MAX`, `briefing::estimate_tokens`); rollback/import/duplicate skip budget check (duplicate preserves approval). Approval/rollback refuse 409 on name collision across personas. `GET /api/personas/item` includes `coreTokens`, `compactTokens`, `budgets`.
  - Refresh race & roles import: briefing generation is read pre-render; mid-prepare bump re-prepares once (`prompt::WAKE_BRIEFING_CHANGED`, no backend alert). Failed re-briefs stay in `rebriefDue` (`GET /api/personas`, UI, `/persona`) and retry on any subsequent assignment. `POST /api/personas/import-roles` imports `resources/roles/*.md` reserved2 views (v2+untagged, 1st-gen commands removed, example spaces -> commas, uncut) as approved personas and sets `importedRolesAt` when >=1 imported, after which import returns 409. Default persona fixture: `her/tests/fixtures/persona/xiaojingyu-v1.json` (guarded by `persona::tests::the_published_default_persona_is_within_budgets_and_approvable`).
- **Persona `failureLine`:** optional single line <=160 UTF-16 units (missing/null/empty/whitespace = silence; omit on update keeps; duplicate copies version; line-only edit takes effect immediately). On terminal failed companion turn, bridge attempts <=1 literal OneBot CQ-escaped text bubble via recorded send after checking mode, access, turn/session authority, mute, silence, outbound policy, and no pending verification/reply/cancel/supersession. Excluded from prompts/history/failure reports; recorded attempt never resends.
- **Persona wake words (`wake_words.rs`):** at reserved2 ingress (`live_bridge.rs`/`reserved2.rs`), active persona `names` (falls back to `[name]` if field absent; `[]` = off) wake as `keyword:<name>`. Re-read every ingress (assignment or names-only edit applies immediately; closed-agent/unassigned/damaged adds none).
  - `triggers.dropNames` via `qq_set_wake_config` (list replaces, non-list clears, omitted keeps; <=10 names, <=40 Unicode scalar values; persona names <=40 UTF-16) suppresses individual persona names; `keywords` follow persona names deduped case-insensitively.
  - Default, no-action, missed-closure and safety (`wake::ensure_wakeable`) resets preserve `dropNames` (missed-closure still clears `keywords`); explicit `/reset` or console reset clears `keywords`, `dropNames`, and `wakeWordLog` (restarting log ids at 1); idle session rotation keeps them.
  - Adding/removing words appends `{id, at, by (her|console|undo), added, removed, [undoes]}` (newest 20) to `wakeWordLog` in `social-v2.json` atomically; reorder alone logs nothing. `GET /api/personas/wake-words?conversation=` inspects; `POST /api/personas/wake-words/undo {conversation, id}` (under social gate) refuses 409 if added words were removed, removed words returned, undo leaves no stored trigger (`wake::ensure_wakeable` counts speaker IDs, not persona names), or >50 `keywords` (`wake::KEYWORDS_MAX`) / >10 `dropNames`.
  - Full briefing renders `wakeWords` (`【名字唤醒】`) in groups only. Console omits `names` when blank; API `names: []` clears. `forYou` ignores persona names.
- **Closed-agent roles:** resolve conversation -> role-group -> default -> current-role (empty/null = none) from `resources/roles`. Han precede Latin via `role_han_order.txt` (Latin case-insensitive). Prompt delivery carries role line; prompt API returns bounded card hint (mode sections, 1st-gen commands stripped for reserved2, normalized example spaces).
- **Initial prompts (`initial_prompts.rs`):** owns `initial-prompts.json` (UTF-16 limits; damaged = read-only). First message/poke atomically claims bootstrap; reset/replacement clears claim while preserving text. Compat/CLI injection follows claim (can lose on pre-delivery crash); live briefings always include bounded operator background. Unallowed keys refused.
- **Recommendations & CLI `[SILENT]`:** `socialV2.provideRecommendations` (default true) gates `qq_get_prompt` `recommended` and optional `wake.recommendedHint`/`send.recommendedHint` (default empty; changes reach sessions on next briefing replacement when rendered sections change). CLI text backends may return `[SILENT]` and read either nonempty live window or console snapshot JSON (defaults: 12 oldest unread, 4 newest recent, 6000 UTF-16 budget, `readThroughSeq`, partial metadata; rendering never marks read).

## Reserved2 admission, budgets and snapshots

- **Drivers (`live_bridge.rs`, `reserved2.rs`, `session::Driver`, `wake::WakeScheduler`):** <=1 running turn/conversation while ingress continues; completion coalesces base queued wakes after exact urgent-coverage checks; finite settings polled every 500 ms. Ingress resolves names/quotes, stores 200 UTF-16 `text`/`plain` and last 200 plain units as `tail`; triggers/slang use `plain`; empty plain without bot quote settles without storage; failed lookups keep `@ID`/quote labels; media/forwards survive durable ingress.
- **Access & suspension:** ingress, bootstrap and wake admission require explicit allow; deny prevails. Hub checks access before timer pump/dispatch; `sync_wake_configs` skips denied conversations. Refused wakes clear scheduler state and settle queued ingress without bootstrap, turn or notice. Engine admission checks access before opening turn ledger. Pause or disabled `socialV2` cancels ordinary queued batches and settles ingress; suspension during wake claim keeps batch/ingress queued until dispatch resumes.
- **Turn budget (`wake::turn_budget`):**
  - Dispatch cap: `max(120000, observation + max_quiet + 5000 + 90000)` ms (default 515000 ms), collector deadline: `ceiling + 30000` ms (default 30.5 min). `socialV2.turnTimeoutSecs` does NOT bound reserved2 turns.
  - Ceiling (`socialV2.wake.turnCeilingMs` / `wake::turn_ceiling_ms`): integer ms 1-2 h, default 30 min, never `< cap` (incl. legacy explicit caps; console refuses out-of-range or `cap > ceiling`; invalid hand edit falls back). Measured from dispatch, or from `engagedAt` (>= dispatch) while engaged, never exceeding ceiling. Hub freezes cap and ceiling at dispatch (`WakeScheduler::turn_cap_at`).
  - `observation` = effective `socialV2.wake.preSleepWaitMs` (default 300000 ms, truncates non-negative decimals from `config.json`; 0 when `preSleepWaitEnabled` is false [default true] or 0), applied in private conversations too. `max_quiet = max(wait.minQuietAfterNewMs, min(120000, wait.maxMs), validated wait.batchMaxMs)`.
  - `socialV2.wake.turnHardCapMs` overrides cap; console refuses `< observation + max_quiet + 5000 + 30000` (455000 ms default), `> 2 h`, or non-integer; reset deletes mirror and restores derived cap; mixed edits commit with wait settings.
- **Deadline enforcement & observation sleep:** dispatch persists token-free `budget` ledger record (`deadline`, `capMs`, `ceiling`) before backend work; console waits extend deadline to `engagedAt + capMs` <= ceiling (records without `capMs`/`ceiling` keep fixed deadline). Waits, reserved observation and batching stop 20000 ms before deadline (`<1000 ms` useful wait returns immediately with `turnBudgetExhausted` and no observation credit). Sends, reply holds and outbox resumes ignore budget. Legacy turns infer deadline from positive nonfuture wake-claim/begun inside hard cap or `waitTurnDeadlineAt`. If hard cap interrupts a messages observation whose `activeWait` (`epoch`, `turn`, `requestId`, `consoleGeneration`) still holds its one-use OS witness (`locks/observation-wait-<hash>.lock`), bridge stops adapter, revokes late-tool authority, and completes `observationSleep` (keeping wake config and unread, skipping closure reminders and no-action reset; stale markers grant no sleep; cap stop and revocation run even if cancellation bookkeeping fails).
- **Cancellation & epoch arbitration:** ingress/tick route `turnTimeout` through one non-aborting cancellation handler (never queued as wake). Expiry while queued for harness admission marks wake; worker checks deadline post-admission and pre-publish (incl. pinned CLI), settling expired wakes without dispatch/retry and consuming matching finite timer claims. Handler owns sole cancelled ledger end post-revocation (`sessions-recovery.md`), preserving prior completed end. Minted cancel epoch is adopted even if DSH stop failed (hub aborts collector `wake::COLLECTOR_HEADROOM_MS` post-cap -> cancelled). Abandon rotation holds shared epoch slot across persistence/publication; ingress/tick read under publication mutex (released before ledger epoch write); completion re-observes and adopts only current nonempty owned token before clearing active or replaying wakes; turn end drops `turnTimeout` for ended turn.
- **Epochs & closures:** tokenless absent/empty epochs are equivalent until first token creation; changed nonempty tokens invalidate queued work. Ingress adopts changed wake config before batching; ticks preserve batch. Closure notifications consume mark-read/set-wake-config; missing closure sends `<= maxWakeConfigReminders` (default 2 incl. original turn) without extra snapshot/counter/rate entry; exhaustion resets wake config (keeps `dropNames`, drops `keywords`). No-action completion checks actual model start/actions (default limit 3) and keeps `keywords`/`dropNames`.
- **Snapshots & receipts:** both engines POST authenticated console snapshot after admission and session replacement. DSH redacts chat fields pre-JSON and filters guidance separately; harness keeps raw packet for replay and redacts at delivery preserving guidance; headings, JSON keys, IDs and cursors stay intact. Only offered unread messages earn process-local token-scoped receipts (bounded by tool switches and size/count limits); each snapshot request names admitted turn and replaces prior grant (incl. retry); console checks captured effective cap at receipt use. Agent mark-read requires explicit `throughSeq <= readThroughSeq`; wake-config may omit. Admin may ack cursor or pass `clearAll: true` without cursor. Independent reads keep separate receipts; restart/token rotation void both (harness wake hitting cap pre-admission attempts immediate rotation). `lastReadThroughSeq` persists (legacy disk receipts deleted on next write); only positive safe seqs present in unread advance receipts/cursors.
- **Mode transitions:** mode revisions increment only on real transitions; before publishing, rotate tokens, settle ingress, retire mappings/policies, then stop/archive DSH. Away-and-back invalidates queues; same-mode writes keep mappings. `preemptAfterMs` defaults 0 (DSH clears inbox & stops turn; harness revokes active epoch; hub adopts minted token and preserves replacement wake).
- **Timers & reminders:** timer callbacks queue without wake quota while busy; completion rearms reply checks from actual read/reply state; wake limits cover message/finite/reply-check/proactive and survive restart; proactive runs without fresh input and clears on pause/disable/revocation. Reminder wake (`reminder:<id>`) renders `【提醒内容】` before tail (delta/compat) and before `【输出要求】` (pinned-CLI text-only, instructed to say it), showing `由你自己设置` for HER-created reminders, flattening line breaks and mapping `【】` -> `〔〕` (cancelled note if cancelled).

## First-generation reserved and chat/closed-agent modes

- **1st-gen reserved (`social-v1.json`):** 5s driver (idle watching, active batching, selective silence, probing, proactive topics, duration farewell); `social.enabled=false` uses chat. `social-v1.json` is gated and reset on startup without replaying old timers/jobs. Partial config normalizes/merges; gap bounds nonnegative/swapped; probabilities clamped `[0, 1]`. Flush awaits silent DSH delivery and keeps failed summaries. Jobs capture mode, driver/conv generation and token, rechecking authority pre-prep/DSH/send; admin idle/reset/exit settles ingress and invalidates before HTTP 200. Proven unsubmitted failures retry <=3; unknown uses turn recovery. Complete replies apply canonical face normalization before burst splitting (preserving face tokens, English spaces, deliberate Han-adjacent spaces, punctuation/URLs); zero gaps fall back to 1000/8000 ms; timestamps advance only after whole-burst success; manual active excludes already-buffered input while preserving history.
- **Chat mode:** admits allowed nonempty member messages (deny > allow incl. aliases > `allowAllWhenEmpty`), drops own echoes; checks silent role -> owner slash commands -> model.
  - Owner commands are whole-message ASCII case-insensitive (`/reset`, `/new`, `/status`, `/silent`, `/quiet`, `/active`, `/speak`, `/role`, `/role <name>` with `off`/`clear`/empty; role arg preserves case). In companion modes (`chat`, `reserved`, `reserved2`) all `/role` forms answer `角色卡已停用：请用 /persona 或控制台的人设页切换人设。` and write nothing. Embedded commands or other owner `/` text go to model/DSH.
  - Non-owner leading `/` is silently ignored (journaled handled, never sent to model/DSH) in chat and reserved modes (except `/update` & `/update deps` refusals). Non-owner DSH `command` results are logged and dropped. Paused-turn recovery commands: `docs/agents/sessions-recovery.md`. Slang skips only leading-slash text. Preset defaults to `qq-chat`; 1 worker/conversation.
  - Delivery: DSH chat acks once -> renames fresh group session -> final reply (harness skips DSH session work). Plain text relays in 4000 UTF-16 parts via outbox with fresh guards; empty/`[SILENT]`/send tools/sentinel/silence suppress relay. Aborted turns say stopped; backend errors/timeouts fail turn and privately alert owner (metadata-only). `command.text` relays via sentinel. Mode POST persists locally and writes DSH settings (`dshSynced`); status does not probe.
- **Admin private slash commands (`/update`, `/update deps`, `/persona`):** intercepted whole-message ASCII case-insensitive (ignoring surrounding whitespace) before mode dispatch within live scope. Groups/non-admins get fixed refusals (`/persona`: `人设只能由管理员在私聊或控制台切换。`).
  - `/update`: confirms current/new versions via recorded QQ send before approval (failed/uncertain admits nothing); holds shared turn admission through reply, approval and handled journal write (drained before replay incl. rollback); refuses concurrent install/restore/handover; reloads owner under config gate. `/update deps` lists pins/versions/diagnostics and approves first displayed change (SnowLuma then DSH) only after confirmed report delivery; dependency discovery runs via supervisor or console check only. Release execution: `docs/agents/lifecycle-tasks.md`.
  - `/persona`, `/persona <name>`, `/persona <name|off> <conversation>` (<=3 words): lists or assigns personas via recorded send, re-checking admin under config gate and naming failed re-brief conversations. In closed-agent, replies `closed-agent 模式不使用人设，人设未改变。` without change; takes no release turn admission.
- **Closed-agent mode:** owner private only. Preset resolves `closedAgentPreset` -> DSH default -> marked default (unresolved empty omitted from session creation, kept in policy). Discovery failure keeps session and fails turn. Owner/preset settings refresh every 5s; policy changes retire mappings/tokens. Receipt handling serializes with console mode writes (45s live wait, 0 maintenance).

## Interactions and approvals

- **DSH interactions (`pending-interactions.json`, cleared at startup):** bind session, turn and token; survive turn end/stream loss until answered, replaced, expired, reset or policy-invalidated. 10s WebSocket handshake; reap/settings timers keep ticking; stream awaits notifications sequentially; reap skips busy pending state.
  - Lock order: pending state -> interaction gate -> shared send chain (release gate between chain retries; bounded by question deadline). Delivery rechecks validity under gate. If all parts definitely undelivered, remove request and save snapshot (even if config unreadable or outbox failed definite refusal), release pending state, and submit empty answer/rejection on blocking worker (30s deadline). Any confirmed/uncertain part keeps request open; ambiguous delivery is outcome-unknown (never auto-resent); definite receipt refusal keeps request.
  - Only owner answers (labels case-insensitive, else custom text); `questionTimeoutMs` defaults 5 min; approvals send no confirmation; timeout notice may run post-turn. Collector tries interaction gate once per retirement check (busy defers to next tick).
- **Harness `ask_owner` (`pending-owner-interaction.json`, cleared at startup):** 1 question <=280 UTF-16 units, <=4 distinct options <=48 UTF-16 each. Owner replies with case-insensitive label or <=2000-char custom text (longer gets notice, keeps open). Accepts replies post-confirmed delivery; mailbox settles first valid private reply before expiry even if deadline/cancel wakes turn (which still fences continuation/tool sends). `/reset` & `/new` bypass mailbox. `questionTimeoutMs` defaults 5 min capped by remaining turn time. Bridge attempts 1 closure notice on expiry without reply (confirmed notice satisfies failure notification). Corrupt snapshot hides only that entry.
- **Group approval:** `/approve <id>` or `/deny <id>` in owner private chat only (unrecognized replies repeat prompt; busy gate asks retry; stray commands report nothing pending).

## Slang learning

- **Windows & queue:** selected data; group messages only (newest 80); consumption removes captured identities so concurrent input survives. 5s store/window gates. Live and console share FIFO queue (`slang-jobs.lock`, per-job OS markers, max 16 pending/running; abandoned markers cleaned on exit; no crash replay).
- **Store & extraction (`slang.rs`, `slang_learn`):** reads/writes serialize via `slang::read_entries_locked` / `slang::mutate_entries` (`slang-store.lock` held only inside `slang.rs`). `slang_learn::extract_now(&RuntimeContext)` and `POST /api/slang/extract` -> `slang_learn::queue_manual_extraction` (`handle_slang_extract` is `#[cfg(test)]`). Only completed textual learner turns mutate/consume; manual extraction picks first inserted window (even empty consumed).
  - Parser tries direct JSON array before bounded UTF-16 fallback scan; valid `[]` consumes batch; malformed non-array/empty-valid gets 1 format-repair re-ask, second malformed consumes with 1 log line (backend failures never consume).
  - Pre-save writes `pendingCommit` (batch signature, message ids, prior `slang.json` SHA-256) in `slang-windows.json` for idempotent crash recovery via `slang::reconcile_if_hash` and `consumedBatches`. Saves normalize/clip/identify, drop empty content, cap 2000 entries by status/count/update time. Confirmed meanings only enter prompts.
  - Learner backend: default (and absent/blank/`"dsh"`/`"harness"`) runs tool-less `harness/one_shot::slang_complete` walking harness route chain (`retry_empty: false`, model/`maxOutputTokens`/`reasoningEffort`, selected relay + `config/harness-api-key`, 120s cap, learner prompt only). Pinned CLI `slang.learnerBackend` runs CLI first and falls back to harness chain only if `slang.learnerFallbackDsh` is `true` (default `false`). Total chain failure leaves `slang-windows.json` untouched, sends content-free owner alert (`backend=harness`, `provider=openai`, asked model), and records `refusal` failures in `data/slang-refusals.json` with backoff `min(max(cooldown, 60s) * 2^(attempts-1), 1h)` up to `REFUSAL_RETRY_CAP = 3` (manual extract ignores backoff). Research is tool-less.
  - UI/config `/api/slang`, `/api/slang/config`, `SlangTab` retire `learnerPreset`, `workspaceTitle`, `learnerBackend` (legacy keys ignored; `data/slang-session.json` & `data/slang-agent/` unread). Config writes hold social gate. First driver/bridge per runtime root per process runs 1 startup catch-up.

## Model text redaction, prompt text and upstream capture

- **Blacklist (`model-text-blacklist.json`):** `socialV2.context.stripFromModelText` merges per turn/read with selected `config/model-text-blacklist.json` (`{"strip":["literal"]}`, <=64 KiB, <=500 entries, <=64 Unicode chars/literal; external writes live without restart). Missing/invalid contributes nothing and warns once per failure-state transition per runtime across processes (`data/model-text-blacklist.state` under `locks/model-text-blacklist.lock`, process-local fallback if unwritable); delivery never writes config.
- **`model_view`:** replaces configured literals in chat-bearing fields with `【已隐藏】` (case-sensitive, list order, 1 pass/literal). CQ codes, media labels and `【已隐藏】` are indivisible; skips replacement if marker insertion would expose a denied term at its boundary. Preserves JSON structure, IDs, cursors, tokens, media refs, learner numbering; format-repair echoes filter before escaping. Logs, source chat, console views and outgoing sends keep originals.
- **`model_text_policy`:** single module (`model_text_policy::denied_terms`) forbids naming harness/model/platform/developer/install layout or calling her AI/robot/assistant on rendered surfaces (`console::tests::model_text_guard_tests`), prompt text, history summaries (`harness.md`), DSH persona guard (`mcp-memory.md`), and upstream capture sweeps.
- **Prompt text (`prompt_text.rs`):** registry text settings (`prompt.notAClerk`, `prompt.proactive`, `prompt.groupConduct`, `prompt.repeat`, `prompt.stickerStrategy`, `prompt.stickerSoften`, `prompt.mode.{chat,ownerPrivate,closedAgent,reserved2,reserved2Owner}` under `/prompts/`, never marked `chat`), hot-read every config load (no restart). Validation on save/load: <=2000 Unicode scalar values (mode prompts 8000), LF/tab only, no runtime harness credential or stored endpoint API key, no `model_text_policy::denied_terms` (checked with invisible format chars stripped, with format chars as word boundaries, with both + full-width ASCII folded + uppercase, and as-written). Refused save preserves stored text and names denied terms; refused stored value falls back to newest passing audit value (stopping at empty-new-value undo rows) -> file value -> compiled default (empty for `notAClerk`, `proactive`, mode prompts). Reset stores compiled default; undo restores old value only if still passing.
- **Upstream capture (`upstream_capture.rs`, `her-cli upstream-capture`):** captures next `dsh` (`session/prompt` envelope) or `harness` (`ChatRequest` + model/token limit, incl. digest/slang one-shot) request when armed (CLI backends uncaptured; arming production is an owner action, `docs/agents/production-ops.md`).
  - `arm --runtime-root <root> --route dsh|harness [--minutes 1-1440]` (default 30) writes `data/upstream-capture/armed.json` (refuses if armed, claim or unswept capture exists; survives restarts until used/expired).
  - Send path snapshots in-memory without waiting and hands to detached writer thread (atomic rename claim -> `data/upstream-capture/captured.json` -> delete claim; <=1 capture; skips if writer in-flight; >16 MiB recorded by size only; writer failures recorded in `data/upstream-capture/last-failure.json`, surfaced by `status`, cleared by `arm`).
  - `sweep` scans strings/keys (masking non-structural keys as `<key>`, skipping base64 >=256B), prints counts + JSON paths (no content), and deletes capture; invalid shape refuses as `capture file invalid`. `disarm` deletes arming/claim/capture. Never included in runtime backups (`data/*.json` only) or copied to vault/repo.

## Wait batching and turn allowance

- **Waits (`socialV2.wait.*`):** messages waits batch arrivals for `batchWindowMs` (default 8000 ms, reset per arrival) capped by `batchMaxMs` (default 30000 ms; both 1-120000 integer ms, independent defaults; shorter max truncates). Owner messages and bot @mentions return immediately (incl. reply quiet waits); other reply waits keep `quietMs`. Ingress stores `atSelf` and `isOwner`.
- **Per-turn allowance:** `maxPerTurn` (default 4, positive safe integer) covers both wait purposes, persisted under social gate scoped by ledger turn and token epoch across restarts (superseded calls spend slot without observation; legacy turns mint `waitTurnId` once pre-execution; closeout/retries keep allowance). Final slot forces full observation timeout (ignoring shorter `timeoutMs`/purpose/minNewMessages); final and later results carry `waitLimitReached=true`, `nextAction="end_turn"`, `"end this turn now: produce your final answer and make no further tool calls"`, returning immediately when exhausted without observation. Exhausted reserved2 turns complete as `observationSleep` (even if final wait delivered a `forYou` message), keeping wake config, rearming finite deadline, skipping closure reminders/no-action reset; closeout tools stay usable with normal authority.
- **Engagement window:** configured observation duration post last successful send (`engagedAt`, cleared at wake claim; started by delivered text/voice/sticker/poke; applies in private too, where mandatory closeout observation is exempt; incoming chatter/skipped messages/other pokes never extend). Pre-sleep never outlasts window; agent-token messages wait runs to window end (clipped by `wait.maxMs` unless forced observation exceeds it, and by turn budget), returning immediately without batching on `forYou` or urgent @/owner arrival, or collecting chatter to window end (re-checked against current send/deadline on return). Window-end chatter sets `engagementEnded=true`, `preSleepWaitSatisfied=true`, `turnBudgetEnded` and ends turn (`observationSleep`, wake config kept, no closure/no-action/cancel). `<1000 ms` remaining hands over waiting `forYou`/urgent message (refunding slot normally) or ends immediately with waiting chatter (no refund). Urgent @/owner or `forYou` anywhere in result write never ends turn (1 response step, no refund, next wait refused). Wait hitting `waitLimitReached` (and refused wait after it; storage failures logged, limit result still returned) also sets `turnBudgetEnded`.
- **`forYou` & slot refund (`question::ingress_for_you`):** non-poke private (`私聊你`), poke targeting her (`拍了拍你`), or group quote-to-her / @her / nickname / group-card / exchange rule (member she replied/@'d or who quoted her within `questionExchangeWindowMs`, without @ing another member). Judged against pre-message state (unreadable state logs and drops exchange evidence; older records fall back to private/quote/@ facts). Wait results carrying `forYou` refund slot up to `socialV2.send.maxPerTurn` (default 20) times per ledger turn; timeout/chatter keep spending 1. Briefings show `【互动窗口】` only while active.

## Briefing and wake delta

- **Delivery (`briefing_delivery.rs`, `session_context.rs`, `session_map.rs`, `pipeline/dsh_adapter.rs`):** full briefing once per session generation (`begin` -> gen 0 on rotation/reset; `next_generation` on compaction/persona switch), then deltas with section replacements/removals. Selected at actual sid/epoch resolution (incl. mid-dispatch replacement) and persisted in `sessions.json` `briefings` (format 1) under mapping+social gates.
  - DSH ack requires observed user/message in same sid/epoch/generation (`requestId` defaults to tracked envelope ID; echoed in `data.source.rpcId`, fixture `tests/fixtures/dsh-0.2.1-rc.2-user-message.json`); pending RPC is not proof. Completed compaction / summary-checkpoint replacement invalidates proof once per compaction ID; prune-only/image-offload do not; unobserved forward history gap forces 1 full briefing; no periodic refresh.
  - Harness replays generation facts (supplying full briefing if clipped) and gets receipt on completed canonical user fact.
- **Sections & memory layers (`briefing.rs`):** Identity (`identity`: role, `briefing::persona_core`, bot identity, role hint) and Relationship (`operator`, `impressions`) are never cut (overruns deduct from Material, then Conversation). Conversation (`memory` topics/thoughts, `participation`, `slang`) cuts backwards from end (`slang` -> `participation` -> oldest thoughts/topics). Material (delta auto-recall + `【记忆索引】` <=60 est. tokens) keeps top-ranked fits; cut memories are unrendered/unheld/uncounted.
  - Defaults: `memory.layers.{identityTokens:1500, relationshipTokens:1500, conversationTokens:800, materialTokens:1000, materialItems:5}` (estimated tokens: 1/non-ASCII, 1/4 ASCII; `materialItems` tracks valid `relatedTopK`). Rule sections (`behaviour`/`stickers`/`sending`/`reply`/`sleep`/`retrieval`/`wakeWords`) sit outside layers. Stickers list `id：note` for up to `socialV2.sticker.promptMaxStickers` (default 8) top stickers without use counts (inventory shown when sticker/`[表情N]` softens reply). Ledger `attempt` records per-layer `{injected, cut}`. Empty Identity (any conv) or empty Relationship (owner private) alerts once per `(conv, sid, epoch, gen, layer)` via `admin_alert::notify_memory`.
- **Member impressions:** ordered newest-speaking in unread/recent (by QQ id or display name), then by `lastSeenAt`, capped at `socialV2.context.impressionPromptLimit` (default 10) in storage order. Repeated traits move to newest slot (`impressionMaxTraits` default 10, max 20); `impressionMaxMembers` (default 50) prunes longest unseen. Speaking advances `interactionCount`/`lastSeenAt` (not on replay); writes do not (`__proto__`-safe).
- **Wake delta payload:** current token authority, reason/instruction, unread count, wake config/timers (omits `sleepRangeMs`, `inheritsKeywords`, `customKeywordsFor`; wake-config writes ignore them), reply quiet/pre-sleep status, installed revision ref, fresh redacted console snapshot (exact IDs/cursors/partial metadata), tool-only reminder. Refusal provenance uses delivered packet only.

## Cache-aware session rotation

- **`session_rotation.rs` & hub:** rotates sleeping DSH conversations when last call's total input (cache hit+miss+write, incl. closing reminders) >= per-model `dsh.rotation.caps` (fallback `default`, else 500000), last completed turn confirmed wake config, and no open/paused turn, queued ingress/wake/retry, compaction or pinned CLI blocks maintenance (owner private uses same policy).
- **Due time:** `dsh.cacheTtlMinutes` (defaults: `local-relay` 5, `opencode-go` 120; unknown providers need explicit positive finite TTL). Idle starts at `max(lastIncoming, completedTurnEnd)`; due at `max(0, TTL - 1 min)`. Below-cap survives cache expiry. Incoming/policy/wake cancels/delays while slot stays owned until digest outcome/stop is known.
- **Digest & recovery:** runs Digest (`docs/agents/lifecycle-tasks.md`) only past `digestedThrough`; memories + cursor commit atomically (never submitted to DSH; restart reruns uncommitted; failed digest alerts once and still permits rotation; reset error marks attempt done to stop loops). Persists `rotate` phase separately from digest success; restart rechecks guards and resumes retirement without re-digesting. Failures record fixed step (`context-read`, `evidence`, `model`, `digest-result`, `memory-write`, `checkpoint`, `digest`) + kind in `sessions.json.rotationFailures` (`GET /api/sessions`). Partial-reset recovery keeps maintenance/ingress held until replacement token persists; 12 state-read failures emit diagnostic + daily-limited notice (`data/rotation-alerts.json` under sessions lock, process fallback) and retry every 60s.
- **Archive:** rechecks guards under social gate -> revokes mapping/token (preserving conv data/recent msgs) -> stops & archives DSH (no deletion) -> logs 1 activity line (conv, input tokens, digest yes/no). DSH mid-turn compaction safety net stays preset-owned (0.6 of 1M, retain 32000). See ADR 0007.

## Harness idle rotation

- **`harness/rotation.rs`:** checked at harness turn admission before first request (`due_at(cfg, last, idle_from)` using `cache_life_minutes` and `cap`). Idle starts at last turn end; due sessions rotate in place with summary + newest whole rounds within 4000 estimated tokens (`docs/agents/harness.md` "History budget and checkpoints"). Failed summary leaves unrotated.
- **Evidence (`harness::store::last_call`):** newest answered model attempt in current generation (by append-only seq) with recorded route id (legacy falls back to `harness.model` route id) and positive `captured_usage.prompt_tokens`. Unanswered or zero/missing input never triggers rotation.
- **Settings (isolated from DSH):** `harness.cacheTtlMinutes` per route id (positive finite; no built-in default, `dsh.cacheTtlMinutes` never applies -> unconfigured routes never idle-rotate); `harness.rotation.caps` per route id -> `default` -> 500000 (`dsh.rotation.caps` never applies). Due at `idle_from + ceil(max(0, cache_life - 1 min) ms)` (saturated `i64`).

## Bridge-enforced reply timing

- **In-turn suppression & urgent coverage:** running turns (incl. generation-matched recovery) suppress non-urgent wakes pre-trigger (`in-turn`). Urgent @/owner wakes use base queue/retries/quotas; same-generation completion drops queued urgent follow-up (`covered`) only when its exact seq appeared in that turn's successful tool response (wait, unread/history, mark-read ack) after all required writes succeed (revision sends require persisted revision budget, outbox supersession and settlement). Prompt snapshots, buffers, cursors, failed/cancelled/timed-out turns, restart and CLI grant no coverage.
- **Quiet & question exchange (`question.rs`):** idle quote replies retain `atMention` when enabled; in-turn quote without `@` is suppressed. `triggers.question` admits questions quoting her or from an active exchange participant within `socialV2.wake.questionExchangeWindowMs` (default 90000 ms) of her last message (evidence: member quote to her or confirmed bot reply/@ to member; excludes questions `@`ing others; nagging requires same exchange even when quoting her; AI words/aliases establish no direction; failed/uncertain sends establish no exchange).
- **Wake debounce:** `socialV2.reply.wakeQuietMs` (default 3000, 1-30000 ms, live next wake); every substantive arrival resets armed message wake up to 30000 ms from first unseen arrival; bot @mentions and owner trigger immediately.
- **Per-bubble quiet & typing holds:** enforced pre-bubble and pre-outbox on `qq_send_message`, burst, reply, direct console sends and text outbox resumes:
  - Quiet window: independent log-normal (log sigma 0.5) clamped to `[quietMinMs, quietMaxMs]` with `quietMedianMs` (defaults 4000/10000/25000 ms; urgent owner/@ uses `urgentQuiet*` 1000/3000/6000 ms; overrides 1-120000 ms; console refuses `!(min <= median <= max)`, load falls back per-field or full triple on ordering violation), measured from `lastReplyIncomingAt` (falls back to `lastIncomingAt`/substantive recent msg, else 0).
  - Typing budget: registered UTF-16 first-gap base + per-char + burst floor/gap cap generalized to all bubbles * uniform `[0.75, 1.25]` (test-seedable RNG, OS entropy in prod), credited by observed DSH thinking (since `started` or last delivered bubble; missing start -> 0 credit) or first harness request start. `firstGapEnabled=false` disables typing delay only; `fillTypingBudget=false` keeps full budget. Quiet and typing overlap (max, not sum).
  - Private held sends issue best-effort `set_input_status(user_id, 1)` (250 ms budget) and clear `0` on release/revision/revocation/failure; groups skip status.
- **`inbound_text::quiet_neutral`:** classifies pre-truncation inbound; neutral only if every segment is image/face/mface/bface/sface, quote wrapper around qualifying media/emoji, or whitespace/emoji-only text (incl. CQ codes and `[图片]`/`[表情…]` placeholders; digits/words/punct/quote-only/voice/video/file/unknown are substantive). Neutral arrivals stay in recent/unread and trigger held-send revision, but never extend `lastReplyIncomingAt` or quiet timers (`lastIncomingAt` and #94 wait batching still track them).
- **Held revisions & supersession:** arrival during hold cancels unsent bubbles pre-outbox and returns HTTP 200 `{held: true, reviseRequired: true, sent, newMessages, receipt/cursor, "对方又说了…"}` (retained delivered bubbles never resent; partial packet uses `nextAfterSeq`, `readThroughSeq` reflects offered only; spends no wait slot or sleep observation). Max 3 revisions/turn-token epoch (`replyRevisionBudget`); beyond 3, fixed deadline ignores later arrivals. Pre-return writes 1 durable outbox `superseded` record covering remaining indices (failure -> 503; legacy per-item `superseded` readable), releasing quota and excluding from resume/recovery; authority cancellation remains `cancelled`.
- **Prompt & schema contract:** `hf119_reply_prompt_leaves_timing_to_the_bridge` verifies `her/tests/fixtures/qq-chat-v2-reply-timing.yml` (`persona.config.prefix`). `socialV2.send.mergeMultiIntoOne` (default true) joins parts with `\n` in 1 bubble; when false, `burstEnabled` allows split parts <= `burstMaxMessages` with inter-bubble gaps; every bubble/merged text must fit `maxMessageChars` UTF-16. `[表情N]` allowlist/normalization follows `docs/agents/media-transport.md`.
- **Send caps & repeat guards:** executed in shared console batch executor pre-quota/intent/hold. Zero minute/hour quota disables that quota (defaults 8/60, cap 500). `socialV2.send.repeatLimit` (default 2) and `maxPerTurn` (default 20; positive safe integers) refuse violating batches with HTTP 429 (no hold/attempt/revision), logging only key/turn scope/reason/count and emitting <=1 durable content-free owner notice per turn. `repeatWindowSends` (default 0 = previous turn/scope; >0 = last N conversation outbox sends; current-turn repeats always count) compares canonical text across confirmed/uncertain typed bot sends (definite failures/cancelled/superseded excluded); limits follow actual turn across token rotations (resumes spend submitting turn cap; restart/timeout never erase outbox).
- **Reserved2 CLI relay:** requires companion console; 1s connect+write budget, 300s total budget (permits holds); transport failure logs `CLI reply send failed: companion console unavailable` and fails turn without OneBot fallback. Passes answer prose directly; retains turn token; audits final canonical face-normalized text via outbound sentinel + known-secret check. Each held revision carries cumulative bounded new-message packets (<=3 revisions; discarded drafts spend no send cap); HTTP 429 ends CLI turn without DSH fallback/alert; empty initial draft may fall back to DSH, empty revised/`[SILENT]` completes without send; blank process output = empty-response failure (`docs/agents/dependency-recovery.md`).
