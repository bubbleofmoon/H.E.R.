# Prompts and participation modes

Read for personas, roles, prompt delivery, scheduling, chat, closed-agent interactions or slang learning.

- Compatibility full/debug and CLI prompts are wrapped once at model delivery with the current-time line, then enabled confirmed slang, then the wake prompt. `TZ` names the zone; only UTC/GMT and host UTC+8 are supported. Their section order is role (closed-agent only), persona (`【人设】`, companion modes only), identity, token, bootstrap initial prompt, fixed guidance, state sections and reason tail. Live reserved2 DSH delivery uses the briefing/wake-delta contract below; reminders retain their own body. Automatic recall (`memory::recall`: up to `memory.inject.relatedTopK` memories, default 3, that share enough with the message being answered (two or more distinct shared terms covering at least four distinct characters of the message, such as two Chinese words (overlapping bigrams count once, so a three-character word is not enough), or one shared identifier (four or more letters or digits with a dot, underscore or letters mixed with digits) or word covering six or more; one shared two-character word, `https` or `2026` is never enough; a message under four letters, digits or Han characters recalls nothing), any-word match ranked by relevance with pin, importance and recency adding at most 0.05, never padded with pinned or recent rows when nothing matches, and never one the session generation already carries (the installed briefing's `recalled` ids, kept across a same-generation full refresh and reset by a new generation, session or epoch; a wake DSH has not accepted holds nothing back), plus the index hint; none when `memory.enabled` is false; the console preview leaves out what the generation carries, so it shows the next wake's block, while the compatibility render holds nothing back) is carried by the compatibility full render and by the DSH wake delta, the same block the console preview shows. Wake reminders and the text-only CLI prompt (`build_text_only`) carry none. Rendering never counts search hits. Each recalled memory counts one hit per delivery of a prompt carrying it: when DSH accepts a submission (the wake delta, or the compatibility render where no delta is rendered), or when a CLI fallback backend answers for the compatibility render. A refused, failed or unaccepted attempt counts nothing, and a retried attempt counts only when it is accepted.
- Personas: `persona.rs` exclusively owns `<data>/personas.json` (format 1; `locks/personas.lock`; a damaged file is refused with 503 and renders no persona, never repaired). A persona has numbered versions (`name`, `core`, `notes`, `compact`, `names`, `traits.neediness` 0-3 default 1, `editMode` auto/manual default auto, `autoRules` {parts ⊆ core/notes/compact/names/traits, perWeek 0-20, monthlyDriftPause, notify}, `source`, `approved`). A saved version whose core and compact equal the active version's is in effect at once; any other waits for approval, and approving an older version rolls back. Assignment is one `default` plus per-conversation `overrides` (canonical keys); only approved personas can be assigned, and assigned personas cannot be deleted. In companion modes (chat, reserved, reserved2) `prompt::identity_core` renders the conversation's active core once as `【人设】<name>\n<core>`: in the DSH briefing's identity section (through `briefing::persona_core`, never twice), the compatibility full and CLI renders, and chat/first-generation prompts (`identity_hint_v1`); wake reminders carry none. Notes, compact, names and traits are stored for later consumers and not rendered yet. An assignment change (console or the owner's private `/persona`) bumps the briefing generation of each mapped conversation whose persona changed, so its next wake carries a full briefing in the same session; memory and history stay. Approving a new core changes the identity section through the normal wake delta. Only an active version with `approved: true`, a name and a non-empty core is rendered or assignable; any other stored record is skipped, never rendered. Approval and rollback refuse (409) a name another persona uses. A save identical to the latest version adds no version (`unchanged: true`); a persona keeps at most 50 versions, dropping the oldest unapproved first and never the active or newest one. Until #18 owns the prompt budget the rendered core is cut at `role.maxInjectChars` (default 6000, range 1000-20000 UTF-16 units). The briefing generation is read before the sections are rendered: a wake prepared while a switch or compaction bumps it is prepared once more (`prompt::WAKE_BRIEFING_CHANGED`) and raises no backend alert. Conversations whose re-brief failed stay in `rebriefDue`: `GET /api/personas` lists them, the page shows them, and `/persona` names them; every later assignment, repeating the same one included, re-runs them. `POST /api/personas/import-roles` imports `resources/roles/*.md` as approved personas, each core being the card's reserved2 view (v2 and untagged sections, first-generation command lines removed, example spaces rewritten to commas, uncut); `importedRolesAt` is set only when at least one card was imported, after which import refuses with 409. Role cards are retired in companion modes; the role bullet below applies to closed-agent (and legacy contexts) only.
- Closed-agent roles resolve conversation mapping, role-group mapping, default, then current-role; empty/null means no role. Cards live under resources/roles. Prompt delivery carries the role line; the prompt API supplies the bounded card hint, keeping mode sections, removing first-generation commands for reserved2 and normalizing example spaces. Han names precede Latin; `role_han_order.txt` supplies portable pinyin order, Latin sorts case-insensitively.
- `initial_prompts.rs` exclusively owns initial-prompts.json with UTF-16 limits. Damaged data is read-only. First message/poke atomically claims bootstrap; reset/replacement clears that claim while preserving saved text. Compatibility full/CLI injection follows that claim and can be lost after a crash before delivery. Live DSH briefings include the bounded operator background independently of the wake reason and scheduler claim. Unallowed initial-prompt keys remain refused.
- CLI text backends use a supplied nonempty live window, otherwise the shared console wake snapshot rendered as JSON: oldest unread first (default 12), newest recent in stored order (default 4), shared UTF-16 JSON budget (default 6000), readThroughSeq and partial metadata. Rendering never marks messages read.
- Reserved2 uses `reserved2.rs`, `session::Driver` and `wake::WakeScheduler`: at most one running turn per conversation while ingress continues; completion coalesces the base queued wakes after exact urgent-coverage checks. Finite settings reach drivers every 500 ms. Incoming text resolves names/quotes, stores text/plain at 200 UTF-16 units and the last 200 plain units as tail; triggers and slang use plain. Empty plain without a bot quote is settled without storage. Failed lookups use @ID/quote labels. Media and forward references survive durable ingress.
- Reserved2 captures one turn budget at dispatch (`wake::turn_budget`): the dispatch-clock cap is `max(120000, observation + max_quiet + 5000 + 90000)` ms (default 515000) and the DSH collector deadline is the per-turn ceiling plus 30000 (default 1830000). The absolute ceiling is `socialV2.wake.turnCeilingMs` (`wake::turn_ceiling_ms`: integer 1 to 7200000, default 1800000, never below the cap, so the effective ceiling exceeds 7200000 ms (2 h) when `turnHardCapMs` does; console saves refuse other values, loading uses the default and logs the bad value once), measured from dispatch; while she is engaged the cap runs from her last successful send in the turn (`engagedAt` at or after dispatch) and never past that ceiling, and the hub freezes cap and ceiling at dispatch (`WakeScheduler::turn_cap_at`). Observation is the larger of the prompt's reading of `socialV2.wake.preSleepWaitMs` (`wake::prompt_pre_sleep_wait_ms`: 0 or non-numbers mean 300000, `preSleepWaitEnabled` ignored) and the gate's; `max_quiet = max(wait.minQuietAfterNewMs, min(120000, wait.maxMs), validated wait.batchMaxMs)` is the messages wait's quiet extension. `socialV2.wake.turnHardCapMs` overrides the cap; console saves refuse an override below observation + max_quiet + 5000 + 30000 (455000 ms with the defaults) or not an integer, while loading never fails on one (the derived cap is used and the value logged once). `socialV2.turnTimeoutSecs` does not bound reserved2 turns.
- Each reserved2 dispatch persists its absolute turn deadline, cap length (`capMs`) and absolute `ceiling` in a token-free `budget` ledger record before backend work; a console wait extends that deadline to `engagedAt + capMs` within the ceiling, and a record without `capMs`/`ceiling` keeps its deadline. Only waits obey it: every messages/reply wait, the reserved observation slot and message batching stop 20000 ms before the deadline, and less than 1000 ms of useful wait returns at once with the existing end-turn instruction (`turnBudgetExhausted`), granting no observation credit. Sends, the reply hold and outbox resumes never read the budget and are never held or superseded by it. Without a captured budget (older turns, legacy no-ledger waits via `waitTurnDeadlineAt`) only a positive, nonfuture wake-claim or begun time still inside the current hard-cap interval supplies a deadline; unknown or expired starts mean no deadline. If the hard cap interrupts a messages observation whose `activeWait` (epoch, turn, request ID, console generation) still holds its one-use OS witness (`locks/observation-wait-<hash>.lock`), the bridge stops DSH work, revokes late-tool authority and ends `completed observationSleep`: wake config and unread messages keep normal wake admission, and closure reminders and the no-action reset are skipped. A marker left after console termination or failed cleanup grants no sleep. Cap stop and revocation run even if cancellation bookkeeping fails.
- Ingress and tick route the driver's `turnTimeout` through one cancellation handler that never aborts them and never queues it as a wake. The handler owns the sole cancelled ledger end after revoking authority (`sessions-recovery.md`), including when the collector consumes DSH's aborted end before the cancel RPC returns. A genuine completed end observed before cancellation intent retains completion while collector bookkeeping finishes. The epoch the cancellation minted is adopted even when the DSH stop failed (the hub then aborts that turn's collector `wake::COLLECTOR_HEADROOM_MS` after the cap and settles it as cancelled, so the conversation is not held to the collector deadline). A capped turn's later abandon rotation holds its shared epoch slot across persistence and publication. Ingress and tick read state under that publication mutex and use that same observation for adoption, admission and early invalidation, preserving buffered valid work across repeated owned rotations. Completion observes again and adopts only its current nonempty owned token before removing Active or replaying queued wakes; rotation releases that mutex before writing the ledger epoch. A reset or revocation still invalidates it. Turn end drops a `turnTimeout` for the turn that just ended.
- Tokenless absent/empty epochs are equivalent until first token creation. Changed nonempty tokens invalidate queued work. Ingress adopts changed wake config before batching; ticks preserve that batch. Closure notifications consume mark-read/set-wake-config. Missing closure sends at most maxWakeConfigReminders (default 2 including original turn), without another snapshot/counter/rate entry; exhaustion resets wake config. No-action completion uses actual DSH start/actions (default limit 3) and preserves configured keywords.
- DSH snapshots are obtained from the console-authenticated wake-snapshot POST after session replacement. Only offered unread messages earn process-local token-scoped receipts; disabled tools and size/count limits restrict them. Restart/token rotation voids receipts. lastReadThroughSeq is the persisted mark; legacy disk receipts are removed on the next write. Only positive safe sequence numbers present in unread can advance new receipts/cursors.
- Mode revisions change only on real transitions. Before publishing, transitions rotate tokens, settle ingress and retire mappings/policies, then stop/archive DSH work. Away-and-back transitions still invalidate queues. Same-mode writes preserve mappings. Optional preemptAfterMs defaults to zero; cancellation removes DSH inbox work, rotates tokens and closes ledger turns. Preemption adopts its cancellation's minted token even when stopping DSH fails, logs failures and lets ingress finish.
- Timer callbacks queue without spending wake quota while busy. Completion rearms reply checks from actual read/reply state. Wake limits cover message, finite, reply-check and proactive wakes and survive restart. Proactive timers work without fresh input; pause/disable/revocation clears them. Every text bubble has a UTF-16 typing budget with observed model-time credit; quiet holds, revision and typing follow the bridge-enforced reply timing contract below.
- First-generation reserved mode uses a five-second driver: idle watching, active batching, selective silence, probing, proactive topics and duration-based farewell. social.enabled=false uses automatic chat delivery. social-v1.json is a gated per-generation console view, reset at startup without replaying old timers/jobs. Partial social config is normalized/merged, saved and returned; the next request adopts the stored top-level partial object. Gap bounds are nonnegative/swapped, probabilities clamped to [0,1]. Flush waits for actual silent DSH delivery and retains failed summaries.
- Every first-generation job captures mode, driver/conversation generation and token and rechecks authority before preparation, DSH submission and sends. Admin idle/reset/mode exit settles ingress and invalidates obsolete work before HTTP success. Proven unsubmitted failures retain input and retry at most three times; unknown attempts use normal turn recovery. Complete replies use canonical face normalization before burst splitting. Splitting preserves supported face tokens, English spaces, deliberate Han-adjacent spaces and punctuation/URL atoms. Zero gaps fall back to 1000/8000 ms; later burst items run after earlier failures, each guarded. Reply/activity timestamps advance only after whole-burst success. Manual active state excludes already buffered input while preserving history.
- Chat admits allowed nonempty member messages in stored chat mode, with deny before allow (including aliases), then allowAllWhenEmpty. Own echoes are dropped. Check silent role → owner slash commands → model. Owner commands are recognised only by their whole-message form: `/reset`, `/new`, `/status`, `/silent`, `/quiet`, `/active`, `/speak`, `/role` and `/role <name>` (`off`/`clear` or no name clears the role), command names ASCII case-insensitive, role-name arguments retaining their case. In companion modes (chat, reserved, reserved2) every `/role` form, an unknown name included, only answers the fixed notice 「角色卡已停用：请用 /persona 或控制台的人设页切换人设。」 and writes nothing. Command words inside ordinary messages (role-switching discussion, `/usr/bin/env`, `/reset now`) are model input, and so is any other owner slash text (it may be a DSH command). A non-owner's message is never a command, and a non-owner message whose text starts with `/` is ignored without a reply (journaled handled, never sent to a model or DSH), in chat and reserved modes alike; `/update` and `/update deps` keep their own refusal (below). A DSH `command` result for a turn the owner did not start is not relayed: it is logged and the turn ends silently. Owner-private paused-turn recovery commands have their own form (`docs/agents/sessions-recovery.md`). Slang learning does not filter role-control words; it skips only leading-slash text. Prompts include role hint, owner marker, group sender and media; preset defaults to qq-chat. One worker per conversation preserves message order.
- Accepted DSH chat prompts send acknowledgement once, then rename fresh group sessions, then final reply. Harness chat uses the same acknowledgement and reply path without DSH session work (`docs/agents/harness.md`). Relay plain text in 4000 UTF-16 parts through the outbox with fresh guards. Empty/SILENT, successful send tools, sentinel rejection or member silence suppress final relay. Aborted turns say stopped; model/backend errors and timeouts fail the turn and privately alert the owner with metadata only; the conversation sees only acknowledgement. DSH command.text relays through the sentinel without a new turn. Mode POST persists locally and writes DSH settings with actual dshSynced; status does not probe that synchronization.
- Only the whole-message forms `/update` and `/update deps` (ASCII case-insensitive, surrounding whitespace ignored) are intercepted; any other text starting with `/update` follows the ordinary slash rules above (owner: model input; member: ignored). Those two forms are intercepted before participation-mode dispatch within the live process's selected conversation scope. Groups and non-administrators receive a fixed refusal and never reach discovery, approval or the model. The administrator's private `/update` confirms current/new versions through the recorded QQ send path before approval; failed or uncertain delivery admits nothing. The command holds shared turn admission through reply, approval and the journal's durable handled write; a replacement therefore drains the command before replaying ingress, including after rollback. Concurrent install/restore or handover refuses another approval. Owner identity is reloaded under the configuration gate before approval. `/update deps` lists cached pins, available dependency versions and explicit missing-source/discovery diagnostics. When a candidate exists, that command explicitly approves the first displayed change (SnowLuma, then DSH) only after its complete report is confirmed delivered; other dependencies require a separate command. Failed, malformed or uncertain replies admit no approval. Dependency discovery is refreshed by the supervisor or the console check action, never by a group or non-administrator command. Release execution: `docs/agents/lifecycle-tasks.md`. `/persona`, `/persona <name>` and `/persona <name|off> <conversation>` (at most three words, ASCII case-insensitive) are intercepted the same way; the administrator's private command lists or assigns personas and gets the result through the recorded send path; groups and non-administrators get the fixed refusal 「人设只能由管理员在私聊或控制台切换。」 and nothing changes. A change commits only after the administrator is re-checked under the configuration gate; the reply names conversations whose re-brief failed. In closed-agent mode it answers 「closed-agent 模式不使用人设，人设未改变。」 and changes nothing. It takes no release turn admission.
- Closed-agent mode admits only the owner's private conversation. Preset comes from closedAgentPreset, DSH default setting or marked default; unresolved empty preset is omitted from session creation and preserved in policy. Discovery failure preserves the session and fails the turn. Owner/preset settings refresh every five seconds; policy changes retire mappings/tokens. Receipt handling is serialized with console mode writes, with a 45-second live wait and no maintenance wait.
- Questions/approvals bind current session, turn and token. They survive turn end/stream loss until answered, replaced, expired, reset or policy-invalidated. WebSocket handshakes have a ten-second deadline; expiry/refresh continue during reconnect. Only the owner answers; labels match case-insensitively, other text is custom. questionTimeoutMs defaults to five minutes. Successful approvals send no confirmation. Definite rejection retains a request; ambiguous delivery is outcome-unknown and never automatically resent. Replacement/timeout/reset attempts an empty answer/rejection; timeout notice still runs after turn end. Retired turns release their worker without a final DSH event. pending-interactions.json is a filtered live snapshot cleared at startup, not a durable queue.
- Slang entries/windows/session live in selected data. Only group messages feed windows (newest 80); consumption removes captured identities so concurrent input survives. Library/window gates wait five seconds. Live and console share a FIFO job queue, per-job OS markers and slang-jobs.lock, at most 16 pending/running jobs. Abandoned markers are removed after owner exit; queued work never replays after a crash.
- Extraction produces candidates; research enriches without confirming. Only completed textual learner turns mutate/consume. Manual extraction selects the first inserted window, even an empty consumed one. Direct JSON arrays precede the bounded UTF-16 fallback scan. A valid empty array is a successful nothing-learned result that consumes the batch; malformed output (not an array, or a non-empty array without a valid entry) gets one format-repair re-ask, and only a second malformed reply consumes the batch with one log line; a backend failure on either ask never consumes it. Reads normalize without changing bytes; saves clip/identify entries, discard empty content and retain at most 2000 by status/count/update time. Only confirmed meanings enter prompts. The learner backend is `slang.learnerBackend` (default `dsh`); after a non-`dsh` backend fails, the corpus reaches DSH only when `slang.learnerFallbackDsh` is exactly `true` (default `false`), the error names every route tried and a fallback logs `slang.learnerFallbackDsh`. The learner session is rebuilt and the prompt re-asked once only after DSH's exact `session-not-found` refusal (`dsh::is_session_gone`); any other error, including prose containing "session", "404" or "not found", is an unknown outcome that keeps the saved session and fails the round. Learner sessions verify preset and model; preset/workspace changes invalidate the saved session. Config writes hold the social gate. Five-second DSH readiness polling holds automatic extraction without spending cooldown, revisiting retained windows upon recovery. Slang watchers reread configuration before probing, skip DSH calls while slang.enabled is false, and resume after enabling learning without a process restart.

- Model-facing text uses `socialV2.context.stripFromModelText` (literal string list, default empty), merged per turn/read with selected `config/model-text-blacklist.json` (`{"strip":["literal"]}`). External writes apply without restart. The file is limited to 64 KiB, 500 entries and 64 Unicode characters per literal; exceeding a limit invalidates the entire file. Missing, unreadable or invalid files contribute no strings and warn once per observed failure-state transition. The delivery overlay never writes config. Filter chat text, nicknames, quotes, natural-language queries, QQ memory `formatted`, slang `block`/`meaning`/`usage`/`example`, and `messages` strings/string arrays before serialization; preserve CQ/media atoms, JSON structure, IDs, cursors, tokens and learner source numbering. Learner format-repair echoes are filtered before escaping, independently of generated source numbering. Stored chat, logs, console views and outgoing messages retain originals. DSH/CLI prompts, harness current/replayed model messages, chat-bearing QQ/MCP reads (including memory/digest reads) and learner input share this boundary.

## Wait batching and turn allowance

- Messages waits collect arrivals for `socialV2.wait.batchWindowMs` (default 8000 ms), resetting on each arrival, bounded by `batchMaxMs` (default 30000 ms) from the first arrival. The maximum returns collected messages even below `minNewMessages`. Both durations accept integers from 1 through 120000; invalid values independently fall back to defaults. A shorter maximum truncates the window. Owner messages and bot @mentions return immediately, including during reply quiet waits. Other reply waits retain `quietMs` timing. Ingress stores structured `atSelf` and `isOwner` flags.
- Both purposes share `socialV2.wait.maxPerTurn` (default 4, positive safe integer; invalid values fall back). Admission persists the reservation under the social gate, scoped by ledger turn and token epoch, across console/MCP restarts. Superseded calls consume their slot without earning observation. Legacy turns mint `waitTurnId` once before backend execution, propagating persistence failure; no-ledger waits use that saved identity, retaining the old wake fallback until the next actual turn. Closeout and retries preserve the allowance.
- If observation is still required, the final slot becomes a messages wait with the complete observation timeout, ignoring the caller's shorter timeout, reply purpose and message minimum. Existing quiet/batched/urgent observation eligibility still applies. Final and later results carry `waitLimitReached=true`, `nextAction="end_turn"` and the exact exit: "end this turn now: produce your final answer and make no further tool calls". They never suggest sending; exhausted waits return immediately without granting observation. Exhausted turns may close with `qq_mark_read` or `qq_set_wake_config`; if observation is missing, closure forces a finite 30-second re-wake while preserving receipt/auth checks and unacknowledged unread messages. Closure repeats the exit and grants no observation evidence. Briefings, wake deltas and the wait tool explain the cap. Console-client deadlines include the full final observation and batch maximum; dispatch budgets include the batch maximum while retaining the default 515000 ms cap and 1830000 ms collector.
- **Engagement window.** `socialV2.wake.preSleepWaitMs` (default 300000, console-editable) after her last successful send (`engagedAt`: delivered text, voice, sticker or poke; cleared at each wake claim) is her engagement window; it does not exist with `preSleepWaitEnabled=false` or a non-positive gate reading. Only her own successful sends restart it; incoming chatter, a message for her she skips and a poke at someone else never extend it. While it runs the pre-sleep requirement never outlasts it, and an agent-token messages wait runs to its end whatever its `timeoutMs`/`defaultMs` (still clipped by `wait.maxMs`, unless a forced observation already exceeds it, and by the turn budget), so a window of chatter costs one slot; other callers keep their own length, clipped to the window. Such a wait returns at once, without batching, with the chatter collected before it when a message for her or an urgent @/owner message arrives; chatter alone is collected until the window ends and returns with that end result, and a wait that runs to the end counts as the window's observation. The end is the one captured when the wait started, re-checked on return: her send during the wait moves the window and keeps the turn alive. At the captured turn-budget closing point the write closure re-reads the effective deadline from the current conversation and the captured ledger budget, so a send that moved the cap prevents that closing point from ending the turn. A result that hands over an urgent @/owner message, or a message for her judged by the `forYou` hint (the @/owner test is the narrower urgent case), never ends the turn, including one that lands after the last poll, and everywhere that decision is made in the result write - at the window end, at the last slot and at the turn-budget closing point alike: one response step, no end-turn instruction, no `turnBudgetEnded`/`turnBudgetExhausted`, the consumed slot stays consumed with no extra refund (the refund bound below still applies) and the next wait is refused normally. Chatter alone ends the window: the result carries `engagementEnded=true`, `preSleepWaitSatisfied=true` and the same end-turn exit and marks `turnBudgetEnded`, so the turn completes `observationSleep` with its wake config kept, no closure reminder, no no-action reset and no cancellation. A wait called with less than 1000 ms of window left first hands over a message for her or an urgent @/owner message already waiting past the read cursor (normally, in a live turn: a message for her refunds its slot and the next wait ends the turn) and otherwise ends at once carrying the chatter already waiting past the cursor (receipts noted, no refund). An engaged wait that reaches `waitLimitReached`, and a refused wait after it (best effort: a ledger or state failure there is logged and the limit result still returns), also marks `turnBudgetEnded`. Hard-cap and ceiling enforcement stay independent.
- Every message a wait hands over carries the bridge hint `forYou` and a short `forYouReason`: any non-poke message in a private conversation (`私聊你`); a poke exactly when it targets her (`拍了拍你`); in a group a quote-reply to her, an @ of her, her nickname/group card, or the exchange rule (a member she replied to/@ or who quoted her within `questionExchangeWindowMs`, without an @ of another member). Ingress stores that classification (`question::ingress_for_you`, judged against the conversation before the message; an unreadable state loses only the exchange evidence and is logged), and results for older records fall back to their stored private/quote/@ facts. The hint never forces a reply. A wait whose result contains a message for her does not spend its `maxPerTurn` slot, at most `socialV2.send.maxPerTurn` times per turn (default 20), counted in the same ledger-turn scope as the slots; beyond that, and for other results (timeout, chatter), it spends one. Briefings state the `【互动窗口】` line only when the window exists (whole minutes, otherwise seconds) and the pre-sleep paragraph points at it; the wait tool describes the same contract.

## Briefing and wake delta

The shared participation contract is a full briefing once per actual session generation, followed by wake deltas with explicit section replacements/removals. The DSH reserved2 route implements it; harness participation remains future work (`harness.md`). Persona/system instructions and tool declarations remain session-owned.

- The briefing contains identity/role, bounded operator background, behaviour, stickers, mandatory tool-only sending and optional sending guidance, reply timing, sleep/observation rules, retrieval hints, memory topics/thoughts (`memory`), member impressions (`impressions`), participation context and enabled confirmed slang, grouped into memory layers (next bullet). Clock-only ageing does not change memory/participation hashes. Briefing memory omits interaction counts, which change with every message. The selected blacklist and configured strips apply before section hashing and rendering, including replacements; metadata describes delivered content.
- Memory layers (`briefing.rs`) cover the DSH briefing and wake delta: Identity (`identity`: role line, bot identity, role hint, then the persona core from `briefing::persona_core`), Relationship (`operator`, `impressions`), Conversation (`memory`: topics then pending thoughts; `participation`; `slang`) and Material (the delta's automatic recall); behaviour, stickers, sending, reply, sleep and retrieval are rule sections outside the layers, never cut or counted. Budgets are runtime configuration read every wake: `memory.layers.identityTokens` (default 1500), `relationshipTokens` (1500), `conversationTokens` (800), `materialTokens` (1000) and `materialItems` (default: `memory.inject.relatedTopK` when set, else 5), in estimated tokens (one per non-ASCII character, one per four ASCII characters); a missing, non-integer or out-of-range value uses the default. Identity and Relationship are never cut: what they use beyond their budgets comes out of Material first, then Conversation. Conversation is cut to what remains from its last section backwards (slang, participation, then pending thoughts and topics, oldest line first). Material keeps the best-ranked recalled memories that fit; the Material budget covers the whole recall block, its header, its footer and the `【记忆索引】` hint (at most 60 estimated tokens for the hint: subjects are dropped from its end until it fits, and the line is omitted when none fits), so when no memory fits only the index hint and footer remain; a cut memory is neither rendered, held for the generation nor counted as a hit; a recall block the model-view strip empties delivers no memories and holds none. The console preview shows recall before the Material budget. Each DSH attempt's ledger `attempt` record carries `layers` `{injected, cut}` item counts per layer; a section the model-view strip empties is not counted as injected (its items are taken back from its layer); a section the strip only partly changes stays counted in full. An Identity that injected nothing (any conversation), or an empty Relationship in the owner's private chat, alerts the owner once per conversation, session, epoch, generation and layer per process (`admin_alert::notify_memory`). Compatibility and CLI renders are not layered.
- Member impressions are listed in prompts, briefings and console memory views by this rule: members speaking in the unread/recent window first (newest speaker first, matched by QQ id or display name), then the rest by `lastSeenAt`, at most `socialV2.context.impressionPromptLimit` (default 10), shown in storage order. A repeated trait moves to the newest slot and the oldest traits beyond `impressionMaxTraits` (default 10, at most 20) are replaced; an explicit update that replaces the trait list keeps the newest `impressionMaxTraits` the same way; `impressionMaxMembers` (default 50) bounds members, pruning the longest unseen. `interactionCount` and `lastSeenAt` advance when a member with an impression speaks in a conversation (a journal replay does not count twice). A memory write (append or update) changes neither: a new entry starts `lastSeenAt` at the write time with count 0, and an update cannot set `interactionCount`. Names such as `__proto__` are ordinary names.
- Every wake carries current token authority, reason/instruction, unread count, wake config/timers, reply quiet and pre-sleep remaining status, a short installed-revision reference and one fresh authenticated message packet with exact IDs/cursors/partial metadata. Wake-config keyword text and the other rendered delta text use the same model-view overlay as the briefing. Packet chat fields are filtered before serialization, preserving structural metadata. Refusal provenance comes from that delivered packet, never a discarded compatibility render. DSH final text is never forwarded; each delta repeats the tool-only sending reminder.
- Full/delta selection happens in `pipeline.rs` after actual sid/epoch resolution, including a replacement inside the current dispatch. `session_map.rs` persists versioned `briefings` records in selected sessions.json under the mapping and social gates. `pending` RPC identity is not installed proof: only its observed user/message in the same sid/epoch/generation acknowledges delivery. Prompt RPCs default the prompt `requestId` to the tracked envelope ID; DSH 0.2.1-rc.2 echoes the prompt `requestId` in durable `data.source.rpcId`. Explicit request IDs remain unchanged, and foreign/missing delivery identities never acknowledge a briefing. Refused/unknown admission keeps existing probe/no-resubmission rules. Stale collectors cannot acknowledge a replacement or rotated epoch.
- `session_context.rs` folds snapshot/live/recovery events by sequence. A completed compaction or a landed summary/checkpoint replacement invalidates exact briefing proof once per compaction ID; failed compaction, prune-only and image offload do not. Refresh occurs on the next external wake, without an extra turn from the collector. Partial tails retain durable proof; a forward unobserved history gap forces one conservative full briefing. No periodic refresh is sent.

## Cache-aware session rotation

- `session_rotation.rs` and the reserved2 hub rotate sleeping DSH conversations whose last call's total input (cache hit + miss + write) is at least the hot-reloaded per-model `dsh.rotation.caps` entry, then `default`, then 500000. Last-call evidence includes closing reminder calls. The last completed turn must have confirmed a wake config; open/paused turns, queued ingress/wakes/retries, active compaction and pinned CLI routes defer new maintenance. Owner private chat uses the same policy.
- `dsh.cacheTtlMinutes` is per provider, with defaults local-relay 5 and opencode-go 120; unknown providers need a positive finite configured TTL. Idle time starts at the later of last incoming message and completed turn end. Rotation becomes due at max(0, TTL minus one minute). Below-cap sessions survive cache expiry. Policy changes, incoming messages and external wakes cancel or delay maintenance; the conversation slot stays owned until digest outcome/stop is known, then the wake proceeds normally.
- Digest runs only for turns beyond `digestedThrough`, with durable RPC identity and no blind resubmission after uncertain admission or restart. A definite rejection finishes failed. Completed refusal/error text uses the shared classifiers, parses structured errors with original JSON key casing, and never advances the digest cursor; an empty final answer after successful memory tools is valid. Failed digest alerts once and still permits rotation when execution is settled. A pending digest is verified by its persisted RPC identity (never replayed under a fresh RPC, including proven absence or queue removal; missing or partial history stays unverified) at most once more; repeated uncertainty checkpoints phase `rotate` with `rotation.retireUnknown`, retires the session without advancing `digestedThrough`, and keeps the memories and archived source history. Failed or unfinished `memory_write` calls (including the legacy `写入失败：` text with `isError:false`) fail the digest. Settled digest execution persists phase `rotate` separately from digest success; restart rechecks current idle/admission guards and resumes retirement without submitting that digest again. Digest failure does not mark the turn as a completed rotation attempt. A reset error marks the attempt done to avoid an automatic failure loop.
- Digest failures carry a fixed step (`context-read`, `connect`, `rpc-lookup`, `follow-open`, `follow-read`, `intent-write`, `prompt`, `turn-facts`, `cancel`, `observe`, `memory-write`, `digest-result`, `checkpoint`) and error kind, never DSH/model text; the last failure per conversation persists in `sessions.json.rotationFailures` (shown by `GET /api/sessions`). Mapping removal alone never releases maintenance: a retained matching `rotate` checkpoint recovers a partial reset, including after restart, and maintenance and queued ingress stay held until the replacement token is durably persisted, so late old tools are denied. Read failures count failed recovery passes per conversation in memory; the twelfth emits one content-free diagnostic and a daily-limited owner notice, then retries every 60 s, and the counter clears only after revocation is confirmed. Owner notices are claimed once per conversation per local day in `data/rotation-alerts.json` under the sessions lock (independent of an unreadable `sessions.json`, adopted into `rotationAlerts` when readable); the notice mutex covers claim and decision, and with no storage a day-aware process guard allows at most one fallback notice. A received DSH error frame stays a rejection despite timeout-like codes or a later reset.
- Rotation rechecks sid, epoch, incoming/unread/wake state and turn admission under the social gate, then uses the shared reset/archive path: revoke the old mapping/token, preserve conversation data/recent messages, stop and archive DSH without deletion. The next external wake creates a fresh session/full briefing. Successful archive logs one activity line with conversation, input tokens and digest yes/no and sends nothing. Digest/reset/archive failures produce one durable deduplicated owner alert per conversation/session; failed archive never logs success.
- DSH compaction remains the preset-owned mid-turn safety net (owner policy: 0.6 of the declared 1M window, retain 32000). HER makes no idle summary/compaction call. Quota-aware sleep is outside this contract. ADR 0007 records the rotation decision.

## Bridge-enforced reply timing

Reserved2 running turns (including generation-matched recovery) suppress non-urgent message wakes before trigger evaluation and log `in-turn`. Bot @mentions and owner messages use the base wake queue, retries, quotas and restart/CLI behavior. At successful same-generation turn completion, drop a queued urgent follow-up and log `covered` only when its exact seq was returned in that turn’s model tool result (wait, unread/history or mark-read acknowledgement). Tool receipts are published only at the successful response boundary after all required writes succeed. Fresh and resumed revision sends require persisted revision budget, outbox supersession and final send settlement; a failed revision or wait write grants no delivery evidence and preserves the base follow-up. Evidence is scoped to one turn; prompt snapshots, buffers and read cursors grant no urgent coverage. Failed, cancelled or timed-out turns, missing evidence, restart and CLI completion preserve the base follow-up. Pre-sleep duration retains its rules; for an engaged turn the engagement window in `## Wait batching and turn allowance` replaces the restart-on-incoming rule.

Idle quote replies retain their existing direct `atMention` trigger when enabled; a quote without an actual @ is still suppressed during a running turn. `triggers.question` remains a boolean. It admits a question quoting her, or a question from an established exchange participant within `socialV2.wake.questionExchangeWindowMs` of her latest conversation message (default 90000 ms; positive safe-integer overrides, invalid values use the default). Exchange evidence within that same window is a member's quote to her or a confirmed bot reply/@ to that member. Questions with an @ of any other member are excluded. Nagging phrases require the same recent exchange even when quoting her. AI words and legacy aliases do not establish direction; current nickname/group-card and configured keyword triggers remain separate. Confirmed text and sticker sends retain explicit reply/@ targets in recent-message metadata for exchange matching; failed or uncertain sends establish no exchange.

Reserved2 message wakes use `socialV2.reply.wakeQuietMs` (3000 ms). Every substantive incoming message, including one that does not match a wake trigger, resets an armed message wake; the deadline is capped at 30000 ms from the first unseen arrival. Bot @mentions and the configured owner's messages trigger an immediate wake. The in-turn admission rule above, wake priority, wake quotas, timer wakes and authority checks still apply. The live hub dispatches due work on its normal tick; the legacy offline scheduler without a reply policy retains its replay timing.

Reserved2 text sends (`qq_send_message`, burst, reply, direct group/private console sends and text outbox resumes) enforce timing before every bubble and before any outbox attempt. Each bubble draws an independent log-normal quiet window (log-space sigma 0.5): median 10000 ms, clamped to 4000–25000 ms. `socialV2.reply.quietMedianMs`, `quietMinMs` and `quietMaxMs` override the ordinary window. An owner message or bot @mention uses median 3000 ms, clamped to 1000–6000 ms. Quiet runs from `lastReplyIncomingAt`, the last substantive arrival, so queueing, reading and thinking count. Older records fall back to `lastIncomingAt` or a substantive recent message timestamp; with no known incoming timestamp, quiet is already satisfied. The wake override accepts integer milliseconds 1–30000; quiet overrides accept 1–120000. Invalid fields independently use defaults; a resulting min/median/max ordering violation restores the entire ordinary default triple. Loading never fails on these overrides.

The typing budget uses the existing UTF-16 first-gap base/per-character settings and clamps, generalized to every bubble, multiplied by an independent uniform factor in [0.75, 1.25]. Observed DSH thinking since `started`, or since the last delivered bubble for subsequent replies, reduces that budget; setup time before the observed start earns no credit. Missing start evidence earns no first-bubble typing credit. Existing `firstGapEnabled=false` disables typing delay only; `fillTypingBudget=false` retains a full typing budget. Quiet and typing deadlines overlap; they are not added. Private held sends issue OneBot `set_input_status(user_id, event_type=1)` and clear with `0` on release, revision, revocation or failure. Groups use the delay without status calls. Status calls are best effort with a 250 ms request budget and cannot refuse a reply. Test randomness is explicitly seedable; production seeds it from OS entropy.

Any arrival during a hold cancels the current and remaining unsent bubbles, without an outbox attempt, and returns HTTP 200 with `held=true`, `reviseRequired=true`, actual `sent`, bounded `newMessages`, receipt/cursor metadata and “对方又说了…” guidance. Already delivered burst bubbles are retained. The model revises or explicitly sends again; it never blindly repeats delivered content. A partial packet continues with `nextAfterSeq`; `readThroughSeq` still reflects only actual offered receipts. Holds reserve no #94 wait slots and grant no sleep observation. Up to three revision returns are admitted per turn/token epoch, persisted as `replyRevisionBudget` using the same identity as wait admission. After that, a send uses its request's fixed quiet/typing deadline despite later arrivals. A new turn or token epoch resets the revision budget. Send guards continue polling while held. Before reporting a revision return, one durable outbox `superseded` decision covers all remaining planned indices; an append/sync failure returns 503 instead. Legacy per-item `superseded` records remain readable. Discarded items release quota and are excluded from resume and recovery liabilities, including after a partially delivered burst or a crash before per-item settlement. Authority cancellation remains `cancelled`.

`inbound_text::quiet_neutral` classifies the original inbound representation before text truncation. An arrival is neutral only when every segment is image/face/mface/bface/sface, a quote wrapper around qualifying media/emoji, or whitespace/emoji-only text; mixed words or unknown segment types are substantive. Raw CQ image/face/mface/bface/sface codes and `[图片]` / `[表情…]` placeholders follow the same rule. Emoji recognition covers Unicode pictograph/emoticon/dingbat blocks, common emoji symbols, skin tones, variation selectors keycaps and ZWJ sequences; ordinary digits, punctuation, words, quote-only messages, voice/video/file markers and unknown forms count as substantive. Neutral messages remain in recent/unread and can be returned by a held send, but do not extend either quiet timer. The stored `quietNeutral` flag and `lastReplyIncomingAt` preserve this decision across processes and restarts; `lastIncomingAt` and #94 wait batching keep tracking all arrivals.

Briefing, wake delta, snapshot, structured prompt and preset guidance assign reply timing to the bridge. The model directly calls a send tool when it has a reply and processes a revision result if one is returned. `qq_wait_for_messages` remains available for deliberately waiting on someone mid-turn and for the existing pre-sleep observation; it is not a first-reply prerequisite.

Harness currently admits only chat and owner-private closed-agent turns (`pipeline.rs::run_chat_turn`); both first-generation reserved and reserved2 execution refuse a harness selection before model submission. The reserved2-only debounce, quiet hold, draft revision and private typing status therefore have no admitted harness turn to time. DSH/CLI and harness chat/closed-agent retain their shared existing delivery policy. Harness QQ tools still use the common console send path and current tool-result filtering; a future reserved2 admission must use that path and its timing/authority checks.

Text send guards run in the shared console batch executor for DSH, CLI and harness QQ tool callers, before quota, intent and reply holds. Hot-read `socialV2.send.repeatLimit` defaults to 2 delivered/uncertain identical normalized bubbles; `maxPerTurn` defaults to 20 bubbles. Both accept positive safe integers; invalid overrides use defaults. A batch exceeding either bound is refused in full with HTTP 429, without a hold, attempt or revision. `repeatWindowSends` defaults to 0 (the previous ledger turn, or previous sending scope for no-ledger calls); a positive safe integer selects the last N conversation outbox sends instead. Current-turn repeats always count independently of that window. The cap and last-N window include typed bot sends in actual attempt order; only canonical text items compare for repeats. Confirmed and uncertain sends count; definite failures, cancelled and superseded items do not. Admission stamps the same ledger-turn/token-epoch identity as waits and revisions, with the same legacy fallback. Send limits and notice claims follow the actual turn across token rotations; wait and revision budgets retain their existing per-epoch reset. Attempts stamp their submitting turn scope, so resumed old batches spend the current turn cap. Restart and timeout never erase outbox history. Refusals log only key, opaque turn scope, reason and count; the first refusal records a durable notice claim and queues one content-free owner-private notice for that turn, through the existing bounded notifier. Authority, quotas and uncertain-send verification continue to apply.

`[表情N]` in a send tool denotes a real QQ face from the supported allowlist. Face conversion, normalized outbox storage and repeat checks share the representation defined in `media-transport.md`; a face-only bubble counts as one send. Unknown/malformed tokens stay text; `[表情]` and `[表情:<summary>]` are stripped. Use a send tool directly when ready; after a limit result, follow its exit instruction.

Reserved2 text-only CLI relays require the companion console and submit their draft through the same authenticated console send endpoint as DSH tools. Connection and request transmission share a one-second budget; the existing 300-second total request budget permits reply holds. A transport failure emits the content-free line `CLI reply send failed: companion console unavailable` and ends the turn through the existing failure path, without a direct OneBot fallback. The bridge retains the turn token captured before the CLI call and audits final canonical face-normalized text with the outbound sentinel and known-secret checks. Each held revision supplies its bounded new-message packet to subsequent CLI drafts, retaining all earlier revision packets within the same actual turn (at most three revisions, matching the shared hold budget); discarded drafts spend no send cap. HTTP 429 ends that CLI turn without another send, DSH fallback or backend-failure alert. An empty initial CLI response retains the existing DSH fallback; an empty revised draft or `[SILENT]` completes the turn without a send. CLI backend failures retain their existing classification and private reporting. Other send failures retain the outbox evidence and are never retried blindly.

## Crate contracts

Model-facing chat copies use `model_view` across DSH, CLI, harness replay, tools and slang extraction; source chat packets and outgoing messages retain their existing text. Harness QQ tool facts retain packets subject to record token masking; memory facts retain token-free structured sources so replay filters fields before rendering generated IDs. For harness stream retry, interrupted-tool recovery and live-handler settlement during reset, read `docs/agents/harness.md`. Model/backend failures use content-free owner-private alerts and refusal records. Read `docs/agents/prompts-modes.md` and `docs/agents/dependency-recovery.md` before changing these boundaries. Outbound sends independently reload `security.outboundGuard`; only boolean `false` disables the default sentinel and its notices (`docs/agents/social-state.md`).

Reserved2 running turns, including generation-matched recovery, suppress non-urgent wakes before probability/question evaluation. Urgent arrivals retain the base queue, retries and quotas; successful same-generation completion removes only exact seqs offered in that turn's successful tool responses after all required writes succeed. Fresh and resumed revision sends publish coverage only after budget, outbox discard and final settlement succeed; failed responses preserve the base follow-up. Prompt snapshots and cursors grant no urgent coverage. `question.rs` owns exchange direction and its configurable 90000 ms window; its contract follows `docs/agents/prompts-modes.md`; confirmed text/sticker targets retain exchange metadata. Harness currently supports chat and owner-private closed-agent only (`docs/agents/harness.md`).

Reserved2 reply debounce, per-bubble quiet/typing holds, bounded durable draft revisions and terminal outbox supersession, wait batching, urgent arrival bypass, durable per-turn allowance, the engagement window (the five-minute `preSleepWaitMs` after her last successful send, restarted only by her sends; its end marks `turnBudgetEnded` so the turn completes `observationSleep` and keeps its wake config, and a wait that returns a message for her keeps its slot up to the per-turn send bound), the reserved final observation and exact wait-cap exit with finite 30-second re-wake closure follow `docs/agents/prompts-modes.md`. Keep wait leases, read-through receipts and token/ledger authority checks intact across console restarts. Legacy turn identity is minted once before backend execution; ingress retains structured `atSelf` and `isOwner` flags and the `forYou`/`forYouReason` hint (`question::ingress_for_you`, judged against the conversation before the message; a poke is classified by whether it targets her), which waits also compute for older records.

Reserved2 DSH briefings/deltas are selected at actual session submission.
