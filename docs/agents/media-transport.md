# Media, stickers and voice

Read for model media acquisition, normalization, voice libraries or delivery verification.

- Missing selected self portrait is 404; redirected/invalid paths and other I/O failures are 503, with containment checked before reads. Media acquisition tries safe gateway cache, bounded base64/local files, URL/CDN and face fallback in order. Gateway local files must be in both the configured home and selected root. Originals stay unchanged. Defaults/clamps are 8 MiB (256 KiB–20 MiB), 64 MP (1–64 MP), five items (1–8); original byte sizes consume budget before compaction and an animation consumes one source slot.
- Ingress, chat and forwards preserve image/mface/face references, subtype/emoji metadata, package/key, sanitized 60-character summaries and forward IDs. Emoji-only images remain resolvable by CDN. Quote previews share the ingress text renderer.
- Every model-bound image uses media_normalize.rs. Decoded PNG/JPEG/WebP at most 64 KiB and 1024×1024 may pass unchanged. Other opaque stills use JPEG qualities 75/60/45/35/25; alpha uses the smaller lossless PNG/WebP. Never upscale; reduce further to at most 96 KiB. Output MIME matches bytes; changed MIME exposes originalMimeType.
- GIF/animated WebP preflight checks canvas/frame dimensions before streaming disposal/composition decoding. At most eight evenly spaced frames include first/last; single-frame input is a still. Ordered image blocks include a Chinese sample-count note. MCP uses type:image, DSH inline type:image/mediaType; singular image remains the first sample alongside images.
- Decode bounds: 20 MiB input, dimensions 1–16384, configured pixel cap, 256 frames, 128 million cumulative canvas pixels, estimated working set 192 MiB (12 bytes/pixel stills, 16 animation, plus one MiB WebP overhead), PNG/JPEG/GIF allocation 128 MiB. WebP preflight permits only one main Huffman group and constant transform maps using single-literal trees; general/meta-Huffman maps and compressed ALPH are refused for stills and ANMF. One process-wide decode/encode gate retains only compressed samples between frames.
- Four process-wide acquisition permits are taken before downloads/gateway/base64/local reads and held through normalization/output. Excess falls back to unreadable-media text/face description. Gateway image JSON caps source bytes×4/3+4096 and headers 16 KiB; face JSON 64 KiB. Failures disclose no decoder details. Curl temp names use an atomic sequence, pin public addresses, revalidate five redirects, try at most four addresses within 20 seconds and reject partial bodies/nonzero children.
- Console startup warms enabled sticker collections once in the background; failure leaves no cache and later list retries. TTL and ten-second agent force throttle are per selected root. Image downloads use safe_fetch. Remark refreshes stale cache, calls the selected gateway then re-reads/writes under the state gate; administrator variants reject agent credentials.
- Voice library uses selected resources/socialV2.voice.dir: 13 extensions, no hidden/link/unreadable files, four levels, pinyin order, at most 100. Missing/unreadable libraries list empty so operator path sends still work. Voice/tool flags default off; voice.enabled gates AI only. AI references must stay in the library, with no traversal/URL/base64/outside path. Operator paths may be any local file, resolving relative to resources then library, with a separate budget. Windows drive-less roots are absolute and checked before library-relative lookup.
- Voice `maxSeconds` defaults to 60 and is capped at 60 for QQ non-members; larger configured values are clamped with a `[voice]` log. Console saves persist the capped value; config views, library limits and prompt summaries expose the effective limit. Smaller positive limits remain valid. Every AI/operator send and dry run requires a finite positive duration or a proven SILK upper bound within the effective limit before processing, outbox intent or any gateway send. SILK/SLK files have length-prefixed packets after `#!SILK_V3` (optional leading 0x02); each packet may contain 1–5 frames (20–100 ms). Report and check the conservative duration bound of 100 ms per packet, including zero-length DTX packets. If that bound exceeds the effective limit, refuse through the existing error path with a message that the SILK file's length cannot be confirmed and requests mp3/wav/ogg instead. Malformed framing remains refused. Other formats require successful ffprobe output with valid duration metadata; unavailable/failed probes and missing/invalid duration are refused through the existing error path with the cause.
- Volume processing uses local ffmpeg (FFMPEG_PATH, configured path, PATH), deletes its temp after sending; ffprobe uses FFPROBE_PATH/PATH with null stdio/temp duration output. Missing required ffmpeg fails. Budgets spend only on confirmed delivery; known-delivered unknown sends count. AI stamps after send, operator at pre-send time. Voice shares the send chain and fresh default-off tool guard.
- Voice outbox stores kind:voice and an intent label. Refusal yields not_committed; uncertain response searches newer own record history excluding already confirmed IDs, otherwise remains unknown without resend. Verify reads get_msg/record without gateway paths unless verify:false; readback requests fetch_ptt_text. Incoming/quoted records render as voice labels. Text resume refuses voice batches.

## QQ face transport

The shared QQ text-send path normalizes model text before the send guard, outbox intent and reply hold. It strips bare `[表情]` and summary `[表情:<summary>]` forms, canonicalizes supported numeric `[表情N]` tokens (including leading zeroes), and trims the result until stable. Normalization is idempotent even when stripping inside malformed or nested notation exposes another token: `a[表情[表情]]b` becomes `ab`. The configured outbound sentinel and CLI known-secret checks audit this final canonical text before submission; admission, outbox, history accounting and OneBot segments use the same representation. Legacy outbox intents remain append-only; resume canonicalizes their in-memory text before verification, admission, settlement and submission, and audits every resend candidate before an attempt. Empty normalized bubbles are removed; an entirely empty batch is refused before an intent. Other text is preserved. Automatic chat replies normalize the complete reply before reserved-mode burst splitting, UTF-16 length splitting and outbox recording; their enabled reply and command audits inspect both raw and canonical text.

Supported IDs are the pinned, sorted QQ system-face allowlist in `her/src/outbound_message.rs`, extracted from the `QSid` entries in [NapCat face_config.json at 98d781d](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/packages/napcat-core/external/face_config.json). The [SnowLuma face codec](https://github.com/SnowLuma/SnowLuma/blob/e44e4ced17c5911b9aa9db449ba29f2d9e567d2a/packages/onebot/src/event-converter/element-codecs.ts) accepts that OneBot face shape; its protocol layer resolves QQ system-face metadata. This bridge uses an explicit known-ID compatibility list rather than accepting every nonnegative integer the codec can parse. Unknown numeric IDs, malformed tokens, signs and non-ASCII digits stay literal text. Updating gateway compatibility requires updating the allowlist and fixtures; there is no runtime network lookup.

Each supported token becomes one OneBot `face` segment with a canonical decimal string `data.id`. Surrounding text becomes ordered `text` segments. Reply and @ segments retain their existing prefix order; raw CQ text remains escaped. A face-only message is one bubble, one outbox item and one quota/guard unit. All send splitters cut before a supported face token that crosses the length boundary; a token longer than the configured limit occupies its own part. Outbox parts preserve the canonical text actually sent. The outbox stores the normalized placeholder spelling, and history verification reconstructs the same spelling from face segments before comparison. An empty canonical comparison never proves delivery of a legacy summary-only item. Unknown/uncertain delivery is never retried without existing history verification.

Inbound `face` segments remain `[表情N]` in model text. Echoing that notation through any text send tool returns a real face. Inbound mface/summary notation carries no reproducible face ID and is stripped outbound. Model-image acquisition and normalization retain the contract in `her/AGENTS.md`.

## Crate contracts

Automatic replies normalize the complete text before burst or length splitting; send splitters preserve supported face tokens and record parts exactly as sent. Text tools and reserved2 CLI replies share canonical face normalization, repeat/cap admission and durable outbox accounting before reply holds; see `docs/agents/media-transport.md` and `docs/agents/prompts-modes.md`. Harness QQ tools dispatch through the common MCP/console handlers and retain uncertain-delivery classification. CLI relay requires the authenticated companion console, bounds connection/transmission to one second, permits held responses within 300 seconds, and never bypasses refusal or transport failure with a direct send. Chat confirmation-append failures retain the known delivery count, surface the persistence failure and stop later parts.
