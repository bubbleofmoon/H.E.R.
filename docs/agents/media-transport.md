# Media, stickers and voice

Read for model media acquisition, normalization, voice libraries or delivery verification.

- Missing selected self portrait is 404; redirected/invalid paths and other I/O failures are 503, with containment checked before reads. Media acquisition tries safe gateway cache, bounded base64/local files, URL/CDN and face fallback in order. Gateway local files must be in both the configured home and selected root. Originals stay unchanged. The global `socialV2.media` settings govern the 8 MiB byte allowance (256 KiB–20 MiB), 64 MP pixel allowance (1–64 MP) and five-item batch (1–8). Sticker sends use the same source byte allowance. Original bytes consume budget before compaction and an animation consumes one source slot.
- `qq_get_self_image` in a selected runtime first serves her live QQ avatar (`self_avatar.rs`): her uin is `userId` in `<data>/identity.json` (5–11 digits, no leading zero); the only address fetched is `https://q1.qlogo.cn/g?b=qq&nk=<uin>&s=640`, through `safe_fetch::fetch_exact` over `guarded_fetch.rs` (pinned public address, no redirect followed, 2 MiB, `media_normalize::looks_like_image` magic, 8 seconds for the transfer after the 5-second lookup; every `guarded_fetch` curl starts with `-q`, clears `CURL_HOME`, `XDG_CONFIG_HOME`, `HOME`, `APPDATA`, `USERPROFILE` and the proxy variables including `NO_PROXY`/`no_proxy`, passes `--noproxy *` and `-K -` stdin config with URL/headers off argv, brackets IPv6 `--resolve`, uses `ChildGuard` and Linux `PR_SET_PDEATHSIG`, and streams `-i` stdout without writing temporary transfer files). The avatar is kept with its uin in `<data>/self-avatar.cache` (JSON, outside state backups, which take only `.json` files) for 30 days, and a failed fetch is recorded there. Every fetch first writes and reads back an attempt reservation, `<data>/self-avatar.attempt` (one `{uin, attemptAt}` entry per account that fetched in the last 15 minutes); while her uin's entry is younger than 15 minutes, or when the file cannot be written and read back, or is unreadable or unparsable, no fetch runs and the portrait is served. So a cache that is missing, damaged, unreadable or cannot be stored allows at most one fetch per 15 minutes, across restarts and processes. Deleting both files forces a fresh fetch. When her uin changes during a fetch, a normalization or the cache store, nothing is served under the old uin (the portrait is served; the record stored carries its own uin). Before each live fetch, `<data>/self-avatar-transfer` is prepared and any legacy `her-fetch-*` leftovers are removed, while the streaming transfer writes no body or header files to disk. A reservation or failure record dated ahead of the clock (the clock moved back) is restamped now and counts as in force. One check-fetch-store runs at a time per runtime under the `<data>/locks/self-avatar.lock` file lock; another caller waits up to 15 seconds for it, and the tool call waits up to 45 seconds. A missing or invalid uin, a failure, the backoff or a gate still taken after the wait serves the static portrait (rules above). The console answer carries `source` (`qqAvatar` or `portrait`); the tool result is one fixed lead line plus the image blocks, so no file name, path or address reaches the model. Unit tests replace the fetch with `self_avatar::FETCH_TEST_HOOK`; without a hook it fails, so unit tests never contact qlogo. Integration tests run the real binary, which has no hook: they never call the self-image route in a runtime whose `identity.json` holds a valid uin (written by the test or by a live bridge).
- Ingress, chat and forwards preserve image/mface/face references, subtype/emoji metadata, package/key, sanitized 60-character summaries and forward IDs. Emoji-only images remain resolvable by CDN. Quote previews share the ingress text renderer.
- Every model-bound image uses media_normalize.rs. Decoded PNG/JPEG/WebP at most 64 KiB and 1024×1024 may pass unchanged. Other opaque stills use JPEG qualities 75/60/45/35/25; alpha uses the smaller lossless PNG/WebP. Never upscale; reduce further to at most 96 KiB. Output MIME matches bytes; changed MIME exposes originalMimeType.
- GIF/animated WebP preflight checks canvas/frame dimensions before streaming disposal/composition decoding. At most eight evenly spaced frames include first/last; single-frame input is a still. Ordered image blocks include a Chinese sample-count note. MCP uses type:image, DSH inline type:image/mediaType; singular image remains the first sample alongside images.
- Decode bounds: 20 MiB input, dimensions 1–16384, configured pixel cap, 256 frames, 128 million cumulative canvas pixels, estimated working set 192 MiB (12 bytes/pixel stills, 16 animation, plus one MiB WebP overhead), PNG/JPEG/GIF allocation 128 MiB. WebP preflight permits only one main Huffman group and constant transform maps using single-literal trees; general/meta-Huffman maps and compressed ALPH are refused for stills and ANMF. One process-wide decode/encode gate retains only compressed samples between frames.
- Four process-wide acquisition permits are taken before downloads/gateway/base64/local reads and held through normalization/output. Excess falls back to unreadable-media text/face description. Gateway image JSON caps source bytes×4/3+4096 and headers 16 KiB; face JSON 64 KiB. Failures disclose no decoder details. `guarded_fetch.rs` (`DnsResolver`/`HttpTransfer` seam with hardened `curl` adapter) rejects `localhost`/`.localhost`/`.local` pre-DNS, pins public addresses with bracketed IPv6 `--resolve`, revalidates five redirects, tries at most four addresses within 20 seconds and rejects partial bodies/nonzero children; binary sniffers (`image_dimensions`, `looks_like_image` in `media_normalize.rs`; `looks_like_silk` in `voice.rs`) live with their media/voice domains. `OneBot` (`onebot.rs`) is the sole OneBot HTTP adapter over `loopback_http.rs`, enforcing strict literal loopback endpoints, split connect/write/read deadlines, mandatory wire-size caps (16 KiB headers; decoded body limits apply to `Transfer-Encoding: chunked` payloads as well as `Content-Length`), optional lone-surrogate-safe JSON decoding and pre-write `NotCommitted` vs post-write `Unknown` tracking.
- Console startup warms enabled sticker collections once in the background; failure leaves no cache and later list retries. Cache TTL is live and the ten-second agent force throttle is fixed, both per selected root. The sticker registry owns the system, collection and prompt switches, list and prompt counts, and collection quotas, bytes and remark length. An unset collection quota disables that time budget. Image downloads use safe_fetch. Remark refreshes stale cache, calls the selected gateway then re-reads/writes under the state gate; administrator variants reject agent credentials.
- Voice library uses selected resources/socialV2.voice.dir: 13 extensions, no hidden/link/unreadable files, four levels, pinyin order, at most 100. Missing/unreadable libraries list empty so operator path sends still work. The `sendVoice` and `socialV2.voice.enabled` switches default off. The voice setting gates AI only. Voice size, rate budgets and automatic readback are also live settings. AI references must stay in the library, with no traversal/URL/base64/outside path. Operator paths may be any local file, resolving relative to resources then library, with a separate budget. Windows drive-less roots are absolute and checked before library-relative lookup.
- Voice `maxSeconds` defaults to 60 and is capped at 60 for QQ non-members; larger configured values are clamped and logged at most once per distinct value per process. If the warning set is busy, the caller skips the warning and a later load can emit it. The settings API accepts positive values up to 60. Legacy social-config saves cap them, and config views, library limits and prompt summaries expose the effective limit. Smaller positive limits, including fractional seconds, remain valid. Every AI/operator send and dry run requires a finite positive duration or a proven SILK upper bound within the effective limit before processing, outbox intent or any gateway send. SILK/SLK files have length-prefixed packets after `#!SILK_V3` (optional leading 0x02); each packet may contain 1–5 frames (20–100 ms). Report and check the conservative duration bound of 100 ms per packet, including zero-length DTX packets. If that bound exceeds the effective limit, refuse through the existing error path with a message that the SILK file's length cannot be confirmed and requests mp3/wav/ogg instead. Malformed framing remains refused. Other formats require successful ffprobe output with valid duration metadata; unavailable/failed probes and missing/invalid duration are refused through the existing error path with the cause.
- Volume processing uses local ffmpeg (FFMPEG_PATH, configured path, PATH), deletes its temp after sending; ffprobe uses FFPROBE_PATH/PATH with null stdio/temp duration output. Missing required ffmpeg fails. Budgets spend only on confirmed delivery; known-delivered unknown sends count. AI stamps after send, operator at pre-send time. Voice shares the send chain and fresh default-off tool guard.
- Voice outbox stores kind:voice and an intent label. Refusal yields not_committed; uncertain response searches newer own record history excluding already confirmed IDs, otherwise remains unknown without resend. Verify reads get_msg/record without gateway paths unless verify:false; readback requests fetch_ptt_text. Incoming/quoted records render as voice labels. Text resume refuses voice batches.
- Inbound voice transcription (`voice_stt.rs`) runs only at reserved2 ingress and only for a conversation key listed in `config.json` `voiceTranscription.conversations` (default none; other modes keep `[语音]`). A message whose segment array holds exactly one `record` segment with an http(s) `data.url` is downloaded through `safe_fetch::fetch_voice` over `guarded_fetch.rs` (public pinned addresses, at most two revalidated redirects, `voiceTranscription.maxBytes` default 1 MiB clamped to 64 KiB–4 MiB, `voice::looks_like_silk` SILK v3 magic with an optional leading 0x02; `<data>/voice/transfer` removes any legacy `her-fetch-*` leftovers before download while streaming `-i` stdout writes no transfer files). It must be whole SILK v3 framing, and a packet count above 50 a second of `maxSeconds` (default and cap 60, at least 1) refuses it, since every packet holds at least one 20 ms frame. The record is posted unchanged to the local transcription helper at `voiceTranscription.helper`, which must be `http://<loopback IP literal>:<port>` (no name, path or credentials): `POST /v1/transcribe`, `Content-Type: application/octet-stream`; the helper answers `200` with a `Content-Length` JSON object of at most 16 KiB whose string `text` is the transcript (other members are ignored; any other status is a refusal, any other shape invalid). One attempt (download and helper) ends within `timeoutMs` (default 8000, clamped to 1000–20000): the download, all redirect hops and address attempts together (a host lookup has its own five-second limit and counts against it), ends 3 s before the deadline (at most half of `timeoutMs`) so the helper keeps the rest, and the record is written to the helper in chunks within that deadline, so a helper that reads slowly ends the call as a timeout. The helper is asked only with at least 250 ms left: a download that overran leaves the label and the attempt ends as a missed deadline, which is no helper outage and no owner notice. The caller waits at most 500 ms more, one transcription runs at a time per runtime (another voice meanwhile keeps its label), and a helper failure or a missed deadline pauses transcription for 60 s. The transcript loses `<|…|>` tags and control characters, its square and lenticular brackets become `［］` and `〔〕` (so it never forms a `model_view` atom), runs of whitespace become one space, and it is cut to 600 characters followed by `…`; it replaces the message's last `[语音]` in the stored text and plain as `[语音转文字] <transcript>`, so model views, `model_view` filtering and the digest treat it as typed text; the activity log (`qq-activity.log`) keeps `[语音]`, and the transcript is read only by the model and kept in the transcript store. Every failure leaves `[语音]` and the message goes on. Transcripts are kept by inbound key in `<data>/voice/transcripts.json` (outside state backups) for 24 hours, at most 2,000, written under the leaf gate `<data>/locks/voice-transcripts.lock`, so a replay never transcribes twice; a store that cannot be written loses only that copy. Audio bytes and record addresses never reach a log, the run record or a file outside the transfer folder. Each failure is a run-record line (component `stt`, fixed reason); the first helper failure (no valid `helper`, connection refused, timeout, a non-200 answer, an invalid answer) after a start or an answer adds `voice-transcription-unavailable` and one owner notice (`voice-stt-down`, notice budget; a notice the limiter refused is tried again on the next helper failure), and the next answer `voice-transcription-recovered` and, when the outage had been told, a recovery notice (`voice-stt-up`, its own key). QQ's own transcription (`fetch_ptt_text`) is never used for inbound voice.

## QQ face transport

The shared QQ text-send path normalizes model text before the send guard, outbox intent and reply hold. It strips bare `[表情]` and summary `[表情:<summary>]` forms, canonicalizes supported numeric `[表情N]` tokens (including leading zeroes), and trims the result until stable. Normalization is idempotent even when stripping inside malformed or nested notation exposes another token: `a[表情[表情]]b` becomes `ab`. The configured outbound sentinel and CLI known-secret checks audit this final canonical text before submission; admission, outbox, history accounting and OneBot segments use the same representation. Legacy outbox intents remain append-only; resume canonicalizes their in-memory text before verification, admission, settlement and submission, and audits every resend candidate before an attempt. Empty normalized bubbles are removed; an entirely empty batch is refused before an intent. Other text is preserved. Automatic chat replies normalize the complete reply before reserved-mode burst splitting, UTF-16 length splitting and outbox recording; their enabled reply and command audits inspect both raw and canonical text.

Supported IDs are the pinned, sorted QQ system-face allowlist in `her/src/outbound_message.rs`, extracted from the `QSid` entries in [NapCat face_config.json at 98d781d](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/packages/napcat-core/external/face_config.json). The [SnowLuma face codec](https://github.com/SnowLuma/SnowLuma/blob/e44e4ced17c5911b9aa9db449ba29f2d9e567d2a/packages/onebot/src/event-converter/element-codecs.ts) accepts that OneBot face shape; its protocol layer resolves QQ system-face metadata. This bridge uses an explicit known-ID compatibility list rather than accepting every nonnegative integer the codec can parse. Unknown numeric IDs, malformed tokens, signs and non-ASCII digits stay literal text. Updating gateway compatibility requires updating the allowlist and fixtures; there is no runtime network lookup.

Each supported token becomes one OneBot `face` segment with a canonical decimal string `data.id`. Surrounding text becomes ordered `text` segments. Reply and @ segments retain their existing prefix order; raw CQ text remains escaped. A face-only message is one bubble, one outbox item and one quota/guard unit. All send splitters cut before a supported face token that crosses the length boundary; a token longer than the configured limit occupies its own part. Outbox parts preserve the canonical text actually sent. The outbox stores the normalized placeholder spelling, and history verification reconstructs the same spelling from face segments before comparison. An empty canonical comparison never proves delivery of a legacy summary-only item. Unknown/uncertain delivery is never retried without existing history verification.

Inbound `face` segments remain `[表情N]` in model text. Echoing that notation through any text send tool returns a real face. Inbound mface/summary notation carries no reproducible face ID and is stripped outbound. Model-image acquisition and normalization retain the contract in `her/AGENTS.md`.

## Crate contracts

Automatic replies normalize the complete text before burst or length splitting; send splitters preserve supported face tokens and record parts exactly as sent. Text tools and reserved2 CLI replies share canonical face normalization, repeat/cap admission and durable outbox accounting before reply holds; see `docs/agents/media-transport.md` and `docs/agents/prompts-modes.md`. Harness QQ tools dispatch through the common MCP/console handlers and retain uncertain-delivery classification. CLI relay requires the authenticated companion console, bounds connection/transmission to one second, permits held responses within 300 seconds, and never bypasses refusal or transport failure with a direct send. Chat confirmation-append failures retain the known delivery count, surface the persistence failure and stop later parts.

The sticker delivery pause and its configured bounds are part of the shared send-chain contract in `docs/agents/social-state.md`.
