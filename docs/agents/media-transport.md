# Media, stickers and voice

Read for model media acquisition, normalization, self-avatar fetch, stickers, voice libraries/STT or QQ face transport.

## Images, normalization and self-avatar

- **Media acquisition:** order is safe gateway cache -> bounded base64/local files (must be inside both configured home and selected root; missing selected self portrait = 404, redirected/invalid/I/O = 503 with pre-read containment) -> URL/CDN -> face fallback. Originals stay unchanged. Global `socialV2.media` caps: 8 MiB byte allowance (256 KiB-20 MiB), 64 MP pixel allowance (1-64 MP), 5-item batch (1-8). Original bytes consume budget pre-compaction; animation uses 1 source slot.
- **Permits & diagnostics:** 4 process-wide acquisition permits held from download/read through normalization/output (excess -> unreadable-media text/face description). Gateway image JSON caps `source_bytes * 4/3 + 4096`, headers 16 KiB; face JSON 64 KiB. Failures in `media::images` and `/api/socialV2/sticker-image` emit content-free `[media] acquire failed:` lines to stderr (symbolic reason + bounded int counts); model text and HTTP errors disclose no URLs, paths or decoder details.
- **`guarded_fetch.rs` & `onebot.rs`:** `guarded_fetch.rs` (`DnsResolver`/`HttpTransfer` seam, hidden `curl` with `-q`, cleared `CURL_HOME`/`XDG_CONFIG_HOME`/`HOME`/`APPDATA`/`USERPROFILE`/proxy env incl. `NO_PROXY`/`no_proxy`, `--noproxy *`, `-K -` stdin config, bracketed IPv6 `--resolve`, `ChildGuard` + Linux `PR_SET_PDEATHSIG`, streaming `-i` stdout with no temp files) rejects `localhost`/`.localhost`/`.local` pre-DNS, pins public addresses, revalidates <=5 redirects, tries <=4 addresses in 20s, rejects partial bodies/nonzero exits. Binary sniffers (`image_dimensions`, `looks_like_image` in `media_normalize.rs`; `looks_like_silk` in `voice.rs`) stay in their domain modules. `OneBot` (`onebot.rs`) over `loopback_http.rs` enforces literal loopback, split connect/write/read deadlines, 16 KiB header cap, decoded wire limits (incl. `Transfer-Encoding: chunked`), optional lone-surrogate-safe JSON and `NotCommitted` vs `Unknown`.
- **`media_normalize.rs`:** decoded PNG/JPEG/WebP `<= 64 KiB` and `<= 1024x1024` may pass unchanged; other opaque stills try JPEG qualities 75/60/45/35/25; alpha uses smaller lossless PNG/WebP; never upscale; reduce further to `<= 96 KiB`; output MIME matches bytes (`originalMimeType` set when changed).
- **Animation & decode bounds:** GIF/animated WebP preflight checks canvas/frame dimensions before streaming disposal/composition; <=8 evenly spaced frames incl. first/last (1-frame = still); ordered image blocks include Chinese sample-count note; MCP uses `type:image`, DSH inline `type:image/mediaType` (`image` = first sample alongside `images`). Bounds: 20 MiB input, dimensions 1-16384, configured pixel cap, 256 frames, 128M cumulative canvas pixels, 192 MiB est. working set (12 B/px still, 16 B/px anim, +1 MiB WebP overhead), 128 MiB PNG/JPEG/GIF alloc. WebP preflight allows only 1 main Huffman group and constant single-literal transform maps (refuses meta-Huffman and compressed ALPH for stills/ANMF). One process-wide decode/encode gate retains only compressed samples between frames.
- **`self_avatar.rs` (`qq_get_self_image`):** in selected runtime, serves live QQ avatar first (`userId` in `<data>/identity.json`, 5-11 digits no leading zero) from `https://q1.qlogo.cn/g?b=qq&nk=<uin>&s=640` via `safe_fetch::fetch_exact` (2 MiB, `looks_like_image`, 8s transfer after 5s lookup, no redirects).
  - Cache & backoff: `<data>/self-avatar.cache` (JSON outside `.json` backups, 30-day TTL, also caches failed fetch); pre-fetch writes+reads back `<data>/self-avatar.attempt` (`{uin, attemptAt}` per account in last 15 min). If entry `< 15 min` or attempt file unwritable/unreadable/unparsable -> no fetch, serve static portrait (bounds missing/damaged cache to <=1 fetch/15 min across restarts; future timestamps restamped `now` and treated active). Deleting both files forces fresh fetch. UIN change mid-fetch/store never serves under old UIN.
  - Lock & hygiene: `<data>/self-avatar-transfer` cleans legacy `her-fetch-*`; `<data>/locks/self-avatar.lock` serializes check-fetch-store per runtime (15s lock wait, 45s tool wait). Missing/invalid UIN, failure, backoff or busy gate -> static portrait. Console returns `source` (`qqAvatar` | `portrait`); tool returns fixed lead + image blocks (no path/URL to model). Tests use `self_avatar::FETCH_TEST_HOOK` (unset fails -> unit tests never contact qlogo; integration tests never hit self-image route with a valid `identity.json` UIN).
- **Ingress & forwards:** preserve image/mface/face refs, subtype/emoji metadata, package/key, sanitized 60-char summaries and forward IDs; emoji-only images stay CDN-resolvable; quote previews share ingress text renderer.

## Stickers and voice

- **Stickers:** console startup warms enabled collections once in background (failure leaves no cache; next list retries). Cache TTL is live; 10s agent force throttle is fixed (per root). Registry owns system/collection/prompt switches, list/prompt counts, collection quotas (unset disables budget), bytes and remark length (same source byte allowance as media). Downloads use `safe_fetch`; remark refreshes stale cache -> gateway -> state-gated write (admin variants reject agent creds). Delivery pause & bounds live in `docs/agents/social-state.md`.
- **Voice library & switches:** selected `resources/` + `socialV2.voice.dir` (13 extensions, no hidden/link/unreadable, 4 levels, pinyin order, <=100; missing/unreadable lists empty so operator path sends still work). `sendVoice` and `socialV2.voice.enabled` default off (`voice` setting gates AI only). AI refs stay in library (no traversal/URL/base64/outside path); operator paths resolve relative to resources then library (Windows drive-less roots checked before library-relative).
- **Duration & SILK bound:** `maxSeconds` defaults 60 and caps at 60 for non-members (larger clamped, logged <=1/distinct value/process; settings API accepts `(0, 60]`; legacy saves capped; fractional positive limits valid). Every AI/operator send and dry run requires finite positive duration or proven SILK upper bound `<= maxSeconds` before processing, outbox intent or gateway send. SILK/SLK (`#!SILK_V3` optional leading `0x02`) length-prefixed packets hold 1-5 frames (20-100 ms); check conservative bound `100 ms * packet_count` (incl. 0-byte DTX); if over limit, refuse asking for mp3/wav/ogg; malformed framing refused. Other formats require `ffprobe` valid duration (`FFPROBE_PATH`/`PATH`, null stdio/temp output; missing/invalid refused with cause).
- **Processing, budgets & outbox:** volume processing uses `ffmpeg` (`FFMPEG_PATH`/config/`PATH`), deletes temp post-send (missing required `ffmpeg` fails). Budgets spend only on confirmed/known-delivered unknown sends (AI stamps post-send, operator pre-send); shares send chain and default-off tool guard. Outbox stores `kind:voice` + intent label (refusal -> `not_committed`, uncertain searches newer own record history excluding confirmed IDs -> `unknown` without resend; verify reads `get_msg`/`record` without gateway paths unless `verify: false`; readback uses `fetch_ptt_text`; text resume refuses voice batches). Incoming/quoted records render as voice labels.
- **Inbound voice transcription (`voice_stt.rs`):** reserved2 ingress only, for conversation keys in `config.json` `voiceTranscription.conversations` (default empty; others keep `[语音]`).
  - Eligibility & download: exact 1 `record` segment with http(s) `data.url` -> `safe_fetch::fetch_voice` (pinned public, <=2 revalidated redirects, `voiceTranscription.maxBytes` default 1 MiB clamped 64 KiB-4 MiB, `voice::looks_like_silk`, cleans `<data>/voice/transfer/her-fetch-*` with streaming stdout). Must be valid whole SILK v3 framing with `packet_count <= 50 * maxSeconds` (default/cap 60, min 1).
  - Helper POST: `voiceTranscription.helper` must be `http://<loopback IP literal>:<port>` (no hostname/path/creds) -> `POST /v1/transcribe` (`application/octet-stream`), expects `200` + `Content-Length` JSON `<= 16 KiB` with string `text` (other fields ignored; other status/shape = failure).
  - Deadlines & backoff: total `timeoutMs` (default 8000, clamped 1000-20000); download+DNS(5s)+redirects end 3s before deadline (at most half `timeoutMs`); helper called only with `>=250 ms` left and streamed in chunks within deadline (overrun download = missed deadline, no helper outage/notice). Caller waits `<=500 ms` extra; 1 STT/runtime at a time; helper failure or missed deadline pauses STT for 60s.
  - Redaction, cache & alerts: strips `<|...|>` + controls, maps `[]`/`【】` -> `［］`/`〔〕`, collapses whitespace, cuts at 600 chars + `…`, replaces last `[语音]` in stored text/plain as `[语音转文字] <transcript>` (`qq-activity.log` keeps `[语音]`; model-only). Cached by inbound key in `<data>/voice/transcripts.json` (outside backups; 24h TTL, <=2000 entries, leaf gate `<data>/locks/voice-transcripts.lock`) so replays never re-transcribe. Audio bytes/URLs never logged or stored outside transfer dir. Failures log `component=stt` fixed reason; first helper failure after start/success adds `voice-transcription-unavailable` + owner notice `voice-stt-down` (retried on next failure if rate-limited), next success adds `voice-transcription-recovered` + `voice-stt-up`. `fetch_ptt_text` is never used for inbound voice.

## QQ face transport

- **Normalization:** shared QQ text-send path strips bare `[表情]` and `[表情:<summary>]`, canonicalizes supported numeric `[表情N]` (incl. leading zeros), trims until stable (idempotent across nested malformed notation: `a[表情[表情]]b` -> `ab`). Outbound sentinel & CLI known-secret checks, admission, outbox, history accounting and OneBot segments all use this canonical form. Legacy outbox resumes canonicalize in-memory and audit pre-attempt. Empty normalized bubbles drop; all-empty batch refuses pre-intent. Automatic chat replies normalize full reply pre-burst/UTF-16 split/outbox (reply/command audits inspect raw and canonical).
- **Allowlist & segments:** pinned sorted `QSid` allowlist in `her/src/outbound_message.rs` from [NapCat face_config.json at 98d781d](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/packages/napcat-core/external/face_config.json) matching [SnowLuma face codec](https://github.com/SnowLuma/SnowLuma/blob/e44e4ced17c5911b9aa9db449ba29f2d9e567d2a/packages/onebot/src/event-converter/element-codecs.ts) (no runtime lookup; unknown IDs, malformed tokens, signs, non-ASCII digits stay literal text). Each supported token -> OneBot `face` segment (`data.id` canonical decimal), surrounding text -> `text` segments (prefix Reply/@ order kept, CQ escaped). Splitters cut before a crossing face token (oversized token gets own part). Outbox stores normalized placeholder spelling and reconstructs it from face segments for history verification (empty canonical comparison never proves legacy summary-only delivery; unknown delivery never auto-retried without history proof).
- **Inbound:** `face` segments render as `[表情N]` (echoable); `mface`/summary carry no face ID and strip outbound.

## Crate contracts

Reserved2 auto-replies normalize pre-split; text tools and reserved2 CLI replies share canonical face normalization, repeat/cap admission and durable outbox accounting pre-hold (`docs/agents/prompts-modes.md`). Harness QQ tools share MCP/console handlers and retain uncertain-delivery classification. CLI relay requires authenticated companion console (1s connect+write, 300s held total, no direct fallback); chat confirmation-append failure retains known delivery count, surfaces persistence failure, and stops later parts.
