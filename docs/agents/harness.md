## Admission, switching and tool loop

- **`turn_engine.rs` & `pipeline/dsh_adapter.rs`:** `Engine`/`Adapter` seam runs each turn on DSH, harness or scripted test adapter and writes `turn-timing.jsonl` from reported facts. DSH code lives behind `dsh_adapter.rs` registration points (`Adapter::Dsh` in `run_admitted_turn`, `prepare_dsh_chat`, `defer_unsubmitted_dsh_chat`, `dsh_switch_summary`, `closed_preset`) until #13 removes DSH.
- **Engine selection:** `conversation.engine` -> `engine.default` (default `dsh`). In reserved2, only `conversation.engine = "harness"` overrides a CLI pin. Harness serves chat, owner-private closed-agent and reserved2 (1st-gen reserved stays DSH). Turns hold selected-runtime conversation gate through delivery/settlement; `/conversations` Switch waits for current turn (409 if unsettled/draining past 180s). Global default changes switch inheriting convs at next admission.
- **`engine_switch.rs`:** fences admission, checks open/paused turns, summarizes source history (`【之前聊天的摘要】`: <=64 facts, <=12000 Unicode chars, <=2000/fact, `model_view` + token/cred masking + denied-term check; empty history -> fixed handover; DSH snapshot 20s / 4 MiB; harness skips payloads >64 KiB; failed summary keeps source). Stages summary, source mapping and epoch in `social-v2.json` before stopping/archiving DSH, then atomically commits engine, fresh token and handover (rechecking permission/mode/gen/engine at staging, archive and publication; reserved2 requires explicit allow incl. owner). Pending matching switch retries captured archive even if binding is gone; return to source clears superseded switch. Access revocation clears handover state. Chat/closed-agent switch failures retry on 5s->10m backoff + 1 owner notice; chat requeues changed admission <=3x (100 ms); reserved/reserved2 retry stale cleanup while authority holds.
- **DSH outage bypass:** chat/reserved2 pipelines build without DSH creds; harness wakes skip DSH queue/login/session/stream when no live DSH mapping or staged archive needs handover. Runtime DSH health/interaction listeners remain active while other convs/jobs use DSH.
- **`harness.rs` & `data/conversations.db`:** SQLite WAL + `synchronous=FULL` (`BEGIN IMMEDIATE` pre-version). Tracks generation-scoped sessions, turns, minted model attempts and append-only events (v2 adds attempt-linked tool runs and canonical genai messages). Admission commits pre-network; complete assistant msg commits pre-outbox.
  - Startup reconciliation (`#297`): interrupted `reserved2` harness wakes (`begun` mode or wake claim) self-reconcile when outbox is absent/settled and store has no unsettled tools/pause; other unfinished harness turns pause `harness-interrupted`; unknown/unreadable sends, unsettled tools or unreadable store pause `send-unresolved` (`confirm:true` retry; `docs/agents/sessions-recovery.md`).
  - Full restore: retained terminal ledger outcomes close restored running turns/attempts without replay (preserving `observationSleep`); missing ledger entries gain paused harness entry (`docs/agents/lifecycle-tasks.md`).
- **Model client & credentials (`#443`):** `genai 0.7.3` with `redirect::Policy::none()` and OpenAI-compatible Chat Completions. `settings::resolve_model_endpoint_and_key` resolves live `E` (`harness.apiBaseUrl` in `settings.db`, else `config.json`, else `dependencies.json` `"model"` baseline `D`; `/v1/` appended only to bare origins). Uses `harness.apiKey` bound to `canonical(E)`, falling back to `config/harness-api-key` only when `canonical(E) == canonical(D)` and no stored key is set (fails closed on mismatch/store-read error). Provider errors/codes/summaries redact `config/harness-api-key` and stored endpoint creds (in-flight requests keep admission masking snapshot).
- **Tool dispatch (`harness/tools.rs`, `harness/profile.rs`):** loop commits complete assistant call list pre-dispatch, then durable start intent + result/canonical response per call sequentially (no DSH MCP config read). `Tools::capture` enforces admitted mode (unreadable `mode.json` refuses; absent `mode.json` defaults `reserved2`); every request/call rechecks mode, allow-list, owner and switches. Duplicate call IDs fail closed; lost/unprovable QQ sends pause `send-unresolved` (`confirm:true`).
  - Modes: chat, owner-private chat, closed-agent, reserved2, owner-private reserved2, digest, slang learner. `sendVoice`/`setStickerRemark` default off; no shell/fs/plugin/agent tools; MCP images persist as binary parts -> Chat Completions user image content (no base64 in tool text). Reserved2 harness profiles include `reminder_{create,list,change,cancel}` (group create/change refuse requiring approval).
  - System message (`Profile::prompt_key`): read at `Tools::capture`, model-view stripped + blank line + tool session line (never stored; jobs have none).
- **Reserved2 wakes, media & budgets:** wakes share section renderer + authenticated snapshot; canonical user fact + token-free briefing receipt commit together in SQLite (delta next turn; checkpoint/new gen/persona switch -> full briefing). First model request records `started` pre-send after checkpoint prep.
  - Inbound media (`media::model_parts`): `[图片N]`/`[表情N]` + Chat Completions `image_url` data URLs (user event `text` stores prompt only; voice keeps `[语音]` label). `harness.imageInput` (default true; false renders `（这张图片现在看不到）` on delivery while keeping canonical image).
  - Budgets captured at admission: `harness.maxSteps` (8, 1-64), `harness.maxTokens` (32768, 1-1_000_000), `socialV2.turnTimeoutSecs` (chat/closed-agent; reserved2 uses `prompts-modes.md` cap/ceiling checked pre-request, pre-tool and pre-commit; live messages wait cap -> `observationSleep`, else `turnTimeout`; uncertain effect pauses). Requests cap output at remaining tokens up to route `maxOutputTokens` (default 4096); missing usage charges UTF-8 bytes.
  - Tool preview: `harness.toolResultChars` (8000, 1000-100000) truncates post-filter/post-format text per request with char-count note (canonical facts, images and refusal ID extraction keep full text).
- **Cancellations, `ask_owner` & stream retry:** cancel/deadline revokes admitted token and retains handler ownership through settlement (unprovable -> `send-unresolved`). Admin `ask_owner` & group-send approval (15s socket read, outbox refuses resume) bind session/turn/epoch (lost on startup; tokens/creds refused; answers masked). `/reset`/`/new` work without DSH mapping (per-turn OS lock settles active handler before cancel). Dropped streams retry once pre-dispatch (same steps/deadline; model fixture restores blocking mode).
- **Redaction & memory facts:** live/replayed delivery applies `model_view` (marking suppressed spans in memory `formatted`, slang fields, `messages` strings/arrays); provider content-filter/refusals fail before completion/relay (`provider: openai`). Memory tools store `_meta.herMemoryResult` v1 (formatter-only `args` + structured `data`, token-masked) and re-filter at render. Record copies mask known session tokens (incl. spaces/escapes) and 48-hex runs (opaque protocol aliases `her_call_`/`her_tool_`, preserving binary/signatures; refuses write if credential snapshot unreadable).

### Blacklist replay

Use `turnId` and `modelCall` from the refusal row to recover the turn's tool results from a read-only copy of `<data>/conversations.db`. Bind the turn ID to `?1` and the one-based call index to `?2`.

```sql
WITH refused AS (
    SELECT seq, session_id FROM events
    WHERE turn_id = ?1 AND kind = 'model_attempt_started'
    ORDER BY seq LIMIT 1 OFFSET (?2 - 1)
)
SELECT events.payload FROM events JOIN refused USING (session_id)
WHERE events.turn_id = ?1 AND events.seq < refused.seq AND events.kind = 'tool_result'
ORDER BY events.seq;
```

Pair `result` and `message` call ID with user/assistant facts and apply `model_view` + `toolResultChars` preview.

## Model routes and failover

- **`harness/routes.rs`:** owns `ModelRoute`, failover memory, `tokio::select!` retry backoff, route health, usage, `model-chain` run records, redaction, shared `genai::Client`, and `ChainExecutor` (`RouteStep` seam: `TurnStep`, `OneShotStep`, test adapters).
- **Chain config (`harness.routes`):** 1-8 ordered routes (`id` 1-64 `[A-Za-z0-9._-]` != `default`, `model`, optional `reasoningEffort` in `zero|none|minimal|low|medium|high|xhigh|max`, `maxOutputTokens` 1-32768 default 4096, `retry429` default true; invalid chain refuses; missing/null falls back to `[harness.model]`). Uses effective endpoint `E` + bound `harness.apiKey` (`config/harness-api-key` on `D` only).
- **Walk & retry (`ModelRoute::for_conversation`):** `conversation.route` -> `harness.firstRoute` -> configured order (each distinct order resets failover memory; one-shot jobs ignore selection). First 429 (`retry429=true`) retries once after `retry-after-ms`/`retry-after`/2s (<=30s, before deadline); empty retries <=3x (1/2/4s) pre-send; first dropped stream retries once pre-dispatch; post-dispatch drop/timeout/network or post-QQ-send failure ends turn. Max 2 failovers/conv until completion (starts at sticky degraded route; lapses after 30m, new gen, chain edit, or restart).
- **Usage (`harness/usage.rs` -> `data/token-usage-rust.jsonl`):** records every response-end request (`k:"turn"`, `key`, `sid`, `turn`, `step`, `retry`, `seq:0`, redacted `model`/`route`, `provider`, `engine:"harness"`, `job: turn|digest|summary|slang`, optional `attemptId`, `b` buckets or `null`; ready usage recorded pre-`Cancelled`). `usage::reconcile_startup` reconciles `conversations.db` above `data/harness-usage-reconcile.json` (`lastSeq`). `/api/usage/attribution` excludes `engine:"harness"`.
- **One-shot jobs (`harness/one_shot.rs`):** `Digest` (`digest_model`, `digest_summarise_async`) and `SlangLearner` (`slang_complete`) run non-streaming tool-less requests via `OneShotStep` + `routes::block_on_shared` (`one_shot::normalize_response_text`/`normalize_failure`). `Digest` sets `retry_empty: true` under `memory.digest.timeoutSecs` (failover memory key `internal:digest`; `memory.digest.model` uses single route without failover/health); `SlangLearner` sets `retry_empty: false` (120s cap). Fixed classes: `quota`, `timeout`, `backend`, `network`, `refusal`, `empty-response`, `unconfigured`, `cancelled`. Test seam: `one_shot::install_test_model(&context, ...)`.

## History budget and checkpoints

- **`harness/budget.rs`:** token estimate = `ceil(ascii/4) + non_ascii + 4/msg + 1500/image` (`imageInput=false` counts placeholder). Window = `harness.contextTokens.<routeId>` (`1000..10_000_000`, default `64000`); budget = `window * harness.historyShare` (`0.1..0.95`, default `0.82`, thousandths); `harness.summaries` defaults true. `budget::fit` drops oldest whole rounds (`1 round` = completed turn or summary) while keeping system + current turn; unoffered tool calls/results render as `〔我用了 …〕` / `〔… 的结果〕` + images.
- **Checkpoints (`harness/handover.rs`):** checked pre-first-request. Idle rotation (`rotation::due_at` + `store::last_call`) keeps <=4000 est. tokens in place; budget overrun keeps <=15% of window. Appends `checkpoint` (`purpose: rotation|budget`, `through`, `summary`) + `checkpoint_failed` atomically; replays newest summary as `【之前聊天的摘要】`.
  - Summary generation uses digest port (`job:"summary"`, excluded from `maxTokens`, bounded by `memory.digest.timeoutSecs` and `turnDeadline - 5s` `SUMMARY_RESERVE`, 24000 est. input tokens, 2000 chars/tool result, no system msg, <=4000 char output, rejected as `wording` if new `model_text_policy::denied_terms` appear). Failed rotation leaves unrotated; failed budget still advances `through` with prior summary. Cancelled/timed-out turns write no checkpoint and revoke token (`harness::resolve_interrupted` on crash).
- **Route health (`harness/route_health.rs`):** `data/route-health/state.json` (`data/locks/route-health.lock` 2s, 64 KiB max; chain change/corrupt resets; never backed up). All-failed chain opens outage episode -> post-turn `admin_alert::notify_route_alert` (`model-routes-all-failed`, count + class only; `begin_alert_delivery` -> `alerted=true`, `NotCommitted` releases, `Unknown` keeps; `reconcile_startup` clears stale claims). Health reports `modelRoutes` alongside parts (`docs/agents/lifecycle-tasks.md`).
